1.2 Java Virtual Machine (JVM) Architecture & Execution Pipeline

Definition: The JVM (Java Virtual Machine) is a runtime engine that loads intermediate bytecode (.class file) produced by javac, verifies it, and converts it into machine code for execution.
StageWhat happens
Compile-time (javac)The .java source file is checked for syntax errors and translated into platform-independent bytecode (.class).
Run-time (java / JVM)The class loader loads the bytecode, verifies it, and the execution engine converts it into native machine instructions to run.
Common mistake: Thinking bytecode is CPU machine code. Bytecode is instructions for the JVM; the JVM translates it into CPU instructions.
Quick recall JVM architecture = Class loader subsystem + Runtime memory areas (Heap, Stack, Method area) + Execution Engine (Interpreter + JIT + GC).

AdvantageWhy

1.10 Short answers (1 mark)

Q1. 1. Define JVM and Bytecode.
JVM is an abstract execution engine that executes Java bytecode. Bytecode is the platform-independent intermediate format compiled from .java source code.
Q2. 2. Differentiate JDK, JRE, and JVM.
JDK contains development tools + JRE; JRE contains class libraries + JVM; JVM is the execution runtime engine that runs bytecode.
Q3. 3. What is Write Once, Run Anywhere (WORA)?
Java's architecture principle where code compiled into bytecode on one platform can run without modification on any OS containing a compatible JVM.
Q4. 4. What is the role of the JIT compiler?
Just-In-Time compiler compiles frequently used bytecode sequences into native CPU instructions at runtime to accelerate execution speed.
Q5. 5. List the 8 primitive data types in Java.
byte, short, int, long, float, double, char, and boolean.
Q6. 6. Differentiate widening and narrowing casting.
Widening is automatic conversion of a smaller type to a larger type (e.g., int to double); narrowing is manual conversion of a larger type to smaller type with cast syntax (int) d.
Q7. 7. What is automatic type promotion in expressions?
In expressions, byte, short, and char are promoted to int; if an operand is long, float, or double, the whole expression promotes to that larger type.
Q8. 8. Differentiate pre-increment and post-increment operators.
Pre-increment (++x) increments the variable before evaluating its value; post-increment (x++) evaluates current value first before incrementing.
Q9. 9. What is short-circuit evaluation in logical operators?
In &&, if the first condition is false, the second is skipped. In ||, if the first condition is true, the second is skipped.
Q10. 10. Explain ternary operator syntax.
Conditional shorthand: condition ? value_if_true : value_if_false;.
Q11. 11. Differentiate while and do-while loops.
while is an entry-controlled loop (0 min executions); do-while is exit-controlled, executing the loop body at least once.
Q12. 12. Differentiate break and continue statements.
break exits the loop or switch block immediately; continue skips the remainder of the current iteration and jumps to the next loop evaluation.
Q13. 13. What is a jagged array?
A multi-dimensional array where each row/sub-array can have a different number of columns/elements.
Q14. 14. How is array length obtained in Java?
Using the built-in .length field of the array object (e.g., arr.length).
Q15. Q. What are the advantages and disadvantages of arrays in Java?
Advantages: code optimization (one variable for many values) and random access (O(1) access by index). Disadvantage: fixed size - an array cannot grow at runtime, so the Collection framework is used when the size must change.
Q16. Q. Differentiate array declaration and array creation.
Declaration (int marks[];) only creates a reference variable with no memory for elements; creation (marks = new int[6];) allocates memory on the heap for the given size and fills it with default values.

2.4 Polymorphism: overloading and overriding

Definition: Polymorphism is the ability of one method name (or reference) to take many forms. In Java it is of two kinds: compile-time polymorphism, achieved by method overloading, and run-time polymorphism, achieved by method overriding with dynamic method dispatch.
Common mistake: the notes add here, "when you write two or more classes in a single file, the file is named upon the class that contains the main method." The precise rule is about public, not about main: if one class in the file is public, the file must be named after THAT class, whether or not it has main; only when no class in the file is public can the file take any name at all (you then simply run whichever class has main). Bike2.java above is named after its public class Bike2, which also happens to hold main — that overlap is what makes the two rules look identical in a single example.
Common mistake: the notes' rule here is "static or final method cannot be overridden." Add private to that same list. There is also a sharper point hiding inside this rule: if a subclass declares a static method with the exact signature of a static method in its parent, that is method hiding, not overriding — Java decides which one runs from the reference type at compile time, unlike genuine overriding, which is decided from the object type at run time. Proof below.
Method overloadingMethod overriding
Same name, different parametersSame name, same parameters
Usually in the same classIn parent and child classes
Compile-time polymorphismRun-time polymorphism
Static (early) bindingDynamic (late) binding
Return type may differReturn type same or covariant
Inheritance not neededInheritance required
static / private / final methods can be overloadedstatic / private / final methods cannot be overridden
Mnemonic overLOADing = LOAD more parameters (different list); overRIDing = RIDE over parent's method (same signature).
Common mistake: with Payment p = new UpiPayment(); you can only call methods that exist in Payment; the child version runs, but child-only methods are not visible through p.
Quick recall Overloading = compile time, different parameters; overriding = run time, same signature, parent reference picks child method; a matching static method in the child HIDES the parent's (reference decides), it never overrides it.

2.5 Static binding and dynamic binding

Definition: Binding is the process of connecting a method call to its actual body (method definition). Static binding (early binding) happens at compile time and is used for overloaded methods; dynamic binding (late binding) happens at run time and is used for overridden methods.
BasisStatic bindingDynamic binding
Also calledEarly bindingLate binding
Resolved byCompilerJVM
Resolved whenCompile timeRun time
Used forOverloaded methods (and static/private/final methods)Overridden (instance) methods
Decided fromReference type / arguments in the callActual object type
Matching polymorphismCompile-time polymorphismRun-time polymorphism
Mnemonic S-C-C vs D-R-R: Static binding = Compiler, Compile time; Dynamic binding = Run time, Real (actual) object.
Common mistake: thinking "static binding" only means "binding of static methods." A static method call IS always statically bound, but so is every overloaded call and every private/final method call — static binding is about when the decision is made (compile time), not only about the static keyword.
Quick recall Binding = connecting a call to its body. Static/early = compiler, compile time, overloading. Dynamic/late = JVM, run time, overriding — the object behind the reference decides.

2.6 Abstract class and abstract methods

Definition: An abstract class is a class declared with the abstract keyword that cannot be instantiated and may contain abstract methods. An abstract method is a method declared without a body (abstract double area();) that every concrete subclass must override.
Quick recall abstract class: no objects, may mix abstract (bodyless) + normal methods, fields, constructors, even main(); child must override every abstract method to become instantiable; abstraction is the general idea, abstract class is one Java tool for it.

Q1. Difference between method overloading and method overriding, with a suitable example

class Shape {
    // overloading: same name, different parameters (same class)
    int area(int side) { return side * side; }
    int area(int length, int breadth) { return length * breadth; }

    void draw() { System.out.println("Drawing a shape"); }
}

class Circle extends Shape {
    // overriding: same name AND same parameters (child class)
    @Override
    void draw() { System.out.println("Drawing a circle"); }
}

public class OverloadOverride {
    public static void main(String[] args) {
        Shape s = new Shape();
        System.out.println("Square area = " + s.area(4));      // area(int)
        System.out.println("Rectangle area = " + s.area(4, 6)); // area(int,int)

        Shape ref = new Circle();   // parent reference, child object
        ref.draw();                 // child's draw() runs at run time
    }
}

Rectangle area = 24
Drawing a circle
  • s.area(4) and s.area(4, 6) call different methods because the arguments differ: overloading.
  • ref is a Shape reference, but the object is a Circle, so Circle's draw() runs: overriding (dynamic method dispatch).
Mnemonic "LOAD in one class, RIDE up to the parent": overload = same class, different parameters; override = child over parent, same parameters.

Q2. Explain abstract class and interface in Java

Abstract class: A class declared with the abstract keyword that cannot be instantiated. It can have abstract methods (no body) and concrete methods (with body), variables and constructors. A subclass must override all abstract methods or itself be abstract.
Interface: A reference type declared with the interface keyword that defines a contract: methods are public and abstract by default and variables are public static final (constants). A class uses implements to provide the bodies. One class can implement many interfaces, which is how Java achieves multiple inheritance.

Rules of an abstract class

  • Declared with abstract; an abstract method has no body and ends with ;.
  • Cannot create objects: new Account() is a compile error, but a reference Account a is allowed.
  • Can have constructors (called through super()), instance variables, static and final methods.
  • If a class has even one abstract method, the class must be abstract.
  • Gives partial abstraction (0 to 100%).

Rules of an interface

  • Methods are public abstract by default; variables are public static final.
  • No constructors, cannot be instantiated.
  • A class implements an interface and must give bodies to all its methods (declared public).
  • An interface can extend other interfaces; a class can implement many interfaces.
  • From Java 8, interfaces can also have default and static methods with bodies.

Program using both:

interface Printable {                 // interface: only a contract
    void print();                     // public abstract by default
}

abstract class Account {              // abstract class: partial blueprint
    double balance;
    Account(double balance) { this.balance = balance; }
    abstract double interest();       // no body
    void show() { System.out.println("Balance = " + balance); }
}

class Savings extends Account implements Printable {
    Savings(double balance) { super(balance); }
    double interest() { return balance * 0.04; }
    public void print() { System.out.println("Interest = " + interest()); }
}

public class AbstractInterface {
    public static void main(String[] args) {
        Savings s = new Savings(10000);
        s.show();
        s.print();
    }
}

Q3 (a). Short note: Array of objects

Definition: An array of objects is an array whose elements are references to objects of a class. The array stores references, not the objects themselves; each object must be created separately with new.
  • Syntax: ClassName[] arr = new ClassName[size];
  • Step 1: creating the array only creates size references, all null.
  • Step 2: create each object: arr[0] = new ClassName(...);
  • Step 3: access members through the index: arr[i].member.
  • Diagram: see Fig 2.4 (array cells holding arrows to separate objects).
  • Use: storing records of many students, employees or products and processing them in a loop.
class Student {
    String name;
    int marks;
    Student(String name, int marks) {
        this.name = name;
        this.marks = marks;
    }
}

public class StudentArray {
    public static void main(String[] args) {
        Student[] list = new Student[3];       // step 1: array of 3 references (all null)
        list[0] = new Student("Aman", 78);      // step 2: create each object
        list[1] = new Student("Riya", 91);
        list[2] = new Student("Kabir", 65);

        for (int i = 0; i < list.length; i++) { // step 3: use them
            System.out.println(list[i].name + " : " + list[i].marks);
        }
    }
}
Aman : 78
Riya : 91
Kabir : 65
Common mistake: using list[0].name before list[0] = new Student(...) throws NullPointerException, because the cell still holds null.

Q3 (b). Short note: Class and objects

Class: A user-defined blueprint (template) that describes the data members (state) and methods (behaviour) common to all its objects. A class takes no memory for data until objects are created.
Object: A real instance of a class created at run time with new. It has its own copy of the data members and occupies memory on the heap.
  • Syntax of a class: class ClassName { data members; methods; }
  • Creating an object, three steps in Car c1 = new Car();: declaration (Car c1), instantiation (new allocates memory), initialization (the constructor Car() runs).
  • Members are accessed with the dot operator: c1.brand, c1.display().
  • Every object has state (values of variables), behaviour (methods) and identity (its own memory reference).
  • Diagram: see Fig 2.1 (one class, many objects) and Fig 2.2 (reference on stack, object on heap).
class Car {
    String brand;          // data member (state)
    int speed;

    void accelerate(int by) {   // method (behaviour)
        speed = speed + by;
    }

    void display() {
        System.out.println(brand + " is running at " + speed + " km/h");
    }
}

public class CarDemo {
    public static void main(String[] args) {
        Car c1 = new Car();   // object 1
        c1.brand = "Tata Nexon";
        c1.accelerate(40);

        Car c2 = new Car();   // object 2, same class, own data
        c2.brand = "Maruti Swift";
        c2.accelerate(60);

        c1.display();
        c2.display();
    }
}

Q4. Short note: Packages (also in the syllabus)

Definition: A package is a group of related classes and interfaces stored together in one folder, declared with the package keyword. It works like a folder in a computer.
  • Types: built-in (java.lang, java.util, java.io) and user-defined. Diagram: Fig 2.19.
  • Advantages: avoids name conflicts, groups related classes, provides access protection, makes code reusable and easy to find.
  • package statement must be the first statement of the file.
  • Compile with javac -d . Calculator.java; -d . creates the folder mypack (see Fig 2.21).
  • Import: import mypack.Calculator; (one class), import mypack.*; (all public classes), or the fully qualified name mypack.Calculator.
  • java.lang is imported automatically.
  • Access protection across packages: only public members are visible to other packages; protected is visible to subclasses in other packages; default (no modifier) stays inside its own package.

File 1 mypack/Calculator.java:

package mypack;

public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }
}

File 2 UsePackage.java (in the folder that contains mypack):

import mypack.Calculator;

public class UsePackage {
    public static void main(String[] args) {
        Calculator c = new Calculator();
        System.out.println("Sum = " + c.add(10, 20));
    }
}

Commands: javac -d . mypack/Calculator.java → javac UsePackage.java → java UsePackage

2.10 Short answers (1 mark)

Q1. Define class and object.
A class is a user-defined blueprint containing fields and methods. An object is an instance of a class created with new, having its own state and memory on the heap.
Q2. What is an array of objects?
An array whose elements are references to objects of one class, e.g. Book[] b = new Book[3];. Each object must be created separately with new, otherwise the element is null.
Q3. Why does Java not support multiple inheritance with classes?
To avoid the diamond problem: if two parents have the same method, the child's call becomes ambiguous. Multiple inheritance is achieved through interfaces.
Q4. Differentiate overloading and overriding.
Overloading: same name, different parameters, same class, compile-time. Overriding: same signature in child class, needs inheritance, run-time (dynamic dispatch).
Q5. What is dynamic method dispatch?
The mechanism by which a call to an overridden method through a parent-class reference is resolved at run time according to the actual object type.
Q6. What is an abstract class?
A class declared abstract that cannot be instantiated; it can have abstract (bodyless) methods, concrete methods and constructors. Subclasses must override the abstract methods.
Q7. Define interface.
A reference type with public abstract methods and public static final constants; a class uses implements to provide the bodies and may implement several interfaces.
Q8. What is a package? Name two built-in packages.
A named group of related classes and interfaces giving a namespace and access control. Examples: java.lang, java.util.
