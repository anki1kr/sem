Q1. Explain the features (buzzwords) of Java. Why is Java called platform independent?

Unit I · 8 marks · list all buzzwords, then be ready to expand any single one (usually platform independence) into its own short question.

Definition: Java is a high-level, object-oriented, class-based, platform-independent programming language created by James Gosling at Sun Microsystems in 1995.
  • Simple: syntax based on C/C++; no explicit pointers or operator overloading; the JVM manages memory automatically.
  • Object-Oriented: software is organised as objects, each holding both data and behaviour.
  • Platform independent: the same bytecode runs on Windows, Linux, macOS — anywhere a JVM exists. This is WORA (Write Once, Run Anywhere): javac compiles source into platform-independent .class bytecode, and any machine with a JVM can execute that same file, because the JVM (not the OS) is what actually runs it.
  • Secured: no explicit pointers, every program runs inside the JVM's sandbox, and Java uses a public-key encryption system for security.
  • Robust: strong memory management, no pointers, and built-in exception handling with compile-time type checking.
  • Architecture neutral: no implementation-dependent feature sizes — int is always 4 bytes in Java on every platform.
  • Portable: the same bytecode file can be carried to any platform; javac itself is written in ANSI C for a clean portability boundary.
  • Dynamic: carries extensive run-time information to verify and resolve access to objects.
  • Interpreted: bytecode is translated on the fly into native instructions and is not stored anywhere.
  • High performance: the JIT (Just-In-Time) compiler translates bytecode directly into native machine code for speed.
  • Multithreaded: supports many things happening at once; threads share one common memory area.
  • Distributed: designed for the internet's distributed environment; RMI lets a program call methods on another machine over a network.
Mnemonic remember all 12 in three groups of four — SOPS (Simple, OOP, Platform-independent, Secured) · RAPD (Robust, Architecture-neutral, Portable, Dynamic) · IHMD (Interpreted, High-performance, Multithreaded, Distributed).
If it comes as 4 marks: write the definition, draw Fig 1.4, and explain only 4 buzzwords in one line each — Simple, Platform-independent, Robust, Multithreaded.
Quick recall 12 buzzwords in 3 groups of 4 (SOPS / RAPD / IHMD). Platform independence = bytecode + JVM = WORA.

Q2. Explain JDK, JRE and JVM, and describe the internal architecture of the JVM with the compilation-execution pipeline.

Unit I · 8 marks · define the three terms, then open up the JVM into its subsystems and explain how bytecode gets executed.

Definition: The JVM (Java Virtual Machine) is a runtime engine that loads intermediate bytecode (.class file) produced by javac, verifies it, and converts it into machine code for execution. JDK = JRE + development tools; JRE = JVM + runtime libraries.
FeatureJDKJREJVM
Full formJava Development KitJava Runtime EnvironmentJava Virtual Machine
PurposeDevelopment & CompilationRunning applicationsExecuting bytecode
ContainsJRE + Tools (javac)JVM + Core LibrariesClass Loader + Execution Engine
  • Class Loader Subsystem: Loading (loads .class file), Linking (Verification, Preparation, Resolution), Initialization (runs static initializers).
  • Runtime Data Areas: Method Area (class/field/static data), Heap (all objects, managed by the garbage collector), Java Stack (frames for active methods and local variables), PC Register (address of the current instruction), Native Method Stack (state for native C/C++ methods).
  • Execution Engine: Interpreter (executes bytecode one instruction at a time), JIT Compiler (compiles hot bytecode into native code), Garbage Collector (frees unreferenced heap memory).
  • WORA: because the class-loader and execution engine sit inside the JVM and not the OS, the same .class file runs unchanged on any OS with a compatible JVM.
Common mistake: thinking bytecode is CPU machine code. Bytecode is instructions for the JVM; the JVM translates it into CPU instructions.

Quick recall JDK = JRE + Tools; JRE = JVM + Libraries. JVM architecture = Class Loader + Runtime Data Areas (Heap, Stack, Method Area, PC, Native Stack) + Execution Engine (Interpreter + JIT + GC).

Q6. Explain selection statements in Java: if, if-else-if ladder, and switch.

Unit I · 8 marks · the if-else-if ladder (grade calculation) is the classic worked example; switch is usually asked alongside it.

Definition: Selection statements allow a program to choose between different execution paths based on the boolean result of a condition or discrete value match.
  • if: executes a block only if the condition is true.
  • if-else: executes the if block when true, else block when false.
  • else-if ladder: tests multiple conditions top to bottom; the first true one runs and skips the rest; a final else catches everything remaining.
  • switch: multi-way branch comparing an int/char/String expression against case values; needs break to prevent fall-through.
Basisif-else / ladderswitch
TestsAny boolean condition (ranges, multiple variables)One variable/expression against fixed int/char/String values
ReadabilityGets messy with many conditionsCleaner for many discrete values
Fall-throughNot applicableHappens if break is missed
Best forRange checks (e.g. marks>=90)Exact-value menus (e.g. day number, choice)
public class SelectionDemo {
    public static void main(String[] args) {
        int number = 15;
        if (number % 2 == 0) {
            System.out.println(number + " is Even");
        } else {
            System.out.println(number + " is Odd");
        }
        int day = 2;
        switch (day) {
            case 1: System.out.println("Monday"); break;
            case 2: System.out.println("Tuesday"); break;
            default: System.out.println("Other day");
        }
    }
}

Q7. Explain iteration (looping) statements and jump statements in Java.

Unit I · 8 marks · while vs do-while is the classic differentiate question; break/continue is the jump-statement half.

Definition: Iteration statements (loops) repeatedly execute a statement block as long as a loop termination condition remains true.
  • for: entry-controlled, best when the number of iterations is known (initialization; condition; update).
  • while: entry-controlled, tests condition before executing the body.
  • do-while: exit-controlled, executes the body at least once before testing the condition.
  • break: immediately terminates the innermost loop or switch block.
  • continue: skips the rest of the current iteration and jumps to the next loop test.
  • A labelled loop (label: for(...)) lets break label;/continue label; target an outer loop from inside a nested one.
Featurewhile Loopdo-while Loop
Control TypeEntry-controlledExit-controlled
Condition CheckTested at the beginningTested at the end
Minimum Executions0 timesAt least 1 time
Syntaxwhile(cond) { ... }do { ... } while(cond);
public class LoopDemo {
    public static void main(String[] args) {
        int sum = 0;
        for (int i = 1; i <= 5; i++) {
            if (i == 4) continue; // Skip i=4
            sum += i;
        }
        System.out.println("Sum = " + sum);
        int count = 1;
        do {
            System.out.print(count + " ");
            count++;
        } while (count <= 3);
        System.out.println();
    }
}
Sum = 11
1 2 3

Q8. What is an array? Explain 1-D and 2-D arrays with their memory layout and Java programs.

Unit I · 8 marks · both dimensions are explicitly in scope, so draw both memory diagrams and give one program for each.

Definition: An array is a fixed-size, contiguous indexed collection of homogeneous elements stored in contiguous heap memory.
  • 1D Array: single row of elements accessed by index arr[i] (0 to length-1).
  • 2D Array: array of 1D arrays forming a matrix accessed as arr[r][c].
  • Declaration only creates a reference (int marks[];); creation with new allocates heap memory and fills default values.
public class Array1DDemo {
    public static void main(String[] args) {
        int[] arr = {12, 45, 7, 23, 89, 34};
        int sum = 0;
        int max = arr[0];
        for (int val : arr) {
            sum += val;
            if (val > max) max = val;
        }
        System.out.println("Sum = " + sum + ", Max = " + max);
    }
}
Sum = 210, Max = 89
public class Array2DDemo {
    public static void main(String[] args) {
        int[][] a = {{1, 2}, {3, 4}};
        int[][] b = {{5, 6}, {7, 8}};
        int[][] sum = new int[2][2];
        for (int i = 0; i < 2; i++) {
            for (int j = 0; j < 2; j++) {
                sum[i][j] = a[i][j] + b[i][j];
                System.out.print(sum[i][j] + " ");
            }
            System.out.println();
        }
    }
}

Q9. Difference between method overloading and method overriding, with a suitable example

Unit II · 8 marks · give both definitions, the difference table, and one program for each — overloading and overriding are never demonstrated by the same code.

Method overloading: Defining two or more methods with the same name but different parameter lists (number, type or order of parameters) in the same class. The call is decided at compile time — compile-time (static) polymorphism.
Method overriding: A child class redefines a method of its parent class with the same name, same parameters and same return type. The method that runs is decided at run time by the actual object — run-time (dynamic) polymorphism.
BasisMethod overloadingMethod overriding
Same name, parametersSame name, different parametersSame name, same parameters
WhereSame classParent and child classes
PolymorphismCompile-time (static)Run-time (dynamic)
BindingStatic (early) bindingDynamic (late) binding
Return typeMay differ; alone cannot overloadSame, or covariant subclass type
InheritanceNot neededRequired
static/private/finalCan be overloadedCannot be overridden

Program 1 — overloading (same class, different parameter list):

class Calculator {
    int add(int a, int b) {              // 2 int parameters
        return a + b;
    }
    int add(int a, int b, int c) {       // different NUMBER of parameters
        return a + b + c;
    }
    double add(double a, double b) {     // different TYPE of parameters
        return a + b;
    }
}

public class OverloadDemo {
    public static void main(String[] args) {
        Calculator c = new Calculator();
        System.out.println(c.add(2, 3));       // compiler picks add(int,int)
        System.out.println(c.add(2, 3, 4));    // picks add(int,int,int)
        System.out.println(c.add(2.5, 1.5));   // picks add(double,double)
    }
}

Program 2 — overriding (parent/child, same signature):

class Vehicle {

Q10. Explain abstract class and interface in Java

Unit II · 8 marks · both definitions, the difference table, one program, and then multiple inheritance through interfaces.

Abstract class: A class declared with the abstract keyword that cannot be instantiated. It can have abstract methods (no body) and concrete methods (with body), variables and constructors. A subclass must override all abstract methods or itself be abstract.
Interface: A reference type declared with the interface keyword that defines a contract: methods are public and abstract by default and variables are public static final (constants). A class uses implements to provide the bodies. One class can implement many interfaces, which is how Java achieves multiple inheritance.
  • Abstract class rules: cannot create objects (new Account() is an error); can have constructors, instance variables; one abstract method forces the whole class to be abstract; gives partial abstraction.
  • Interface rules: methods public abstract by default, variables public static final; no constructors; implementing methods must be public; from Java 8 an interface can also have default/static methods.
BasisAbstract classInterface
Keywordabstract classinterface
MethodsAbstract and concreteAbstract (plus default/static from Java 8)
VariablesAny kind (instance, static, final)Only public static final constants
ConstructorYesNo
Inheritance keywordextendsimplements
Multiple inheritanceNo (extend only one class)Yes (implement many)
AbstractionPartialFull (for abstract methods)
Use whenRelated classes share code and stateUnrelated classes share a capability
interface Printable {                 // interface: only a contract
    void print();                     // public abstract by default
}

abstract class Account {              // abstract class: partial blueprint
    double balance;
    Account(double balance) { this.balance = balance; }
    abstract double interest();       // no body
    void show() { System.out.println("Balance = " + balance); }
}

class Savings extends Account implements Printable {
    Savings(double balance) { super(balance); }
    double interest() { return balance * 0.04; }
    public void print() { System.out.println("Interest = " + interest()); }
}

public class AbstractInterface {
    public static void main(String[] args) {
        Savings s = new Savings(10000);
        s.show();
        s.print();
    }
}
Balance = 10000.0
Interest = 400.0

Multiple inheritance through interfaces: a class can implement many interfaces at once, which is how Java gives multiple inheritance without the ambiguity of two parent classes.

  • class Smartphone implements Camera, MusicPlayer { ... } — Smartphone must give a body to every abstract method of both interfaces.
  • Java classes cannot extend two classes at once because of the diamond problem (two parents with the same method make the call ambiguous); interfaces avoid this since the implementing class always writes its own single body for each method.
Mnemonic "Abstract = Half-built house, Interface = Rule book": a half-built house already has some walls (concrete methods, variables, constructor); a rule book only lists what must be done.
If it comes as 4 marks: write both definitions, Fig 2.28, and the difference table (skip the program and the multiple-inheritance figure).
Quick recall Abstract class: extends, one only, can mix abstract + concrete + constructor. Interface: implements, many allowed, public abstract methods + public static final constants — this is how Java gets multiple inheritance.

Q11. Short note on array of objects

Unit II · usually a 4-mark short note; see the note below for the 8-mark version.

Definition: An array of objects is an array whose elements are references to objects of a class. The array stores references, not the objects themselves; each object must be created separately with new.
  • Syntax: ClassName[] arr = new ClassName[size];
  • Step 1: creating the array only creates size references, all null.
  • Step 2: create each object: arr[0] = new ClassName(...);
  • Step 3: access members through the index: arr[i].member.
  • Use: storing records of many students, employees or products and processing them in a loop.
class Student {
    String name;
    int marks;
    Student(String name, int marks) {
        this.name = name;
        this.marks = marks;
    }
}

public class StudentArray {
    public static void main(String[] args) {
        Student[] list = new Student[3];       // step 1: array of 3 references (all null)
        list[0] = new Student("Aman", 78);      // step 2: create each object
        list[1] = new Student("Riya", 91);
        list[2] = new Student("Kabir", 65);

        for (int i = 0; i < list.length; i++) { // step 3: use them
            System.out.println(list[i].name + " : " + list[i].marks);
        }
    }
}
Aman : 78
Riya : 91
Kabir : 65
Common mistake: using list[0].name before list[0] = new Student(...) throws NullPointerException, because the cell still holds null.
If it comes as 8 marks: also draw Fig 2.2 (reference lives on the stack, object lives on the heap) to explain why two separate steps are needed, and add one line comparing it with a normal array (a normal array's cells hold values directly; an array of objects' cells hold addresses).
Quick recall Array of objects = array of references; create the array first, then each object with new.

Q12. Short note on class and objects

Unit II · usually a 4-mark short note; see the note below for the 8-mark version.

Class: A user-defined blueprint (template) that describes the data members (state) and methods (behaviour) common to all its objects. A class takes no memory for data until objects are created.
Object: A real instance of a class created at run time with new. It has its own copy of the data members and occupies memory on the heap.
  • Syntax of a class: class ClassName { data members; methods; }
  • Creating an object, three steps in Car c1 = new Car();: declaration (Car c1), instantiation (new allocates memory), initialization (the constructor Car() runs).
  • Members are accessed with the dot operator: c1.brand, c1.display().
  • Every object has state (values of variables), behaviour (methods) and identity (its own memory reference).
class Car {
    String brand;          // data member (state)
    int speed;

    void accelerate(int by) {   // method (behaviour)
        speed = speed + by;
    }

    void display() {
        System.out.println(brand + " is running at " + speed + " km/h");
    }
}

public class CarDemo {
    public static void main(String[] args) {
        Car c1 = new Car();   // object 1
        c1.brand = "Tata Nexon";
        c1.accelerate(40);

        Car c2 = new Car();   // object 2, same class, own data
        c2.brand = "Maruti Swift";
        c2.accelerate(60);

        c1.display();
        c2.display();
    }
}
Tata Nexon is running at 40 km/h
Maruti Swift is running at 60 km/h
BasisClassObject
MeaningBlueprint / templateInstance of the class
MemoryNo memory for data when declaredGets memory on the heap when created
Created withclass keywordnew keyword
ExampleCarc1 (Tata Nexon), c2 (Maruti Swift)
Mnemonic "Class = cookie cutter, Object = cookie". Object has S-B-I: State, Behaviour, Identity.
If it comes as 8 marks: also draw Fig 2.2 (the reference variable lives on the stack, the object it points to lives on the heap) and add the access-modifier table (private/default/protected/public) that decides who can use a class member.

Q13. Packages

Unit II · 8 marks · define, show the built-in tree, create-compile-run a user package, list the import ways, and mention subpackages.

Definition: A package is a group of related classes and interfaces stored together in one folder, declared with the package keyword. It works like a folder in a computer. Packages are built-in (java.lang, java.util, java.io) or user-defined.
Built-in packageContains (examples)
java.langString, Math, System (imported automatically)
java.utilScanner, ArrayList, Arrays
java.ioFile, InputStreamReader, IOException
  • Advantages: avoids name conflicts, groups related classes, access protection, reusability, easier maintenance.
  • package statement must be the first statement of the file; package name = folder name (lowercase).
  • Compile with javac -d . File.java; -d . creates the package folder automatically. Classes used from outside the package must be public.

File 1 mypack/Calculator.java:

package mypack;

public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }
}

File 2 UsePackage.java (in the folder that contains mypack):

import mypack.Calculator;

public class UsePackage {
    public static void main(String[] args) {
        Calculator c = new Calculator();
        System.out.println("Sum = " + c.add(10, 20));
    }
}

Commands: javac -d . mypack/Calculator.java → javac UsePackage.java → java UsePackage

Sum = 30

1-mark questions

Q1. Define JVM and Bytecode.
JVM is an abstract execution engine that executes Java bytecode. Bytecode is the platform-independent intermediate format compiled from .java source code.
Q2. Differentiate JDK, JRE, and JVM.
JDK contains development tools + JRE; JRE contains class libraries + JVM; JVM is the execution runtime engine that runs bytecode.
Q3. What is Write Once, Run Anywhere (WORA)?
Java's principle where code compiled into bytecode on one platform can run without modification on any OS containing a compatible JVM.
Q4. What is the role of the JIT compiler?
Just-In-Time compiler compiles frequently used bytecode sequences into native CPU instructions at runtime to accelerate execution speed.
Q5. List the 8 primitive data types in Java.
byte, short, int, long, float, double, char, and boolean.
Q6. Differentiate widening and narrowing casting.
Widening is automatic conversion of a smaller type to a larger type (e.g., int to double); narrowing is manual conversion of a larger type to a smaller type with cast syntax (int) d.
Q7. What is automatic type promotion in expressions?
In expressions, byte, short, and char are promoted to int; if an operand is long, float, or double, the whole expression promotes to that larger type.
Q8. Differentiate pre-increment and post-increment operators.
Pre-increment (++x) increments the variable before evaluating its value; post-increment (x++) evaluates the current value first before incrementing.
Q9. What is short-circuit evaluation in logical operators?
In &&, if the first condition is false, the second is skipped. In ||, if the first condition is true, the second is skipped.
Q10. Explain ternary operator syntax.
Conditional shorthand: condition ? value_if_true : value_if_false;.
Q11. Differentiate while and do-while loops.
while is entry-controlled (0 min executions); do-while is exit-controlled, executing the body at least once.
Q12. Differentiate break and continue statements.
break exits the loop or switch block immediately; continue skips the remainder of the current iteration and jumps to the next loop evaluation.
Q13. What is a jagged array?
A multi-dimensional array where each row/sub-array can have a different number of columns/elements.
Q14. How is array length obtained in Java?
Using the built-in .length field of the array object (e.g., arr.length).
Q15. What are the advantages and disadvantages of arrays in Java?
Advantages: code optimization (one variable for many values) and random access (O(1) by index). Disadvantage: fixed size — cannot grow at runtime, so the Collection framework is used when size must change.
Q16. Differentiate array declaration and array creation.
Declaration (int marks[];) only creates a reference variable with no memory for elements; creation (marks = new int[6];) allocates heap memory for the given size and fills it with default values.
Q17. Define class and object.
A class is a user-defined blueprint containing fields and methods. An object is an instance of a class created with new, having its own state and memory on the heap.
Q18. What is an array of objects?
An array whose elements are references to objects of one class, e.g. Book[] b = new Book[3];. Each object must be created separately with new, otherwise the element is null.
Q19. Why does Java not support multiple inheritance with classes?
To avoid the diamond problem: if two parents have the same method, the child's call becomes ambiguous. Multiple inheritance is achieved through interfaces instead.
Q20. Differentiate overloading and overriding.
Overloading: same name, different parameters, same class, compile-time. Overriding: same signature in a child class, needs inheritance, run-time (dynamic dispatch).
Q21. What is dynamic method dispatch?
The mechanism by which a call to an overridden method through a parent-class reference is resolved at run time according to the actual object type.
Q22. What is an abstract class?
A class declared abstract that cannot be instantiated; it can have abstract (bodyless) methods, concrete methods and constructors. Subclasses must override the abstract methods.
Q23. Define interface.
A reference type with public abstract methods and public static final constants; a class uses implements to provide the bodies and may implement several interfaces.
Q24. What is a package? Name two built-in packages.
A named group of related classes and interfaces giving a namespace and access control. Examples: java.lang, java.util.
