Q1. Explain JDK, JRE and JVM, and describe the internal architecture of the JVM with the compilation-execution pipeline.

Unit I · 8 marks · Exam focus: Define JDK, JRE, and JVM clearly, illustrate the compile-and-run pipeline, open up the JVM into its internal subsystems, and explain how bytecode is executed.

Definition: The JVM (Java Virtual Machine) is the abstract execution engine that loads, verifies, and executes intermediate bytecode (.class files) by translating it into native machine code. JDK is the full development kit (compiler javac + tools + JRE); JRE is the runtime environment (JVM + standard runtime class libraries like rt.jar).
// Every Java program must be inside a class
public class HelloWorld {
    // Entry point method executed by the JVM launcher
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
Hello, Java!
  • Execution Pipeline (Fig 1.6):
    1. Write: You author human-readable code in HelloWorld.java.
    2. Compile: Running javac HelloWorld.java invokes the Java compiler, translating your code into platform-independent intermediate bytecode stored in HelloWorld.class.
    3. Execute: Running java HelloWorld starts the JVM, which loads the bytecode, verifies its integrity, and translates it into native CPU instructions for the host operating system.
ComponentFull FormTarget AudienceWhat It Contains
JDKJava Development KitSoftware DevelopersDevelopment Tools (javac, jar, javadoc, jdb) + JRE
JREJava Runtime EnvironmentEnd Users / ClientsJVM + Core Runtime Class Libraries (e.g. java.lang, java.util)
JVMJava Virtual MachineThe Operating SystemClass Loader + Runtime Memory Areas + Execution Engine (Interpreter, JIT, GC)
  • 1. Class Loader Subsystem: Responsible for bringing .class bytecode files into memory through three sequential phases:
    • Loading: Reads the binary bytecode from disk into the JVM memory.
    • Linking: Divided into three security steps:
      • Verify: Checks that bytecode conforms to Java language specifications and does not corrupt system memory.
      • Prepare: Allocates memory for static variables and assigns their default primitive values.
      • Resolve: Replaces symbolic memory references with direct physical memory pointers.
    • Initialization: Executes static blocks and assigns actual initial values to static variables.
  • 2. Runtime Data Areas (JVM Memory Layout):
    • Method Area (Shared across threads): Stores class-level data, method codes, static variables, and runtime constant pools.
    • Heap Area (Shared across threads): The central storage where ALL objects, instances, and arrays are allocated using new. Automatically managed by the Garbage Collector.
    • Java Stack (Thread-isolated): Created per thread. Every method invocation creates a temporary Stack Frame storing local variables, intermediate calculations, and return addresses. When the method finishes, its frame is destroyed.
    • PC (Program Counter) Register (Thread-isolated): Holds the exact physical memory address of the JVM bytecode instruction currently being executed by the thread.
    • Native Method Stack (Thread-isolated): Manages low-level native C/C++ function calls invoked via the Java Native Interface (JNI).
  • 3. Execution Engine: The computational heart that executes the loaded instructions:
    • Interpreter: Reads bytecode instructions one-by-one and executes them. Fast to start up, but slower for repeated loops.
    • JIT (Just-In-Time) Compiler: Monitors execution to identify "hotspot" code (frequently executed loops). It compiles these hotspots directly into native machine code, boosting execution speed up to native C++ levels.
    • Garbage Collector (GC): Automatically tracks and reclaims memory occupied by abandoned objects on the heap that no longer have any active references.
  • Why Java is "Write Once, Run Anywhere" (WORA): Bytecode is 100% platform-independent. The JVM translates bytecode into local CPU machine instructions. While the JVM itself is platform-dependent (different installers for Windows, Linux, macOS), the compiled .class file runs identically on all of them without changing a single line of code!
Common mistake: Do not confuse bytecode with machine code. Bytecode is the intermediate instruction set understood only by the JVM; the JVM converts bytecode into native CPU machine instructions.

Q2. Explain the features (buzzwords) of Java. Why is Java called platform independent?

Unit I · 8 marks · Exam focus: The 12 official Java buzzwords defined in simple English, followed by a dedicated breakdown of Platform Independence (WORA).

Definition: Java is an object-oriented, class-based, high-level, concurrent, and platform-independent programming language designed in 1995 by James Gosling at Sun Microsystems. Its core design philosophy is embodied in 12 foundational architectural features known as the Java Buzzwords.
  • 1. Simple: Syntax is clean and derived from C++, but intentionally removes confusing, error-prone features like direct memory pointers, multiple inheritance through classes, and operator overloading. Memory is automatically managed by Garbage Collection.
  • 2. Object-Oriented: Everything in Java revolves around classes and objects encapsulating data (state) and methods (behavior), enforcing the 4 OOP pillars: Abstraction, Encapsulation, Inheritance, and Polymorphism.
  • 3. Platform Independent (WORA): You compile your source code once, and the resulting bytecode runs on any operating system that has a compatible JVM installed.
  • 4. Secured: Programs run inside the controlled JVM "sandbox". With no raw pointers, applications cannot accidentally or maliciously access private operating system memory. The Bytecode Verifier checks for safety before execution.
  • 5. Robust (Crash-Resistant): Emphasizes early bug detection: strict compile-time type checking, mandatory run-time exception handling (try-catch), and automatic Garbage Collection that prevents memory leaks.
  • 6. Architecture Neutral: Primitive data type sizes never change across hardware platforms. In C, an int can be 2 bytes on a 16-bit CPU and 4 bytes on a 32-bit CPU; in Java, an int is strictly 4 bytes on every machine on Earth.
  • 7. Portable: The compiled bytecode file (.class) can be copied to any computer via USB, email, or network, running without recompilation.
  • 8. Dynamic: Classes are linked dynamically on-demand at runtime. New classes, libraries, and methods can be linked into a running application without restarting it.
  • 9. Interpreted: The JVM execution engine reads and interprets intermediate bytecode instructions on the fly into native machine code.
  • 10. High Performance: The modern Just-In-Time (JIT) compiler detects frequently executed code and translates it directly into native CPU instructions, delivering performance comparable to compiled languages like C++.
  • 11. Multithreaded: Java has built-in language-level support for running multiple threads concurrently (e.g. playing audio while downloading a file), sharing common heap memory efficiently.
  • 12. Distributed: Engineered for the internet era. Java includes rich networking libraries (TCP/IP, HTTP) and Remote Method Invocation (RMI), allowing a program on one computer to invoke methods running on a completely different server across the globe.
Mnemonic Remember the 12 buzzwords in 3 friendly groups of 4:
• SOPS: Simple, Object-Oriented, Platform-Independent, Secured.
• RAPD: Robust, Architecture-Neutral, Portable, Dynamic.
• IHMD: Interpreted, High-Performance, Multithreaded, Distributed.
If it comes as a 4-mark question: Write the definition, draw Fig 1.4, and explain the 4 most critical buzzwords: Simple, Platform Independent, Robust, and Multithreaded.
Quick recall 12 Buzzwords grouped as SOPS, RAPD, IHMD. Platform independence = javac compiles to universal bytecode → JVM translates to host CPU instructions = Write Once, Run Anywhere.

  • Widening Type Casting (Implicit / Automatic): Converting a smaller data type into a larger data type.

        // Widening: byte -> int (automatic, safe)
        byte b = 42;
        int i = b;

        int x = (int) d; // x becomes 99, 0.78 is lost!

        System.out.println("Narrowed int: " + x);

Q4. What is an array? Write a Java program to find the largest and smallest element in an array.

Unit I · 8 marks · Exam focus: Definition, contiguous heap memory layout, zero-based indexing, and a working program that finds both the maximum and minimum element in one pass.

Definition: An array in Java is a dynamically created container object that holds a fixed number of homogeneous (same-type) values stored in contiguous memory locations on the heap, accessed using zero-based integer indices.
  • 1D Array: A linear sequence of elements accessed by index arr[i] ranging from 0 to arr.length - 1.
  • 2D Array: In Java, a 2D array is technically an array of arrays, accessed as arr[row][col]; each row can even have a different length (a jagged array).
  • Memory Mechanics: The array variable (e.g. int[] marks) is a reference stored on the Stack. The actual array contents are allocated on the Heap when instantiated with the new keyword.
  • Largest/Smallest Algorithm: Assume the first element is both the current largest and smallest, then scan every remaining element once — whenever a value beats the current largest, replace it; whenever a value is below the current smallest, replace that too. One pass, O(n) time.
public class ArrayMinMax {
    public static void main(String[] args) {
        int[] arr = {12, 45, 7, 23, 89, 34};
        int max = arr[0], min = arr[0];

        // single pass: update max and min together
        for (int val : arr) {
            if (val > max) max = val;
            if (val < min) min = val;
        }
        System.out.println("Largest = " + max + ", Smallest = " + min);
    }
}
Largest = 89, Smallest = 7
Common mistake: Accessing index arr[arr.length] throws ArrayIndexOutOfBoundsException. The highest valid index is always arr.length - 1 because Java arrays start at index 0. Also initialize both max and min to arr[0], never to 0 — an array of only negative numbers would otherwise give a wrong "largest".
If it comes as a 4-mark question: Write the definition, draw Fig 1.21, and give the program (skip the 2D array point).

Q5. What is containership in Java? Explain with an example, and differentiate it from inheritance.

Unit II · 8 marks · Exam focus: Definition of containership/composition as a HAS-A relationship, how it differs from inheritance's IS-A relationship, and a working delegation example.

Definition: Containership (composition / aggregation) is a relationship in which a class contains an object of another class as its data member. It represents a HAS-A relationship and reuses code by delegating work to the contained object.
  • Implemented by declaring a reference field of another class: Engine engine;
  • The outer class delegates work to it: engine.start().
  • Loose coupling: the contained object can be replaced without changing any class hierarchy.
  • Textbooks split it into composition (part cannot exist without the whole, strong) and aggregation (part can exist separately, weak).
  • Rule of thumb: prefer HAS-A over IS-A (inheritance) when "X is a Y" sounds wrong — a Bike is not an Engine, but it has one.
class Engine {
    int cc;
    Engine(int cc) { this.cc = cc; }
    void start() { System.out.println(cc + " cc engine started"); }
}

class Bike {
    String model;
    Engine engine;                  // Bike HAS-A Engine (containership)

    Bike(String model, int cc) {
        this.model = model;
        engine = new Engine(cc);    // contained object created inside
    }
    void ride() {
        engine.start();             // work delegated to the contained object
        System.out.println(model + " is running");
    }
}

public class BikeEngine {
    public static void main(String[] args) {
        new Bike("Pulsar", 150).ride();
    }
}

Pulsar is running

Q6. Short note on class and objects

Unit II · 4 or 8 marks · Exam focus: Clear definitions, the 3 steps of object creation, memory distribution (stack vs heap), State-Behavior-Identity characteristics, and access modifiers.

Class: A user-defined blueprint or template that defines the data members (state) and methods (behavior) common to all objects created from it. A class declaration consumes zero memory for data until an object is instantiated.
Object: An identifiable runtime instance of a class created on the heap with the new keyword. It possesses its own private copy of the class's instance variables and consumes physical memory.
  • The Three Steps of Object Creation: In the statement Car c1 = new Car();:
    1. Declaration: Car c1 declares a reference variable named c1 of type Car on the Stack.
    2. Instantiation: The new keyword allocates memory on the Heap for the new object.
    3. Initialization: The constructor Car() executes, initializing the object's instance variables.
  • The Three Universal Properties of Any Object (SBI):
    • State: The values stored in its instance variables (e.g. brand = "Tata Nexon", speed = 40).
    • Behavior: The actions it can perform via its methods (e.g. accelerate()).
    • Identity: A unique memory address managed internally by the JVM distinguishing it from all other objects.
class Car {
    String brand; // State (data member)
    int speed;

    void accelerate(int by) { // Behavior (method)
        speed += by;
    }

    void display() {
        System.out.println(brand + " running at " + speed + " km/h");
    }
}

public class CarDemo {
    public static void main(String[] args) {
        Car c1 = new Car(); // Object 1
        c1.brand = "Tata Nexon";
        c1.accelerate(50);

        Car c2 = new Car(); // Object 2
        c2.brand = "Maruti Swift";
        c2.accelerate(70);

        c1.display();
        c2.display();
    }
}
Tata Nexon running at 50 km/h
Maruti Swift running at 70 km/h

Q7. Explain constructors and their types in Java, with an example.

Unit II · 8 marks · Exam focus: The constructor rules (same name, no return type, auto-called by new), the four types, and one program that exercises all of them.

Definition: A constructor is a special member of a class that has the same name as the class, has no return type (not even void), and is called automatically by new to initialise a newly created object.
  • Default constructor: if a class has no constructor, the compiler adds one with no parameters; fields get default values (0, null, false). It disappears as soon as you write any constructor of your own.
  • No-arg constructor: written by the programmer with no parameters, to set fixed starting values.
  • Parameterized constructor: takes arguments, so each object can start with different values: new Point(3, 4).
  • Copy constructor: takes an object of the same class and copies its fields: Point(Point p). Java does not provide it automatically (unlike C++); the programmer writes it.
  • Constructor overloading: several constructors in one class that differ in parameter list; new picks the matching one, exactly like method overloading.
class Point {
    int x, y;
    Point() { x = 0; y = 0; }    // no-arg constructor
    Point(int a, int b) {        // parameterized constructor (overloaded)
        x = a; y = b;
    }
    Point(Point p) {             // copy constructor (we write it ourselves)
        x = p.x; y = p.y;
    }
    void show(String label) {
        System.out.println(label + " = (" + x + ", " + y + ")");
    }
}

class Empty { int n; }           // no constructor: compiler adds default one

public class ConstructorTypes {
    public static void main(String[] args) {
        Point p1 = new Point();         p1.show("p1");
        Point p2 = new Point(3, 4);     p2.show("p2");
        Point p3 = new Point(p2);       p3.show("p3 (copy of p2)");
        System.out.println("Empty n = " + new Empty().n);
    }
}

Q8. What is polymorphism? Explain the types of inheritance in Java.

Unit II · 8 marks · Exam focus: A one-line polymorphism recap (Q10 has the full overloading/overriding answer), then the 5 types of inheritance, which three Java supports directly with extends, and why the other two need interfaces.

Polymorphism: The ability of the same method call to behave differently depending on the arguments passed (compile-time / static polymorphism, via method overloading) or the actual object on the heap (run-time / dynamic polymorphism, via method overriding). See Q10 for the full definitions, table, and both programs.
Inheritance: The mechanism by which one class (subclass / child) acquires the fields and methods of another class (superclass / parent) using the extends keyword. It represents an IS-A relationship. Based on how classes connect, it comes in 5 types: single, multilevel, hierarchical, multiple and hybrid.
  • IS-A test: "ElectricCar is a Car, Car is a Vehicle" makes sense, so inheritance fits.
  • A class can extends only one class — Java classes never support multiple inheritance directly.
  • Multiple (one child, two+ parents) and Hybrid (a mix) are achieved only through interfaces, to avoid the Diamond Problem: if two parent classes both implemented the same method differently, the child's call would be ambiguous. Interfaces have no method body to conflict, so this never arises (see Q11).

class Account {

Q9. Explain static data members, static methods and static blocks in Java.

Unit II · 8 marks · Exam focus: The "one shared copy" definition, instance vs static comparison table, static block execution order, and a counter program.

Definition: A static data member (class variable) is declared with static and has only one copy shared by all objects of the class; it is created when the class is loaded. A static method belongs to the class and can be called without an object, and a static block runs once when the class is loaded.
  • Shared copy: change it through any object or the class name, all objects see the new value. Good for counters, rates, constants.
  • Access it as ClassName.var (preferred), e.g. Visitor.count.
  • Static method: called as ClassName.method(); can use static members directly but cannot use instance variables, this or super directly. main is static so the JVM can call it without an object.
  • Static block static { ... }: runs once when the class is loaded, before any object; used to initialise static data.

Program: object counter using a static variable, static block and static method.

class Visitor {
    static int count;            // ONE shared copy for all objects
    String name;                 // separate copy in each object

    static {                     // static block: runs once, when class loads
        count = 0;
        System.out.println("static block ran");
    }
    Visitor(String n) {
        name = n;
        count++;                 // every new object updates the shared copy
    }
    static void report() {       // static method: called without an object
        System.out.println("Visitors so far = " + count);
    }
}

public class CounterDemo {

Q10. Difference between method overloading and method overriding, with a suitable example

Unit II · 8 marks · Exam focus: Provide clear definitions for both, a comprehensive comparison table, and two distinct code programs (overloading and overriding must never be demonstrated in the same code snippet!).

Method Overloading: Defining two or more methods with the same name but different parameter lists (varying by number, type, or order of parameters) within the same class. The method call is resolved at compile time — known as Compile-time (Static) Polymorphism.
Method Overriding: When a subclass (child) provides its own specific implementation of a method that is already defined in its superclass (parent), using the exact same name, same parameter list, and compatible return type. The method to execute is resolved at run time based on the actual object instance — known as Run-time (Dynamic) Polymorphism.

Important Exam Warning on Operator Overloading: Unlike C++, Java does not support user-defined operator overloading (to maintain simplicity and avoid code obfuscation). The only built-in overloaded operator in Java is the + operator, which performs addition on numbers and concatenation on String objects. Program 1 — Method Overloading (Inside One Class):

class Calculator {
    // 1. Two integer parameters
    int add(int a, int b) {
        return a + b;
    }
    // 2. Overloaded by NUMBER of parameters (three integers)
    int add(int a, int b, int c) {
        return a + b + c;
    }
    // 3. Overloaded by TYPE of parameters (two doubles)
    double add(double a, double b) {
        return a + b;
    }
}

public class OverloadDemo {
    public static void main(String[] args) {
        Calculator c = new Calculator();
        System.out.println("2 ints: " + c.add(5, 10));       // Calls add(int, int)
        System.out.println("3 ints: " + c.add(5, 10, 15));   // Calls add(int, int, int)
        System.out.println("2 doubles: " + c.add(2.5, 3.5)); // Calls add(double, double)
    }
}

Program 2 — Method Overriding (Inheritance — Parent and Child Classes):

class Vehicle {
    // Parent method
    void run() {
        System.out.println("Vehicle is running on the road");
    }
}

public class OverrideDemo extends Vehicle {
    // Overriding parent method with child-specific implementation
    @Override
    void run() {
        System.out.println("Bike is running safely at 60 km/h");
    }

    public static void main(String[] args) {
        // Parent reference pointing to child object (Dynamic Method Dispatch)
        Vehicle v = new OverrideDemo();
        v.run(); // Calls the overridden child method at runtime!
    }
}

Q11. Explain abstract class and interface in Java

Unit II · 8 marks · Exam focus: Detailed definitions, comparison table, working code example, and how interfaces achieve Multiple Inheritance safely without the Diamond Problem.

Abstract Class: A class declared with the abstract keyword that cannot be directly instantiated with new. It serves as a partial template and can contain both abstract methods (without bodies) and concrete methods (with bodies), instance variables, and constructors.
Interface: A pure specification blueprint declared with the interface keyword defining a strict contract. All methods are public and abstract by default, and variables are public, static, and final constants. A class uses the implements keyword to provide method bodies. A single class can implement multiple interfaces, giving Java clean Multiple Inheritance.

// Interface defining a pure contract
interface Printable {
    void print(); // public abstract by default
}

// Abstract class providing a partial blueprint with state and constructor
abstract class Account {
    double balance;
    Account(double balance) {
        this.balance = balance;
    }
    abstract double computeInterest(); // Must be implemented by child
    void display() {
        System.out.println("Current Balance = " + balance);
    }
}

// Concrete class extending one class and implementing an interface
class SavingsAccount extends Account implements Printable {
    SavingsAccount(double balance) {
        super(balance);
    }
    @Override
    double computeInterest() {
        return balance * 0.05; // 5% interest
    }
    @Override
    public void print() {
        System.out.println("Savings Statement -> Interest: " + computeInterest());
    }
}

public class AbstractInterfaceDemo {
    public static void main(String[] args) {
        SavingsAccount sa = new SavingsAccount(10000);
        sa.display();
        sa.print();
    }
}
Current Balance = 10000.0
Savings Statement -> Interest: 500.0

Multiple Inheritance Through Interfaces (Resolving the Diamond Problem)

In C++, if class D inherits from both class B and class C which both inherit from class A, method calls become ambiguous if B and C both implemented the same method with different code (the notorious Diamond Problem). Java strictly forbids extending multiple classes. However, Java allows implementing multiple interfaces (Fig 2.16) because interfaces contain only method declarations without bodies—the child class writes its own single implementation, eliminating any ambiguity!

Intuitive Analogy: An Abstract Class is like a half-built house (it has some solid walls and a foundation, but some rooms are left for you to finish). An Interface is an architectural blueprint or contract (it lists the exact rooms that must exist, but provides zero bricks or mortar).

Quick recall Abstract class = extends, partial blueprint, can have constructors & instance variables. Interface = implements, pure contract, constants only, enables Multiple Inheritance safely without the Diamond Problem.

1-mark questions

Quick revision flashcards · High-yield 1-mark concepts written in clear, direct English with supporting micro-diagrams for instant exam recall.

Q1

Define JVM and Bytecode.

Bytecode: The platform-independent intermediate instruction set compiled from .java source code by javac.
JVM: The runtime engine that loads, verifies, and executes bytecode by translating it into native CPU machine code.
Flow: Source (.java) → javac → Bytecode (.class) → JVM execution.
Q2

Differentiate JDK, JRE, and JVM.

JDK: Complete developer toolbox containing compiler (javac) + tools + JRE.
JRE: Runtime package for running apps containing core class libraries + JVM.
JVM: The actual execution engine that runs bytecode.
Nesting: JDK = JRE + Tools; JRE = JVM + Core Libraries.
Q3

What is Write Once, Run Anywhere (WORA)?

Java source code is compiled into universal intermediate bytecode. Any computer with a compatible JVM installed can execute this bytecode without recompiling, making Java platform-independent.
Key concept: Bytecode is platform-independent; JVM is platform-dependent.
Q4

What is the role of the JIT compiler?

The Just-In-Time (JIT) compiler monitors bytecode at runtime, identifies frequently executed "hotspot" loops, and compiles them directly into native machine code to dramatically boost execution speed.
Role: Compiles hot bytecode into native CPU instructions at runtime.
Q5

List the 8 primitive data types in Java.

Scalar types stored directly on the stack:
• Integers: byte (1B), short (2B), int (4B), long (8B)
• Floating-point: float (4B), double (8B)
• Character & Boolean: char (2B Unicode), boolean (true/false)
Key numbers: byte(1), short(2), int(4), long(8), float(4), double(8), char(2).
Q6

Differentiate widening and narrowing type casting.

Widening (Implicit): Converting smaller type to larger type (e.g. int → double); automatic and safe.
Narrowing (Explicit): Converting larger type to smaller type (e.g. double → int); manual cast (int), may truncate data.
Rule: Widening is automatic; Narrowing requires explicit cast syntax.
Q7

Differentiate method overloading and overriding.

Overloading: Same class, same name, different parameters; resolved at compile time.
Overriding: Parent-child classes, exact same name and parameters; resolved at runtime via dynamic dispatch.
Key difference: Compile-time (Overloading) vs Run-time (Overriding).
Q8

What is the significance of the static keyword?

Declares class-level members (variables or methods) shared across all objects. A static method can be invoked directly on the class name without creating an instance with new.
Role: Belong to the class, not individual instances; accessed without new.
Q9

What is an abstract class?

A class declared with abstract that cannot be instantiated with new. It can contain both abstract methods (no body) and concrete methods (with body), instance variables, and constructors.
Key takeaway: Partial blueprint; cannot be instantiated directly.
Q10

What is an interface in Java?

A pure contract blueprint where all methods are public abstract by default, and all variables are public static final constants. Implemented using implements to achieve Multiple Inheritance.
Key takeaway: Pure contract; enables multiple inheritance safely.
Q11

Differentiate while and do-while loops.

while: Entry-controlled; checks condition before running body (can execute 0 times).
do-while: Exit-controlled; checks condition after running body (guaranteed at least 1 execution).
Key difference: Check first (0+ runs) vs Run first (1+ runs).
Q12

What is a package in Java?

A directory container grouping related classes and interfaces. Prevents namespace naming collisions, controls access visibility, and is compiled using javac -d . File.java.
Key takeaway: Namespace folder container; prevents naming collisions.
Q13

What is an Array of Objects?

An array holding references to objects rather than primitive values. Step 1 (new Student[3]) creates null references; Step 2 (new Student()) creates each individual object on the heap.
Key rule: Array stores references on stack/heap; objects allocated separately.
Q14

Why does Java not support multiple inheritance with classes?

To avoid the Diamond Problem where inheriting conflicting implementations of the same method from two parent classes causes ambiguity. Java uses interfaces instead because interfaces have no method bodies to conflict.
Solution: Multiple inheritance is allowed in Java only through interfaces.
Q15

What is the difference between break and continue?

break: Immediately exits and terminates the entire innermost loop or switch block.
continue: Skips only the rest of the current iteration and jumps directly to the next loop evaluation.
Rule: break terminates; continue skips current pass.
Q16

List the four types of constructors in Java.

Default: compiler-added, no parameters.
No-arg: programmer-written, no parameters.
Parameterized: takes arguments so each object differs.
Copy: copies another object's fields (written manually, not automatic like C++).
Key rule: a constructor has the same name as the class and no return type.
Q17

What is containership (composition) in Java?

A class holding an object of another class as a data member — a HAS-A relationship (e.g. a Bike has an Engine), unlike inheritance's IS-A relationship.
Key difference: IS-A (inheritance, extends) vs HAS-A (containership, reference field).
Q18

List the five types of inheritance. Which does Java support directly?

Single, Multilevel, Hierarchical, Multiple, Hybrid. Java classes support only Single, Multilevel, Hierarchical directly with extends; Multiple and Hybrid need interfaces (to avoid the diamond problem).
Rule: S-M-H via extends; M-H only via interfaces.
