2.1 Classes and objects

A class is the plan of a house; an object is the actual house built from that plan. (class = naksha, object = asli ghar)

Definition: A class is a user-defined blueprint that groups data (fields) and behaviour (methods) under one name. An object is an instance of a class: a real entity created in memory with the new keyword, having its own state (field values) and sharing the class's behaviour.
  • Members of a class: fields (variables that store state) and methods (functions that act on the state). Constructors and blocks also live inside a class.
  • State + behaviour + identity: every object has field values (state), methods (behaviour) and its own memory location (identity).
  • A class takes no memory for fields until an object is created; each object gets its own copy of instance variables.
  • new does three things: allocates memory on the heap, runs the constructor, returns the reference. (new = memory + constructor + address)
  • The dot operator (s1.name, s1.show()) reaches a member through a reference.
  • A class body can hold six kinds of members: data members, methods, constructors, blocks, nested classes and interfaces. General shape: class ClassName { // fields // methods }; an object is then declared as ClassName obj = new ClassName();.
  • Student s1; only makes a reference (value null). s1 = new Student(); makes the object.
  • Student s3 = s1; copies the reference, not the object: both names now point to one object (see output line 3 below).
  • Unreferenced objects are later removed by the garbage collector; Java has no delete.

Instance variables vs local variables: a field declared inside the class body (outside every method) is an instance variable — it gets memory only when an object is created with new, and every object carries its own copy. 2.2 Array of objects

A shelf with numbered slots, and each slot holds the address of a book. (array me objects nahi, unke address rehte hain)

Definition: An array of objects is an array whose every element is a reference to an object of the same class. Book[] shelf = new Book[3]; creates 3 references (all null); each object must then be created separately with new.
  • Two steps: (1) create the array of references, (2) create each object with new. (pehle khaane, phir saaman)
  • Using shelf[0].title before step 2 throws NullPointerException.
  • Useful for records: list of students, books, IRCTC passengers on one ticket, etc.
  • Loop with shelf.length to process all objects.
class Book {
    String title;
    int price;

    Book(String t, int p) {
        title = t;
        price = p;
    }
}

public class ArrayOfObjects {
    public static void main(String[] args) {
        Book[] shelf = new Book[3];          // 3 references, all null
        shelf[0] = new Book("Java", 450);    // now create the objects
        shelf[1] = new Book("DBMS", 380);
        shelf[2] = new Book("C++", 300);
        int total = 0;
        for (int i = 0; i < shelf.length; i++) {
            System.out.println(shelf[i].title + " Rs." + shelf[i].price);
            total = total + shelf[i].price;
        }
        System.out.println("Total = Rs." + total);
    }
}
Java Rs.450
DBMS Rs.380
C++ Rs.300
Total = Rs.1130
Common mistake: thinking new Book[3] creates three books. It creates three empty (null) slots only.
Quick recall Array of objects = array of references; create array first, then each object with new.

2.3 Objects as function arguments and returning objects

Giving a friend a photocopy of your house address: they can repaint your house, but changing the address on their paper does not move your house. (address ki copy jaati hai)

Definition: When an object is passed to a method, Java passes a copy of the reference (Java is always pass-by-value). The method can change the object's fields through that copy, but reassigning the parameter to a new object does not affect the caller's variable.
  • Modify fields inside the method (b.size = ...): the caller sees it, because both references point to the same object.
  • Reassign parameter (b = new Box()): only the local copy changes; caller's x still points to the old object.
  • Primitives (int, double) are also passed by value, so a method can never change the caller's primitive variable.
  • Returning an object: a method can create an object and return its reference (static Box makeDouble(Box b)); the object stays alive as long as someone refers to it.
class Box { int size; }

public class PassObject {
    static void grow(Box b) {        // b gets a COPY of the reference
        b.size = b.size + 10;        // same object changed: visible outside
    }
    static void replace(Box b) {
        b = new Box();               // b now points elsewhere: NOT visible
        b.size = 999;
    }
    static Box makeDouble(Box b) {   // method RETURNING an object
        Box r = new Box();
        r.size = b.size * 2;
        return r;
    }
    public static void main(String[] args) {
        Box x = new Box();
        x.size = 5;
        grow(x);    System.out.println("after grow    : " + x.size);
        replace(x); System.out.println("after replace : " + x.size);
        Box y = makeDouble(x);
        System.out.println("returned object: " + y.size);
    }
}

2.4 Scope resolution operator (and how Java does it)

C++ uses :: to say "the one that belongs to that class"; Java says the same thing with a dot and the words this, super or the class name. (Java me :: nahi, dot se kaam chalta hai)

Definition: In C++, the scope resolution operator :: is used to access a global variable hidden by a local one, define member functions outside the class, and reach static members. Java has no :: scope resolution operator; it resolves such names using this.member, ClassName.staticMember and super.member.
  • this: reference to the current object. Needed when a parameter shadows a field: this.cc = cc;
  • ClassName.member: reaches static fields and methods, e.g. Math.sqrt(), Child.count.
  • super: reaches the parent's version of a hidden field or overridden method: super.value, super.show().
  • Why Java does not need ::: there are no global variables (everything is inside a class) and method bodies are always written inside the class.
  • Java 8 did add ::, but only as a method reference (System.out::println), not for scope resolution.

2.5 Static data members, static methods and static block

A classroom whiteboard: every student has their own notebook, but there is one whiteboard shared by all. (static = sabka ek common copy)

Definition: A static data member (class variable) is declared with static and has only one copy shared by all objects of the class; it is created when the class is loaded. A static method belongs to the class and can be called without an object, and a static block runs once when the class is loaded.
  • Shared copy: change it through any object or the class name, all objects see the new value. Good for counters, rates, constants.
  • Access it as ClassName.var (preferred), e.g. Visitor.count.
  • Static method: called as ClassName.method(); can use static members directly but cannot use instance variables, this or super directly. main is static so the JVM can call it without an object.
  • Static block static { ... }: runs once when the class is loaded, before any object; used to initialise static data.
  • Instance variable vs static: instance = one copy per object; static = one copy per class.

A static field you already use every day: System (package java.lang) declares three predefined static fields — in (keyboard, standard input stream), out (monitor, standard output stream) and err (monitor, standard error stream). That is exactly why System.out.println(...) works in every program without ever creating an object of System: out is reached as ClassName.member, the same rule as Visitor.count above.

public class SystemStaticDemo {
    public static void main(String[] args) {
        System.out.println("out is a static field of the System class");
        java.io.PrintStream p1 = System.out;   // read the static field
        java.io.PrintStream p2 = System.out;   // read it again
        System.out.println("p1 == p2 ? " + (p1 == p2));
    }
}

2.6 Methods and method overloading

A method is a labelled job a class knows how to do; call it by name and it does that job, as many times as you like. (kaam ka naam do, jab chaho bulao)

Definition: A method is a named block of statements, grouped together to perform one task, declared inside a class. Method overloading is having two or more methods in the same class with the same name but a different parameter list (number, type or order of parameters).
  • modifiers (optional): access level (public, private, ...) plus keywords like static.
  • return type: void if the method returns nothing, otherwise the type of value it sends back with return.
  • method name: a valid identifier, by convention starting with a lower-case letter.
  • parameter list: the values the caller passes in, listed in parentheses after the name; can be empty.
  • method body: the statements between { } that do the work.
  • Java has no free-standing functions: every method is declared inside some class.
  • Two kinds by how they are called: an instance method needs an object (obj.method()) and may use instance variables; a class (static) method is called on the class itself (ClassName.method()) and cannot use instance variables unless it creates an object first.

(b) Method overloading: a class can have several methods with the same name, as long as their parameter lists differ. The compiler matches each call to the correct one by counting and typing the arguments, before the program ever runs. This is different from method overriding (same name, same parameter list, in a parent/child pair, resolved while the program runs) — see 2.10 Polymorphism.

  • Overloading by changing the data type of the arguments: sum(int, int) and sum(float, float).
  • Overloading by changing the number of arguments: sum(int, int) and sum(int, int, int).
  • Java matches the name first, then the number and type of arguments, to pick the right overload.
  • Return type alone cannot overload a method: int f() and double f() together are a compile error.

        cal.sum(8, 5);           // sum(int, int) is called
        cal.sum(4.6f, 3.8f);     // sum(float, float) is called
    }

2.7 Constructors and their types

A constructor is the setup step that runs automatically the moment an object is born, like filling a form while opening a bank account. (object bante hi apne aap chalta hai)

Definition: A constructor is a special member of a class that has the same name as the class, has no return type (not even void), and is called automatically by new to initialise a newly created object.
  • Default constructor: if a class has no constructor, the compiler adds one with no parameters; fields get default values (0, null, false). It disappears as soon as you write any constructor.
  • No-arg constructor: written by the programmer with no parameters, to set fixed starting values.
  • Parameterized constructor: takes arguments, so each object can start with different values: new Point(3, 4).
  • Copy constructor: takes an object of the same class and copies its fields: Point(Point p). Java does not provide it automatically (unlike C++); we write it ourselves.
  • Constructor overloading: several constructors in one class that differ in parameter list; new picks the matching one.
Textbook variation: some books call the programmer-written no-arg constructor the "default constructor" too. Strictly, the default constructor is the one the compiler supplies.
class Point {
    int x, y;
    Point() { x = 0; y = 0; }    // no-arg constructor
    Point(int a, int b) {        // parameterized constructor (overloaded)
        x = a; y = b;
    }
    Point(Point p) {             // copy constructor (we write it ourselves)
        x = p.x; y = p.y;
    }
    void show(String label) {
        System.out.println(label + " = (" + x + ", " + y + ")");
    }
}

class Empty { int n; }           // no constructor: compiler adds default one

public class ConstructorTypes {
    public static void main(String[] args) {

        Point p2 = new Point(3, 4);     p2.show("p2");
        Point p3 = new Point(p2);       p3.show("p3 (copy of p2)");
        System.out.println("Empty n = " + new Empty().n);
    }
}

Constructor chaining: one constructor calling another. this(...) calls another constructor of the same class; super(...) calls the parent constructor. Either must be the first statement, so a constructor can use only one of them. If neither is written, the compiler inserts super(), so the parent part is always built first.

class Person {
    Person() {
        System.out.println("1. Person() runs first");
    }
}

class Employee extends Person {
    int salary;

    Employee() {
        this(25000);             // this(): calls another constructor of SAME class
        System.out.println("3. Employee() finishes last");
    }
    Employee(int s) {
        super();                 // super(): calls parent constructor, must be 1st line
        salary = s;
        System.out.println("2. Employee(int) salary = " + salary);
    }
}

public class ChainDemo {
    public static void main(String[] args) {
        new Employee();
    }
}

Class-notes example — constructor overloading: two constructors with a different number of parameters; new matches by the argument list, exactly like method overloading.

public class Sum {
    int a, b, c;

    Sum(int x, int y) {                // constructor with 2 parameters
        a = x;
        b = y;
    }
    Sum(int x, int y, int z) {         // constructor with 3 parameters (overloaded)

        b = y;

        System.out.println("Sum is " + (a + b + c));
    }

Common mistake: forgetting that an unset field still compiles. In Sum s1 = new Sum(10, 11), field c is never assigned by the 2-parameter constructor, so it keeps its default value 0 — that is why 10 + 11 + 0 = 21, not an error.

Rules of constructors

  • Name must be exactly the class name; no return type.
  • Cannot be static, final or abstract; access modifiers are allowed (a private constructor blocks outside object creation).
  • this() or super() must be the first statement; not both.
  • Constructors are not inherited, so they cannot be overridden, but they can be overloaded.

2.8 Inheritance, extends and super

A child inherits the family surname and property, and can add things of its own. (baap ka sab bete ko milta hai, beta apna bhi jod sakta hai)

Definition: Inheritance is the mechanism by which one class (subclass / child) acquires the fields and methods of another class (superclass / parent) using the extends keyword. It represents an IS-A relationship and provides code reusability.
  • Syntax: class Child extends Parent { ... }. A class can extend only one class.
  • Reusability: write common code once in the parent; children reuse it. (code dobara nahi likhna)
  • IS-A test: "Dog is an Animal" makes sense, so inheritance fits.
  • Child inherits non-private members; private members and constructors are not inherited.
  • Every class that extends nothing implicitly extends java.lang.Object, the root of all classes.
  • A final class (e.g. String) cannot be extended.

The super keyword has three uses:

Mnemonic super V-M-C: Variable, Method, Constructor.
class Animal {                   // parent (super) class
    String name = "Animal";
    void eat() {
        System.out.println(name + " is eating");
    }
}

class Dog extends Animal {       // child (sub) class: Dog IS-A Animal
    Dog() {
        name = "Tommy";          // inherited field
    }
    void bark() {
        System.out.println(name + " is barking");
    }
}

public class SingleInherit {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.eat();                 // inherited method
        d.bark();                // own method
    }
}

2.9 Types of inheritance

Family trees come in shapes: a straight line, a ladder, one parent with many children, or a child with two parents. (shape dekh ke type pehchano)

Definition: Based on how classes are connected, inheritance is of five types: single, multilevel, hierarchical, multiple and hybrid. With classes Java supports only the first three; multiple and hybrid inheritance are achieved through interfaces.

In the figures below, an arrow points from child to parent. Solid arrow = extends, dashed arrow = implements.

class Vehicle {

class Car extends Vehicle {              // level 1

class ElectricCar extends Car {          // level 2
    void charge() { System.out.println("ElectricCar charges"); }
}

public class MultilevelDemo {
    public static void main(String[] args) {
        ElectricCar e = new ElectricCar();
        e.start();     // from grandparent
        e.drive();     // from parent
        e.charge();    // its own
    }
}

Why multiple inheritance with classes is not supported: the diamond problem

  • If class D extends B, C were allowed and both override show(), then new D().show() would be ambiguous. (kaunsa show chalega? confusion)
  • To keep the language simple and unambiguous, Java allows only one superclass: extends B, C is a compile error.
  • Interfaces avoid this because a class writes the method body itself; if two interfaces give the same default method, the class must override it.

2.10 Containership (composition, HAS-A)

A bike is not an engine, but a bike has an engine inside it. (IS-A nahi, HAS-A)

Definition: Containership (composition / aggregation) is a relationship in which a class contains an object of another class as its data member. It represents a HAS-A relationship and reuses code by delegating work to the contained object.
  • Implemented by declaring a reference field of another class: Engine engine;
  • The outer class delegates work: engine.start().
  • Loose coupling: the engine can be replaced without changing the class hierarchy.
  • Textbooks split it into composition (part cannot exist without whole, strong) and aggregation (part can exist separately, weak).
  • Rule of thumb: prefer HAS-A when "X is a Y" sounds wrong.
class Engine {
    int cc;
    Engine(int cc) { this.cc = cc; }
    void start() { System.out.println(cc + " cc engine started"); }
}

class Bike {
    String model;
    Engine engine;                  // Bike HAS-A Engine (containership)

    Bike(String model, int cc) {
        this.model = model;
        engine = new Engine(cc);    // contained object created inside
    }
    void ride() {
        engine.start();             // work delegated to the contained object
        System.out.println(model + " is running");
    }
}

public class BikeEngine {
    public static void main(String[] args) {
        new Bike("Pulsar", 150).ride();
    }
}

2.11 Polymorphism: overloading and overriding

One word, many forms: "pay" works differently for UPI, card and cash, but you just say pay. (ek naam, kai roop)

Definition: Polymorphism is the ability of one method name (or reference) to take many forms. In Java it is of two kinds: compile-time polymorphism, achieved by method overloading, and run-time polymorphism, achieved by method overriding with dynamic method dispatch.

(a) Compile-time polymorphism: method overloading

  • Overloading: same method name, different parameter list (number, type or order) in the same class.
  • The compiler picks the version by matching the arguments, so it is decided before the program runs.
  • Return type alone cannot overload: int f() and double f() is an error.
  • Java does not allow user-defined operator overloading (only built-in + joins strings).
class Calculator {
    int add(int a, int b) {              // 2 int parameters
        return a + b;
    }
    int add(int a, int b, int c) {       // different NUMBER of parameters
        return a + b + c;
    }
    double add(double a, double b) {     // different TYPE of parameters
        return a + b;
    }
}

public class OverloadDemo {
    public static void main(String[] args) {
        Calculator c = new Calculator();
        System.out.println(c.add(2, 3));       // compiler picks add(int,int)
        System.out.println(c.add(2, 3, 4));    // picks add(int,int,int)
        System.out.println(c.add(2.5, 1.5));   // picks add(double,double)
    }
}

(b) Run-time polymorphism: method overriding and dynamic method dispatch

  • Overriding: child class gives its own body for a method with the same signature as the parent's.
  • Dynamic method dispatch: a parent-type reference can hold a child object (Payment p = new UpiPayment();); the JVM calls the method of the actual object at run time, not of the reference type.
  • @Override annotation asks the compiler to check that a method really overrides.
class Payment {
    void pay(int amt) { System.out.println("Paying Rs." + amt); }
}

class UpiPayment extends Payment {
    @Override
    void pay(int amt) { System.out.println("Paying Rs." + amt + " by UPI"); }
}

class CardPayment extends Payment {
    @Override
    void pay(int amt) { System.out.println("Paying Rs." + amt + " by card"); }
}

public class DispatchDemo {
    public static void main(String[] args) {
        Payment p;                   // parent-type reference
        p = new UpiPayment();
        p.pay(200);                  // decided at RUN time: UpiPayment's pay
        p = new CardPayment();
        p.pay(500);                  // same call, now CardPayment's pay
        p = new Payment();
        p.pay(50);
    }
}

Paying Rs.500 by card
Paying Rs.50

Rules of method overriding

  • Same name and same parameter list as the parent method.
  • Return type same, or a subclass of it (covariant return).
  • Access cannot be more restrictive (a public method cannot become private).
  • final, static and private methods cannot be overridden (a static method with the same signature only hides the parent's).
  • Needs inheritance (IS-A); constructors cannot be overridden.

2.12 Abstract class and abstract methods

"Every shape has an area" is true, but you cannot compute the area of just "a shape"; each real shape must say how. (adhoora class, bacche poora karein)

Definition: An abstract class is a class declared with the abstract keyword that cannot be instantiated and may contain abstract methods. An abstract method is a method declared without a body (abstract double area();) that every concrete subclass must override.
  • Cannot create an object: new Figure() is a compile error, but a reference Figure f = new Rect(4, 5); is allowed.
  • Can have both abstract and concrete methods, fields and constructors. (kuch ready, kuch baaki)
  • If a class has even one abstract method, the class must be declared abstract.
  • A subclass must override all abstract methods, or itself be declared abstract.
  • Gives partial abstraction (0 to 100 percent) and a common base for run-time polymorphism.
  • abstract cannot combine with final, static or private on a method.
abstract class Figure {
    String name;
    Figure(String n) { name = n; }       // abstract class CAN have a constructor
    abstract double area();              // no body: child must override it
    void print() { System.out.println(name + " area = " + area()); }  // concrete
}
class Rect extends Figure {
    double l, b;
    Rect(double l, double b) { super("Rectangle"); this.l = l; this.b = b; }
    double area() { return l * b; }
}
class Round extends Figure {
    double r;
    Round(double r) { super("Circle"); this.r = r; }
    double area() { return 3.14 * r * r; }
}

public class AbstractDemo {
    public static void main(String[] args) {
        // Figure f = new Figure("x");   error: Figure is abstract
        Figure f1 = new Rect(4, 5);   f1.print();
        Figure f2 = new Round(2);     f2.print();
    }
}
Rectangle area = 20.0
Circle area = 12.56
Quick recall abstract class: no objects, may have abstract (bodyless) + normal methods and constructors; child must override abstract methods.

2.13 Interface and multiple inheritance

An interface is a contract, like a phone charging port standard: any company's phone that implements it must provide those pins. (interface = wada, class ko nibhana padega)

Definition: An interface is a reference type declared with the interface keyword that contains abstract methods (and constants) specifying what a class must do. A class uses implements to accept the contract and must provide bodies for all its abstract methods. A class can implement many interfaces, which is how Java achieves multiple inheritance.
  • Methods are public abstract by default; variables are public static final (constants).
  • No constructors, no object creation: new Camera() is an error.
  • Implementing methods must be declared public in the class.
  • Java 8 added default methods (with a body, e.g. volume()) and static methods in interfaces; Java 9 added private methods.
  • Multiple inheritance: class Smartphone implements Camera, MusicPlayer (Fig 2.19). A class can extend one class and implement many interfaces together: class A extends B implements X, Y.

Program: multiple inheritance through interfaces, with a default method.

interface Camera {
    void click();                        // public abstract by default
}

interface MusicPlayer {
    void play();
    default void volume() {              // Java 8 default method (has a body)
        System.out.println("Volume set to 50");
    }
}

class Smartphone implements Camera, MusicPlayer {   // multiple inheritance
    public void click() { System.out.println("Photo clicked"); }
    public void play()  { System.out.println("Song playing"); }
}

public class InterfaceDemo {
    public static void main(String[] args) {
        Smartphone s = new Smartphone();
        s.click();
        s.play();
        s.volume();
        Camera c = s;  c.click();        // interface-type reference
    }
}

Definition: A package is a named group of related classes and interfaces that provides a namespace (avoids name clashes), access protection and easy reuse. Packages are of two types: built-in (Java API) and user-defined.

Creating a user-defined package

Q1. Difference between method overloading and method overriding, with a suitable example

Method overloading: Defining two or more methods with the same name but different parameter lists (number, type or order of parameters) in the same class. The call is decided at compile time, so it is compile-time (static) polymorphism.
Method overriding: A child class redefines a method of its parent class with the same name, same parameters and same return type. The method that runs is decided at run time by the actual object, so it is run-time (dynamic) polymorphism.

Program showing both:

class Shape {
    // overloading: same name, different parameters (same class)
    int area(int side) { return side * side; }
    int area(int length, int breadth) { return length * breadth; }

    void draw() { System.out.println("Drawing a shape"); }
}

class Circle extends Shape {
    // overriding: same name AND same parameters (child class)
    @Override
    void draw() { System.out.println("Drawing a circle"); }
}

public class OverloadOverride {
    public static void main(String[] args) {
        Shape s = new Shape();
        System.out.println("Square area = " + s.area(4));      // area(int)
        System.out.println("Rectangle area = " + s.area(4, 6)); // area(int,int)

        Shape ref = new Circle();   // parent reference, child object
        ref.draw();                 // child's draw() runs at run time
    }
}
Square area = 16
Rectangle area = 24
Drawing a circle
  • s.area(4) and s.area(4, 6) call different methods because the arguments differ: overloading.
  • ref is a Shape reference, but the object is a Circle, so Circle's draw() runs: overriding (dynamic method dispatch).
Mnemonic "LOAD in one class, RIDE up to the parent": overload = same class, different parameters; override = child over parent, same parameters.

Q2. Explain abstract class and interface in Java

Abstract class: A class declared with the abstract keyword that cannot be instantiated. It can have abstract methods (no body) and concrete methods (with body), variables and constructors. A subclass must override all abstract methods or itself be abstract.
Interface: A reference type declared with the interface keyword that defines a contract: methods are public and abstract by default and variables are public static final (constants). A class uses implements to provide the bodies. One class can implement many interfaces, which is how Java achieves multiple inheritance.

Rules of an abstract class

  • Declared with abstract; an abstract method has no body and ends with ;.
  • Cannot create objects: new Account() is a compile error, but a reference Account a is allowed.
  • Can have constructors (called through super()), instance variables, static and final methods.
  • If a class has even one abstract method, the class must be abstract.
  • Gives partial abstraction (0 to 100%).

Rules of an interface

  • Methods are public abstract by default; variables are public static final.
  • No constructors, cannot be instantiated.
  • A class implements an interface and must give bodies to all its methods (declared public).
  • An interface can extend other interfaces; a class can implement many interfaces.
  • From Java 8, interfaces can also have default and static methods with bodies.

Program using both:

interface Printable {                 // interface: only a contract
    void print();                     // public abstract by default
}

abstract class Account {              // abstract class: partial blueprint
    double balance;
    Account(double balance) { this.balance = balance; }
    abstract double interest();       // no body
    void show() { System.out.println("Balance = " + balance); }
}

class Savings extends Account implements Printable {
    Savings(double balance) { super(balance); }
    double interest() { return balance * 0.04; }
    public void print() { System.out.println("Interest = " + interest()); }
}

public class AbstractInterface {
    public static void main(String[] args) {
        Savings s = new Savings(10000);
        s.show();
        s.print();
    }
}

Q3 (a). Short note: Array of objects

Definition: An array of objects is an array whose elements are references to objects of a class. The array stores references, not the objects themselves; each object must be created separately with new.

  • Step 1: creating the array only creates size references, all null.
  • Step 2: create each object: arr[0] = new ClassName(...);
  • Step 3: access members through the index: arr[i].member.
  • Diagram: see Fig 2.4 (array cells holding arrows to separate objects).
  • Use: storing records of many students, employees or products and processing them in a loop.
class Student {

2.16 Short answers (1.5 marks)

Q1. Define class and object.
A class is a user-defined blueprint containing fields and methods. An object is an instance of a class created with new, having its own state and memory on the heap.
Q2. What is an array of objects?
An array whose elements are references to objects of one class, e.g. Book[] b = new Book[3];. Each object must be created separately with new, otherwise the element is null.
Q3. How are objects passed to methods in Java?
By value of the reference: the method gets a copy of the reference. Changes to the object's fields are visible to the caller; reassigning the parameter is not.
Q4. Does Java have a scope resolution operator?
No. Java has no :: for scope; it uses this. for fields, ClassName. for static members and super. for parent members. Java 8 :: is a method reference only.
Q5. What is a static data member? What is a static block?
A static data member is declared static and has one copy shared by all objects, accessed as ClassName.var. A static block static { } runs once when the class is loaded, to initialise static data.
Q6. Define constructor. List its types.
A special member with the class's name and no return type, called automatically by new to initialise an object. Types: default, no-arg, parameterized, copy.
Q7. What is a copy constructor?
A constructor that takes an object of the same class and copies its field values into the new object, e.g. Point(Point p). Java does not supply one automatically.
Q8. Differentiate this() and super().
this() calls another constructor of the same class; super() calls the parent class constructor. Both must be the first statement, so only one can be used in a constructor.
Q9. Define inheritance. Which keyword is used?
Inheritance lets a subclass acquire the fields and methods of a superclass (IS-A relationship), giving code reuse. Keyword: extends.
Q10. Why does Java not support multiple inheritance with classes?
To avoid the diamond problem: if two parents have the same method, the child's call becomes ambiguous. Multiple inheritance is achieved through interfaces.
Q11. What is containership?
A HAS-A relationship where a class holds an object of another class as a member, e.g. Bike HAS-A Engine, and delegates work to it.
Q12. Differentiate overloading and overriding.
Overloading: same name, different parameters, same class, compile-time. Overriding: same signature in child class, needs inheritance, run-time (dynamic dispatch).
Q13. What is dynamic method dispatch?
The mechanism by which a call to an overridden method through a parent-class reference is resolved at run time according to the actual object type.
Q14. What is an abstract class?
A class declared abstract that cannot be instantiated; it can have abstract (bodyless) methods, concrete methods and constructors. Subclasses must override the abstract methods.
Q15. Define interface.
A reference type with public abstract methods and public static final constants; a class uses implements to provide the bodies and may implement several interfaces.
Q16. What is a package? Name two built-in packages.
A named group of related classes and interfaces giving a namespace and access control. Examples: java.lang, java.util.
