1.2 Java Virtual Machine (JVM) Architecture & Execution Pipeline

Bytecode is the universal language that lets Java code travel across any operating system without re-compilation. (bytecode sabhi OS ki aam bhasha hai)

Definition: The JVM (Java Virtual Machine) is a runtime engine that loads intermediate bytecode (.class file) produced by javac, verifies it, and converts it into machine code for execution.
  • Bytecode: Platform-independent intermediate code representation stored in .class files after compilation.
  • WORA (Write Once, Run Anywhere): Java code compiled on one OS can run on any OS having a compatible JVM.
  • Class Loader Subsystem: Performs three steps: Loading (loads .class file), Linking (Verification, Preparation, Resolution), and Initialization (executes static initializers).
  • Runtime Data Areas:
    • Method Area: Stores class structure, field/method data, and static variables.
    • Heap: Stores all created objects and instance variables. Managed by the garbage collector.
    • Java Stack: Stores stack frames for active methods, local variables, and partial results.
    • PC Register: Holds the address of the current JVM instruction being executed.
    • Native Method Stack: Contains state for native (C/C++) methods.
  • Execution Engine:
    • Interpreter: Reads and executes bytecode instructions one by one.
    • JIT Compiler (Just-In-Time): Compiles frequently executed bytecode chunks (hotspots) directly into native CPU code to boost performance.
    • Garbage Collector: Automatically deallocates unreferenced heap memory.

Compile-time vs run-time, in one line each:

StageWhat happens
Compile-time (javac)The .java source file is checked for syntax errors and translated into platform-independent bytecode (.class).
Run-time (java / JVM)The class loader loads the bytecode, verifies it, and the execution engine converts it into native machine instructions to run.
Common mistake: Thinking bytecode is CPU machine code. Bytecode is instructions for the JVM; the JVM translates it into CPU instructions.
Quick recall JVM architecture = Class loader subsystem + Runtime memory areas (Heap, Stack, Method area) + Execution Engine (Interpreter + JIT + GC).
