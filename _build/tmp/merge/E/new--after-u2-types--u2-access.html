2.9 Access modifiers (member access rules)

Four lock levels on a member: only me, only my colony, my family anywhere, or everyone. (kitna khula rakhna hai, modifier decide karta hai)

Definition: An access modifier fixes the accessibility (scope) of a class, field, method or constructor. Java has four: private, default (no keyword written), protected and public, from most to least restrictive.
  • private: usable only inside the same class. Used to hide data (encapsulation).
  • default (write nothing): usable anywhere in the same package, but not outside it, not even by a subclass in another package.
  • protected: usable in the same package, and in a subclass in a different package, but only through inheritance.
  • public: usable everywhere, the widest scope.
  • private and protected can be applied to a data member, method or constructor. They cannot be applied to a top-level class; a top-level class is only default or public.

Mnemonic widening scope C-P-S-E: Class only (private) → Package (default) → Subclass elsewhere too (protected) → Everyone (public).

(a) private is not accessible outside its own class, not even from code that holds an object of it:

class A {
    private int data = 40;

    private void msg() {
        System.out.println("Hello Java");
    }
}

public class Simple {
    public static void main(String[] args) {
        A obj = new A();
        System.out.println(obj.data);
        obj.msg();
    }
}

Compile error (real javac message):

Simple.java:12: error: data has private access in A
        System.out.println(obj.data);
                              ^
Simple.java:13: error: msg() has private access in A
        obj.msg();
           ^
2 errors
Common mistake: the notes write this line as System.out.println(" obj.data);; a stray quote before obj leaves the string unterminated, so javac stops at "unclosed string literal" and never even reaches the private-access lesson. Removing the extra quote (System.out.println(obj.data);, as above) gives the two real private-access errors that this example is actually meant to teach.

(b) default: two classes with no package line sit in the same (unnamed) package, so default access already works between them:

class Adef {
    void msg() {
        System.out.println("Hello");
    }
}

public class DefaultDemo {
    public static void main(String args[]) {
        Adef obj = new Adef();
        obj.msg();
    }
}
Hello

Move Adef into its own package and reach it from a different package, and default access fails even with an import:

Save Adef.java inside a folder named pack1:

package pack1;
class Adef {
    void msg() {
        System.out.println("Hello");
    }
}

Save Bdef.java inside a folder named pack2:

package pack2;
import pack1.Adef;
class Bdef {
    public static void main(String args[]) {
        Adef obj = new Adef();
        obj.msg();
    }
}

Compile error (real javac message) for javac -d . pack1\Adef.java then javac -d . pack2\Bdef.java:

pack2\Bdef.java:2: error: Adef is not public in pack1; cannot be accessed from outside package
import pack1.Adef;
            ^
pack2\Bdef.java:5: error: Adef is not public in pack1; cannot be accessed from outside package
        Adef obj = new Adef();
        ^
pack2\Bdef.java:5: error: Adef is not public in pack1; cannot be accessed from outside package
        Adef obj = new Adef();
                       ^
3 errors
Common mistake: the notes write the import as import pack.*; while the package actually declared is pack1; that typo alone gives "package pack does not exist". Fixing the package name is not enough to make it work: Adef is default-access, so it stays invisible outside pack1 no matter how it is imported. The real, intended error is the "not public in pack1" message above.

(c) protected is not usable from an unrelated class in another package, but is usable from a subclass in another package:

Save ProtectA.java inside a folder named pack:

package pack;
public class ProtectA {
    protected void msg() {
        System.out.println("Hello");
    }
}

Save ProtectB.java inside a folder named mypack:

package mypack;
import pack.*;
class ProtectB extends ProtectA {
    public static void main(String args[]) {
        ProtectB obj = new ProtectB();
        obj.msg();
    }
}
javac -d . pack\ProtectA.java
javac -d . mypack\ProtectB.java
java mypack.ProtectB

Hello

(d) public is the widest scope: usable from any package with a plain import:

Save X.java inside a folder named pack:

package pack;
public class X {
    public void msg() {
        System.out.println("Hello");
    }
}

Save Y.java inside a folder named mypack:

package mypack;
import pack.X;
class Y {
    public static void main(String args[]) {
        X obj = new X();
        obj.msg();
    }
}
javac -d . pack\X.java
javac -d . mypack\Y.java
java mypack.Y

Hello
Quick recall private < default < protected < public, in scope; only default/public may sit on a top-level class; protected reaches another package only through a subclass.
