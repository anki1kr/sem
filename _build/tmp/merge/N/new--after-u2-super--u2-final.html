2.11 The final keyword

"final" is Java's way of saying "this is locked, do not touch." (ek baar final, phir badlega nahi)

Definition: final is a non-access modifier used to restrict the user. It can be applied to a variable (its value cannot be changed once initialised), a method (it cannot be overridden by a subclass) or a class (it cannot be extended/inherited by any class).
  • final variable: usually written in UPPER_CASE by convention (it is a constant); must be given a value either at declaration or in the constructor, and never re-assigned after that.
  • final method: can still be inherited and called normally by a subclass — only overriding it is blocked.
  • final class: its methods can still be called and its objects created as usual — only being the parent of another class is blocked. String is a well-known final class.
  • A final variable that is not given a value at declaration (given one later, exactly once, e.g. in every constructor) is sometimes called a blank final variable; the notes for this unit do not go into that case.
Applied toWhat it preventsStill allowed
VariableRe-assigning the value after it is initialisedReading the value anywhere it is visible
MethodA subclass overriding it (same signature, own body)A subclass inheriting it and calling it as-is
ClassAny other class extending it (extends)Creating objects of it, calling its methods
Mnemonic final V-M-C: stops a Value from changing, a Method from being overridden, a Class from being extended.

(a) final variable — the class notes' own Bike-style example, a speed limit that must not change:

class Glamour {
    final int speedLimit = 100;   // final variable

    void run() {
        speedLimit = 400;
    }

    public static void main(String[] args) {
        Glamour obj = new Glamour();
        obj.run();
    }
}

Compile error (real javac message):

Glamour.java:5: error: cannot assign a value to final variable speedLimit
        speedLimit = 400;
        ^
1 error
Common mistake: the notes declare the field speedLimit (capital L) but the re-assignment line reads Speedlimit = 400; (capital S, lowercase l) — a different, undeclared identifier. Java is case-sensitive, so javac never even reaches the final-variable rule; it stops one step earlier with "cannot find symbol: variable Speedlimit". Using the same spelling everywhere (as above) gives the error the example is actually meant to teach: "cannot assign a value to final variable speedLimit".

A final variable is perfectly usable — only re-assignment is blocked; reading it works exactly like any other field:

class Bike3 {
    final int SPEED_LIMIT = 90;   // final variable used as a constant

    void show() {
        System.out.println("Speed limit is: " + SPEED_LIMIT);
    }
}

public class FinalConstDemo {
    public static void main(String[] args) {
        Bike3 b = new Bike3();
        b.show();                 // read is fine; only re-assignment is blocked
    }
}
Speed limit is: 90

(b) final method — the class notes' Bike/Hero example, a run() that must not be overridden:

class Bike {
    final void run() {                 // final method
        System.out.println("running");
    }
}

class Hero extends Bike {
    void run() {                       // attempting to override a final method
        System.out.println("running safely with 60mph");
    }

    public static void main(String[] args) {
        Hero obj = new Hero();
        obj.run();
    }
}

Compile error (real javac message):

Hero.java:8: error: run() in Hero cannot override run() in Bike
    void run() {
         ^
  overridden method is final
1 error

(c) final class — the class notes' Bike/Honda example, a class that must not be extended:

final class Bike {                     // final class
    void run() {
        System.out.println("running safely with 60kmph");
    }
}

class Honda extends Bike {             // attempting to inherit a final class
    public static void main(String[] args) {
        Honda obj = new Honda();
        obj.run();
    }
}

Compile error (real javac message):

Honda.java:7: error: cannot inherit from final Bike
class Honda extends Bike {
                    ^
1 error
Quick recall final on a variable = constant (no re-assign); final on a method = no overriding; final on a class = no extending; in all three cases, normal use (read / call / instantiate) still works.
