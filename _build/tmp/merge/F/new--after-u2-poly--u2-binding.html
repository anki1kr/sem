2.11 Static binding and dynamic binding

Binding is just: which body gets wired up to a method call. Decide it while reading the code (compiler), or decide it while the program is actually running (JVM)? (binding = call ko uske body se jodna)

Definition: Binding is the process of connecting a method call to its actual body (method definition). Static binding (early binding) happens at compile time and is used for overloaded methods; dynamic binding (late binding) happens at run time and is used for overridden methods.
  • Static binding is done by the compiler: when several overloaded methods share a name, the compiler looks at the arguments in the call and wires up the matching method there and then.
  • Dynamic binding is done by the JVM: when a method is overridden, the same call can reach different bodies depending on which object is actually sitting behind the reference; that object exists only at run time, so only the JVM can make this decision.
  • Static binding is also called early binding; dynamic binding is also called late binding.
  • This is the same split as compile-time vs run-time polymorphism (Fig 2.17) seen from the compiler/JVM's point of view instead of the programmer's.

1. Static binding — resolved by the compiler, for overloaded methods:

public class Animal {
    void eat() {                       // method without arguments
        System.out.println("animal is eating");
    }
    void eat(String food) {            // overloaded: method with a String argument
        System.out.println("dog is eating... " + food);
    }
    public static void main(String[] args) {
        Animal a = new Animal();
        a.eat();                        // compiler binds this to eat() at compile time
        a.eat("Biscuits");               // compiler binds this to eat(String) at compile time
    }
}
animal is eating
dog is eating... Biscuits
  • Both calls are wired up while javac reads the source: the number and type of arguments in a.eat() and a.eat("Biscuits") are enough to pick a method, with no need to know what a points to at run time.

2. Dynamic binding — resolved by the JVM, for overridden methods:

class Animal {
    void eat() {
        System.out.println("Animal is eating...");
    }
}

public class Dog extends Animal {
    void eat() {                        // same name + same parameters: overriding
        System.out.println("dog is eating...");
    }
    public static void main(String[] args) {
        Animal a = new Dog();
        a.eat();                          // reference type Animal, object type Dog: Dog's eat() runs
        Animal a1 = new Animal();
        a1.eat();                          // object type Animal: Animal's eat() runs
        Dog d = new Dog();
        d.eat();                          // object type Dog: Dog's eat() runs
    }
}
dog is eating...
Animal is eating...
dog is eating...
  • a and a1 are declared with the same type (Animal), yet a.eat() and a1.eat() print different lines — the only difference is the object each one actually refers to, which the JVM checks at run time. That is dynamic binding.

Mnemonic S-C-C vs D-R-R: Static binding = Compiler, Compile time; Dynamic binding = Run time, Real (actual) object.
Common mistake: thinking "static binding" only means "binding of static methods." A static method call IS always statically bound, but so is every overloaded call and every private/final method call — static binding is about when the decision is made (compile time), not only about the static keyword.
Quick recall Binding = connecting a call to its body. Static/early = compiler, compile time, overloading. Dynamic/late = JVM, run time, overriding — the object behind the reference decides.
