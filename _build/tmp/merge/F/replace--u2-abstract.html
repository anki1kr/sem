2.12 Abstract class and abstract methods

"Every shape has an area" is true, but you cannot compute the area of just "a shape"; each real shape must say how. (adhoora class, bacche poora karein)

Definition: An abstract class is a class declared with the abstract keyword that cannot be instantiated and may contain abstract methods. An abstract method is a method declared without a body (abstract double area();) that every concrete subclass must override.
  • Abstraction (the general idea) means hiding implementation detail and showing only functionality — sending an SMS or paying by UPI, you just type and send; the delivery mechanics stay hidden. (andar kya ho raha hai, dekhne ki zarurat nahi) An abstract class is one of Java's two tools for achieving it (the other is the interface, next topic).
  • Cannot create an object: new Figure() is a compile error, but a reference Figure f = new Rect(4, 5); is allowed.
  • Can have both abstract and concrete methods, fields, a constructor, and even a main() method. (kuch ready, kuch baaki)
  • If a class has even one abstract method, the class must be declared abstract.
  • A subclass must override all abstract methods, or itself be declared abstract.
  • An abstract class with zero abstract methods is legal too (unusual, but the compiler does not complain) — though the whole point of declaring one is usually to hold at least one abstract method.
  • Gives partial abstraction (0 to 100 percent) and a common base for run-time polymorphism.
  • abstract cannot combine with final, static or private on a method.
abstract class Figure {
    String name;
    Figure(String n) { name = n; }       // abstract class CAN have a constructor
    abstract double area();              // no body: child must override it
    void print() { System.out.println(name + " area = " + area()); }  // concrete
}
class Rect extends Figure {
    double l, b;
    Rect(double l, double b) { super("Rectangle"); this.l = l; this.b = b; }
    double area() { return l * b; }
}
class Round extends Figure {
    double r;
    Round(double r) { super("Circle"); this.r = r; }
    double area() { return 3.14 * r * r; }
}

public class AbstractDemo {
    public static void main(String[] args) {
        // Figure f = new Figure("x");   error: Figure is abstract
        Figure f1 = new Rect(4, 5);   f1.print();
        Figure f2 = new Round(2);     f2.print();
    }
}
Rectangle area = 20.0
Circle area = 12.56

A second example from the notes — an abstract class mixing one abstract method with an ordinary (parameterised) method:

abstract class Animal {
    abstract void sound();                 // abstract method: no body
    void eat(String food) {                // concrete (normal) method, takes a parameter
        System.out.println("this animal likes " + food);
    }
}

public class Lion extends Animal {
    void sound() {
        System.out.println("Lions Roar! Roar!");
    }
    public static void main(String[] args) {
        Lion l = new Lion();
        l.sound();               // Lion's own body
        l.eat("flesh");           // inherited concrete method
    }
}
Lions Roar! Roar!
this animal likes flesh
  • Animal is abstract only because of sound(); eat(String food) already has a full body and is inherited by Lion unchanged, exactly like a normal parent-child method.
  • Lion becomes a normal, instantiable class the moment it supplies a body for the one abstract method it inherited.
Quick recall abstract class: no objects, may mix abstract (bodyless) + normal methods, fields, constructors, even main(); child must override every abstract method to become instantiable; abstraction is the general idea, abstract class is one Java tool for it.
