2.1 Classes and objects

A class is the plan of a house; an object is the actual house built from that plan. (class = naksha, object = asli ghar)

Definition: A class is a user-defined blueprint that groups data (fields) and behaviour (methods) under one name. An object is an instance of a class: a real entity created in memory with the new keyword, having its own state (field values) and sharing the class's behaviour.
  • Members of a class: fields (variables that store state) and methods (functions that act on the state). Constructors and blocks also live inside a class.
  • State + behaviour + identity: every object has field values (state), methods (behaviour) and its own memory location (identity).
  • A class takes no memory for fields until an object is created; each object gets its own copy of instance variables.
  • new does three things: allocates memory on the heap, runs the constructor, returns the reference. (new = memory + constructor + address)
  • The dot operator (s1.name, s1.show()) reaches a member through a reference.
  • A class body can hold six kinds of members: data members, methods, constructors, blocks, nested classes and interfaces. General shape: class ClassName { // fields // methods }; an object is then declared as ClassName obj = new ClassName();.
  • Student s1; only makes a reference (value null). s1 = new Student(); makes the object.
  • Student s3 = s1; copies the reference, not the object: both names now point to one object (see output line 3 below).
  • Unreferenced objects are later removed by the garbage collector; Java has no delete.

Program: class, objects and a shared reference.

class Student {
    int roll;          // instance variable
    String name;

    void show() {      // method
        System.out.println(roll + " : " + name);
    }
}

public class StudentDemo {
    public static void main(String[] args) {
        Student s1 = new Student();   // object created on heap
        s1.roll = 1;
        s1.name = "Aman";
        Student s2 = new Student();
        s2.roll = 2;
        s2.name = "Riya";
        s1.show();
        s2.show();
        Student s3 = s1;              // s3 refers to the SAME object
        s3.name = "Aman Kumar";
        s1.show();
    }
}
1 : Aman
2 : Riya
1 : Aman Kumar
Common mistake: Student s3 = s1; does NOT make a copy. Changing s3.name also changes what s1 shows, because there is only one object.

Instance variables vs local variables: a field declared inside the class body (outside every method) is an instance variable — it gets memory only when an object is created with new, and every object carries its own copy. A variable declared inside a method is a local variable — it gets memory only while that method is running and disappears when the method returns; unlike an instance variable it has no default value, so it must be assigned before it is read.

class StudentRecord {
    int id = 521;              // instance variable: memory made when new runs
    String name = "Madhu";       // instance variable
}

public class StudentInstanceDemo {
    public static void main(String[] args) {
        StudentRecord s1 = new StudentRecord();
        System.out.println("Your R.No is: " + s1.id);
        System.out.println("Your name is: " + s1.name);
        int age = 30;              // local variable: exists only inside main
        String branch = "CSE";        // local variable
        System.out.println("Your age is: " + age);
        System.out.println("Your branch is: " + branch);
    }
}

Your name is: Madhu
Your age is: 30
Your branch is: CSE
Quick recall Class = blueprint, object = instance made by new; reference on stack, object on heap. Instance variable = field, memory at object creation; local variable = inside a method, memory at call, no default value.
