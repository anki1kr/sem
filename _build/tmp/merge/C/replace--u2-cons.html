2.6 Constructors and their types

A constructor is the setup step that runs automatically the moment an object is born, like filling a form while opening a bank account. (object bante hi apne aap chalta hai)

Definition: A constructor is a special member of a class that has the same name as the class, has no return type (not even void), and is called automatically by new to initialise a newly created object.
  • Default constructor: if a class has no constructor, the compiler adds one with no parameters; fields get default values (0, null, false). It disappears as soon as you write any constructor.
  • No-arg constructor: written by the programmer with no parameters, to set fixed starting values.
  • Parameterized constructor: takes arguments, so each object can start with different values: new Point(3, 4).
  • Copy constructor: takes an object of the same class and copies its fields: Point(Point p). Java does not provide it automatically (unlike C++); we write it ourselves.
  • Constructor overloading: several constructors in one class that differ in parameter list; new picks the matching one.
Textbook variation: some books call the programmer-written no-arg constructor the "default constructor" too. Strictly, the default constructor is the one the compiler supplies.
class Point {
    int x, y;
    Point() { x = 0; y = 0; }    // no-arg constructor
    Point(int a, int b) {        // parameterized constructor (overloaded)
        x = a; y = b;
    }
    Point(Point p) {             // copy constructor (we write it ourselves)
        x = p.x; y = p.y;
    }
    void show(String label) {
        System.out.println(label + " = (" + x + ", " + y + ")");
    }
}

class Empty { int n; }           // no constructor: compiler adds default one

public class ConstructorTypes {
    public static void main(String[] args) {
        Point p1 = new Point();         p1.show("p1");
        Point p2 = new Point(3, 4);     p2.show("p2");
        Point p3 = new Point(p2);       p3.show("p3 (copy of p2)");
        System.out.println("Empty n = " + new Empty().n);
    }
}
p1 = (0, 0)
p2 = (3, 4)
p3 (copy of p2) = (3, 4)
Empty n = 0

Class-notes example — default constructor: a constructor with no parameters supplies default values and announces itself when the object is built.

public class DefaultConstr {
    DefaultConstr() {                // constructor method: same name as class
        System.out.println("Default Constructor method called.");
    }
    public static void main(String[] args) {
        DefaultConstr dc = new DefaultConstr();    // constructor runs automatically here
    }
}
Default Constructor method called.

Class-notes example — parameterized constructor: different values passed in at new time give each object its own data.

public class Students {
    int id;
    String name;

    Students(int i, String n) {      // parameterized constructor
        id = i;
        name = n;
    }
    void display() {
        System.out.println(id + " " + name);
    }
    public static void main(String[] args) {
        Students s1 = new Students(521, "Madhu");
        Students s2 = new Students(512, "Hari");
        s1.display();
        s2.display();
    }
}
521 Madhu
512 Hari

Constructor chaining: one constructor calling another. this(...) calls another constructor of the same class; super(...) calls the parent constructor. Either must be the first statement, so a constructor can use only one of them. If neither is written, the compiler inserts super(), so the parent part is always built first.

class Person {
    Person() {
        System.out.println("1. Person() runs first");
    }
}

class Employee extends Person {
    int salary;

    Employee() {
        this(25000);             // this(): calls another constructor of SAME class
        System.out.println("3. Employee() finishes last");
    }
    Employee(int s) {
        super();                 // super(): calls parent constructor, must be 1st line
        salary = s;
        System.out.println("2. Employee(int) salary = " + salary);
    }
}

public class ChainDemo {
    public static void main(String[] args) {
        new Employee();
    }
}
1. Person() runs first
2. Employee(int) salary = 25000
3. Employee() finishes last

Class-notes example — constructor overloading: two constructors with a different number of parameters; new matches by the argument list, exactly like method overloading.

public class Sum {
    int a, b, c;

    Sum(int x, int y) {                // constructor with 2 parameters
        a = x;
        b = y;
    }
    Sum(int x, int y, int z) {         // constructor with 3 parameters (overloaded)
        a = x;
        b = y;
        c = z;
    }
    void display() {
        System.out.println("Sum is " + (a + b + c));
    }
    public static void main(String[] args) {
        Sum s1 = new Sum(10, 11);          // matches the 2-parameter constructor
        Sum s2 = new Sum(10, 20, 30);      // matches the 3-parameter constructor
        s1.display();
        s2.display();
    }
}
Sum is 21
Sum is 60
Common mistake: forgetting that an unset field still compiles. In Sum s1 = new Sum(10, 11), field c is never assigned by the 2-parameter constructor, so it keeps its default value 0 — that is why 10 + 11 + 0 = 21, not an error.

Rules of constructors

  • Name must be exactly the class name; no return type.
  • Cannot be static, final or abstract; access modifiers are allowed (a private constructor blocks outside object creation).
  • this() or super() must be the first statement; not both.
  • Constructors are not inherited, so they cannot be overridden, but they can be overloaded.

Mnemonic S-N-A rules: Same name as class, No return type, Automatically called by new.
Quick recall 4 types: default, no-arg, parameterized, copy; overload by parameters; chain with this() / super() as first line. An unassigned field in an overloaded constructor silently keeps its default value.
