2.56 Methods and method overloading

A method is a labelled job a class knows how to do; call it by name and it does that job, as many times as you like. (kaam ka naam do, jab chaho bulao)

Definition: A method is a named block of statements, grouped together to perform one task, declared inside a class. Method overloading is having two or more methods in the same class with the same name but a different parameter list (number, type or order of parameters).
  • modifiers (optional): access level (public, private, ...) plus keywords like static.
  • return type: void if the method returns nothing, otherwise the type of value it sends back with return.
  • method name: a valid identifier, by convention starting with a lower-case letter.
  • parameter list: the values the caller passes in, listed in parentheses after the name; can be empty.
  • method body: the statements between { } that do the work.
  • Java has no free-standing functions: every method is declared inside some class.
  • Two kinds by how they are called: an instance method needs an object (obj.method()) and may use instance variables; a class (static) method is called on the class itself (ClassName.method()) and cannot use instance variables unless it creates an object first.

Class-notes example — a method that returns a value, called without an object because it is static:

public class MaxNumber {
    public static void main(String[] args) {
        int a = 56, b = 51;                    // hard-coded (notes read these from the keyboard)
        int maxc = maxFunction(a, b);         // static method called directly: no object needed
        System.out.println("Maximum Number is = " + maxc);
    }
    public static int maxFunction(int n1, int n2) {
        int max;
        if (n1 > n2)
            max = n1;
        else
            max = n2;
        return max;
    }
}
Maximum Number is = 56
Common mistake: the notebook calls MaxFunction(a, b) but defines maxFunction — Java is case-sensitive, so the two names are different methods and javac reports "cannot find symbol: method MaxFunction(int,int)". The notebook's method body also mixes two different variable names, man and max, assigning one and returning the other, which separately fails as "cannot find symbol: variable max". Fixed above: the call matches maxFunction exactly, and only max is used throughout.

Class-notes example — a void method, also called without an object:

public class Grade {
    public static void main(String[] args) {
        int marks = 92;              // hard-coded (notes read this from the keyboard)
        grade(marks);
    }
    public static void grade(int m) {   // void: nothing is returned
        if (m >= 90)
            System.out.println("Grade A");
        else if (m >= 70)
            System.out.println("Grade B");
        else if (m >= 50)
            System.out.println("Grade C");
        else
            System.out.println("Grade D");
    }
}

Class-notes example — calling an instance method, which needs an object:

public class Calc {
    public static void main(String[] args) {
        Calc obj = new Calc();          // object creation for class Calc
        int x = 20, y = 5;             // hard-coded (notes read these from the keyboard)
        obj.sum(x, y);                  // instance method: needs the object "obj"
        obj.sub(x, y);
    }
    void sum(int a, int b) {
        System.out.println("Sum is : " + (a + b));
    }
    void sub(int a, int b) {
        System.out.println("Sub is : " + (a - b));
    }
}

(b) Method overloading: a class can have several methods with the same name, as long as their parameter lists differ. The compiler matches each call to the correct one by counting and typing the arguments, before the program ever runs. This is different from method overriding (same name, same parameter list, in a parent/child pair, resolved while the program runs) — see 2.10 Polymorphism.

  • Overloading by changing the data type of the arguments: sum(int, int) and sum(float, float).
  • Overloading by changing the number of arguments: sum(int, int) and sum(int, int, int).
  • Java matches the name first, then the number and type of arguments, to pick the right overload.
  • Return type alone cannot overload a method: int f() and double f() together are a compile error.
public class Calculate {
    void sum(int a, int b) {              // version 1: two ints
        System.out.println("sum is : " + (a + b));
    }
    void sum(float a, float b) {          // version 2: two floats (overloaded by TYPE)
        System.out.println("sum is : " + (a + b));
    }
    public static void main(String[] args) {
        Calculate cal = new Calculate();
        cal.sum(8, 5);           // sum(int, int) is called
        cal.sum(4.6f, 3.8f);     // sum(float, float) is called
    }
}
sum is : 13
sum is : 8.4
public class Calsum {
    void sum(int a, int b) {                // version 1: 2 parameters
        System.out.println(a + b);
    }
    void sum(int a, int b, int c) {         // version 2: 3 parameters (overloaded by COUNT)
        System.out.println(a + b + c);
    }
    public static void main(String[] args) {
        Calsum obj = new Calsum();
        obj.sum(10, 10, 10);     // sum() with 3 parameters
        obj.sum(20, 20);         // sum() with 2 parameters
    }
}

Mnemonic overload by T-C: Type of arguments, Count of arguments (name and return type never decide it).
Quick recall Method = modifiers + return type + name(parameters) + body; instance method needs an object, static method does not. Overloading = same name, different parameter list, matched by the compiler; different from overriding (2.10).
