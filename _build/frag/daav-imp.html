Q1. What is Big Data? Discuss in detail.

Unit I · 8 marks · Exam focus: Definition, why an ordinary RDBMS fails at scale, the historical evolution, and a clear breakdown of advantages and disadvantages.

Definition: Big Data refers to datasets whose volume, velocity, and variety are so massive and complex that traditional relational database management systems (RDBMS) cannot capture, store, manage, or analyze them within an acceptable timeframe. Handling Big Data requires distributed computing architectures running across clusters of standard commodity hardware.
  • Historical Evolution (Fig 1.1):
    • Flat files (1960s): Data was saved in basic text files on magnetic tapes without any standardized query language. Finding a record required scanning the entire file sequentially.
    • RDBMS (1970s onward): Edgar Codd introduced the relational model using structured tables, rows, columns, and SQL. This was great for structured accounting and business ledgers, but required rigid, unchanging table schemas.
    • Data Warehouses (1990s): Companies needed historical data to run business reports without slowing down live transactional databases, giving birth to centralized enterprise data warehouses.
    • Web-Scale Boom (2000s): With the explosion of Google, Yahoo, Facebook, and YouTube, user-generated clicks, searches, and photos exploded beyond what a single massive server could physically store or process.
    • Hadoop & NoSQL (2006 onward): Inspired by Google's internal GFS and MapReduce whitepapers, Apache Hadoop democratized open-source distributed storage (HDFS) and parallel computing across cheap commodity machines, evolving into today's cloud-native data lakes and Apache Spark pipelines.
  • Why Traditional RDBMS Breaks Down at Big Data Scale:
    • Vertical Scaling Limits (Scale-up Ceiling): An RDBMS runs on a single central server. When data increases 100-fold, you have to buy an exorbitantly expensive super-server with more CPUs and RAM. Eventually, you hit physical hardware limits of the motherboard and bus speeds.
    • Rigid Schema Lock-in: Relational tables require a fixed schema defined before writing data (schema-on-write). When incoming data contains an unpredictable mix of JSON payloads, video files, sensor telemetry, and unstructured text, an RDBMS cannot adapt without costly and slow table redesigns.
    • Speed & Concurrency Bottlenecks: RDBMS row-level locking and strict transactional integrity (ACID) create severe bottlenecks when millions of continuous events stream in per second.
    • High Cost of Enterprise Hardware: Proprietary database licenses combined with high-end enterprise storage area networks (SAN) cost millions, whereas Big Data platforms run on regular, inexpensive commodity disks.
    • Single Point of Failure: Relying on one centralized database server means if that machine crashes or loses power, your entire organization's data goes dark.
  • The Big Data Approach: Instead of buying one giant server, Big Data uses horizontal scaling (scale-out) across hundreds of inexpensive computers. It moves the program code to where the data is already stored (data locality) to avoid network congestion, and applies schema-on-read—storing raw data immediately and only structuring it when analyzing.
  • Key Advantages (Mnemonic: D-C-F-P-S-A):
    • Decisions: High-velocity analytics give managers real-time facts instead of gut feelings.
    • Cost reduction: Open-source tools and commodity machines slash infrastructure costs.
    • Fraud detection: Banking systems analyze transaction patterns in milliseconds to block suspicious credit card charges instantly.
    • Productivity: Automated data pipelines eliminate manual reporting delays.
    • Service: Recommender engines deliver personalized recommendations (e.g. Netflix, Amazon) that delight customers.
    • Agility: Rapidly adapt to new market trends by ingesting new data formats on the fly.
  • Major Disadvantages (Mnemonic: T-S-C):
    • Talent shortage: High demand and scarcity of skilled data engineers and distributed systems architects.
    • Security risks: Managing sensitive personal information across hundreds of distributed nodes increases the attack surface.
    • Compliance burden: Meeting strict privacy laws (like India's DPDP Act and Europe's GDPR) across massive distributed clusters is complex and costly.

Q2. Discuss the sources of Big Data.

Unit I · 8 marks · Exam focus: The three primary families (Human-generated, Machine-generated, and Organisational data) with realistic, everyday examples for each.

Definition: Sources of Big Data are the origins and channels that produce massive streams of data. In modern computing, these sources are broadly classified into three major families: Human-generated, Machine-generated, and Organisational (Transactional) data.
  • 1. Human-Generated Data: Data intentionally created by humans through everyday digital interaction. This includes social media posts on Instagram and X (Twitter), YouTube videos, WhatsApp chats, personal emails, blog articles, product reviews on Amazon, and search engine queries.
    Nature: Mostly unstructured text, images, and audio. It has massive volume and variety, but requires Natural Language Processing (NLP) and computer vision to extract useful meaning.
  • 2. Machine-Generated Data: Data generated automatically by hardware sensors, industrial machines, and computer software without direct human intervention. Examples include:
    • IoT & Smart Sensors: Industrial temperature gauges, smart electricity meters recording readings every second, and smart home appliances.
    • Web Server Logs & Clickstreams: Every web page visit, link click, mouse hover, and IP session logged automatically by web servers.
    • Telematics & Satellites: GPS coordinates beamed by Uber/Ola cabs every 5 seconds, weather satellite imagery, and RFID tracking tags in warehouses.
    Nature: Characterized by extremely high velocity and continuous, real-time streaming.
  • 3. Organisational / Transactional Data: Highly structured records generated during the core daily operations of businesses and institutions. Examples include:
    • Financial & Payment Systems: UPI transactions, banking deposits, credit card swipes, and stock market trades.
    • Enterprise Software: Inventory tracking and employee payroll inside ERP systems (like SAP), along with sales pipelines and customer complaints in CRM systems (like Salesforce).
    Nature: Highly structured, accurate, and organized into rows and columns with strict consistency requirements.
  • Additional Dimensions:
    • Open / Public Data: Government census portals, open weather data, and public transport feeds that are freely accessible for research.
    • Internal vs. External Data: Internal data lives behind company firewalls (ERP, employee logs), while external data is gathered from outside partners, social media sentiment, and third-party APIs.

Q3. Explain the types of Big Data with real-world examples.

Unit I · 8 marks · Exam focus: Structured, Semi-structured, and Unstructured categories, a clear comparison table, and one end-to-end example spanning all three.

Definition: Based on its underlying organization and formatting, Big Data is classified into three distinct types: Structured (organized in fixed rows and columns), Semi-structured (not in rigid tables, but self-described by tags or keys), and Unstructured (raw data with no predefined data model).
  • 1. Structured Data: Data that strictly conforms to a predefined schema with fixed data types, neatly arranged in rows and columns.
    Characteristics: Easily stored in traditional relational tables and queried using standard SQL.
    Examples: An IRCTC train ticket reservation table, a student university database (`roll_no`, `name`, `cgpa`), or a bank account balance table.
  • 2. Semi-Structured Data: Data that does not fit into a rigid relational table, but still contains internal structural markers, tags, or key-value pairs that clearly describe each element.
    Characteristics: Flexible and schema-less; fields can be added dynamically without rebuilding the entire database.
    Examples: JSON payloads returned by mobile APIs, XML documents, NoSQL document databases (like MongoDB), and web server log files where each entry has timestamps and IP tags.
  • 3. Unstructured Data: Data that possesses absolutely no predefined conceptual structure or tabular data model.
    Characteristics: It represents over 80% of all data generated worldwide. It cannot be queried with SQL and requires machine learning, natural language processing, or audio/video signal processing to extract actionable insights.
    Examples: WhatsApp voice recordings, YouTube videos, Instagram photos, scanned PDF invoices, customer support call transcripts, and medical MRI scans.

Q4. Explain the technologies used in Big Data.

Unit I · 8 marks · Exam focus: The layered technological stack (Ingestion → Storage → Processing → Analytics → Visualisation) with specific tools named at each tier.

Definition: Big Data technologies are the specialized software tools, frameworks, and distributed platforms engineered to ingest, store, process, analyze, and visualize petabyte-scale datasets across networked clusters of computers.
  • 1. Ingestion Layer: Acts as the front door that collects data from diverse outside systems and pulls it into the cluster.
    • Apache Sqoop: Specializes in bulk data transfer between relational databases (MySQL, Oracle) and Hadoop.
    • Apache Flume: Distributed service for aggregating and collecting massive streams of web server log data.
    • Apache Kafka: High-throughput distributed publish-subscribe messaging queue that ingests millions of real-time event streams per second.
  • 2. Storage Layer: Provides durable, fault-tolerant, scalable storage across hundreds of hard drives.
    • HDFS (Hadoop Distributed File System): Breaks giant files into large blocks (128 MB) and replicates them 3× across worker nodes.
    • Cloud Object Storage: Low-cost, virtually limitless storage such as Amazon S3, Google Cloud Storage, and Azure Blob Storage.
    • NoSQL Databases: High-performance non-relational stores like HBase, Apache Cassandra (columnar), MongoDB (document), and Redis (in-memory key-value).
  • 3. Processing Layer: The computational muscle that executes parallel algorithms on the stored data.
    • Batch Processing (MapReduce & Apache Spark): Computes massive historical datasets overnight. MapReduce writes intermediate data to disk; Apache Spark runs up to 100× faster by caching intermediate computations in RAM.
    • Stream Processing (Spark Streaming, Apache Flink, Storm): Analyzes events on the fly in real-time with millisecond latency (e.g. live sensor alerts or fraud detection).
  • 4. Analytics & Query Layer: Allows data analysts to run queries without writing complex low-level code.
    • Apache Hive: Provides an SQL-like interface (HiveQL) that automatically translates SQL queries into distributed MapReduce/Tez jobs.
    • Apache Pig: High-level dataflow scripting language (Pig Latin) for ETL pipeline design.
    • Machine Learning: Spark MLlib, TensorFlow, and Python/R scientific libraries for building predictive models.
  • 5. Visualisation Layer: Business intelligence tools like Tableau, Power BI, and Grafana that convert raw data into intuitive charts, graphs, and executive dashboards.
  • Programming Languages: Hadoop's core is written in Java; Python is the industry favorite for data manipulation and machine learning (PySpark); and Scala is the native language of Apache Spark.

Q5. Explain Hadoop architecture (HDFS, MapReduce and YARN) with a diagram.

Unit I · 8 marks · Exam focus: The four core modules, master-slave architecture, HDFS storage mechanics, MapReduce phases, and YARN resource management.

Definition: Apache Hadoop is an open-source Java-based framework designed for distributed storage and parallel processing of massive datasets across clusters of commodity hardware. It consists of four core modules: Hadoop Common, HDFS (Storage), YARN (Resource Management), and MapReduce (Processing).
  • 1. HDFS (Hadoop Distributed File System — Storage): Built on a master-slave design:
    • NameNode (Master): The "brain" of the filesystem. It maintains the directory tree, file permissions, and the exact mapping of data blocks to DataNodes. It stores all metadata entirely in RAM for fast lookups (it does not store actual file contents).
    • DataNodes (Slaves/Workers): The "muscle". They store the actual data blocks on local physical hard drives and periodically send health "heartbeat" signals and block reports to the NameNode.
    • Block Size & Replication: Files are automatically split into large blocks (default 128 MB in Hadoop 2.x/3.x). Each block is replicated 3 times across different physical server racks (rack awareness) so that if a drive or whole rack fails, zero data is lost.
  • 2. MapReduce (Distributed Compute Engine): Processes big data in parallel across nodes in three sequential phases:
    • Map Phase: Master node passes small data chunks to worker nodes. The mapper processes records in parallel and outputs intermediate (key, value) pairs.
    • Shuffle & Sort Phase: Hadoop automatically sorts and groups all intermediate pairs sharing the exact same key onto the same reducer node.
    • Reduce Phase: The reducer receives all grouped values for each key, aggregates them (e.g. sums them up), and writes final results directly back to HDFS.
    • Classic Example: Word Count — mappers output (word, 1); reducers sum all counts for each unique word.
  • 3. YARN (Yet Another Resource Negotiator — Scheduling): Introduced in Hadoop 2.x to separate cluster resource management from data processing:
    • ResourceManager (Cluster Master): The ultimate authority that allocates CPU cores and RAM across the entire cluster. It consists of a Scheduler and an ApplicationsManager.
    • NodeManager (Node Agent): Runs on every worker node, monitoring resource usage and launching task containers.
    • ApplicationMaster: One instance created per job. It negotiates required resource containers with the ResourceManager and tracks task execution.
    • Containers: An isolated physical bundle of CPU and memory on a worker node where tasks actually execute.
  • The Magic of Data Locality: Moving petabytes of data over network wires would clog the cluster switches. Hadoop places worker tasks directly on the exact physical node where the required HDFS data block already sits. Moving 50 KB of code to data is 1,000× faster than moving gigabytes of data to code!

Q6. Explain the 5 V's of Big Data.

Unit I · 8 marks · Exam focus: Define and explain each of the 5 Vs with intuitive, real-world examples, plus the two modern extensions (Variability & Visualization).

Definition: The defining characteristics of Big Data are widely summarized as the 5 V's: Volume, Velocity, Variety, Veracity, and Value. Together, they explain why traditional database systems fail and why distributed architectures are essential.
  • 1. Volume (Scale & Size): Refers to the sheer physical quantity of data being produced and stored, measured in Terabytes (TB), Petabytes (PB), and Exabytes (EB).
    Intuition: A single jumbo jet engine generates 20 Terabytes of operational telemetry per hour. Over millions of flights worldwide, this accumulates into astronomical volume that single hard drives cannot handle.
  • 2. Velocity (Speed of Arrival & Processing): The rapid rate at which new data flows into systems and how quickly it must be analyzed.
    Intuition: In online financial payments (like UPI or credit cards), transactions hit the servers at thousands of requests per second. The fraud detection system cannot wait hours; it must approve or block the transaction in under 100 milliseconds.
  • 3. Variety (Diversity of Formats): The wide assortment of data structures arriving at the same time.
    Intuition: Data is no longer just neat rows in an Excel spreadsheet. An enterprise today handles structured relational tables, semi-structured JSON and XML files, along with totally unstructured CCTV video footage, audio voice notes, and customer tweets.
  • 4. Veracity (Trustworthiness & Quality): Refers to the messiness, noise, inconsistencies, and trustworthiness of incoming data.
    Intuition: Real-world data is dirty. GPS coordinates jump when a cab enters a tunnel, weather sensors report bogus negative values when batteries die, and users submit typo-riddled addresses. Data systems must filter and sanitize this noise before feeding models.
  • 5. Value (Business Impact & ROI): The ultimate goal of storing all this data: extracting actionable insights that improve business decisions, cut operational costs, or save lives. Storing petabytes of data is useless unless it generates a clear positive Return on Investment (ROI).
  • Modern Extensions (The Extra V's):
    • Variability: Unpredictable changes in data flow rate or meaning (e.g. massive sudden traffic spikes on Amazon during Diwali flash sales).
    • Visualization: The art of turning billions of raw data points into clear, understandable visual charts so human managers can understand the story behind the numbers.

Q7. What is NoSQL? Discuss its advantages and disadvantages.

Unit I · 8 marks · Exam focus: Definition, why NoSQL emerged (horizontal scale-out vs vertical scale-up), and a clear, balanced comparison of its advantages and disadvantages.

Definition: NoSQL (originally "Non-SQL", now commonly interpreted as "Not Only SQL") refers to non-relational, highly distributed databases designed without rigid table schemas. They excel at horizontal scaling across commodity servers, handling massive volumes of structured, semi-structured, and unstructured data with high availability.
  • Why NoSQL Emerged (Fig 1.24): Traditional relational databases (RDBMS) rely on vertical scaling (scale-up)—buying an increasingly expensive server with more CPU and RAM. When millions of internet users access an app simultaneously, single servers hit a hard physical ceiling and sharding across multiple RDBMS nodes is notoriously painful. NoSQL was engineered from the ground up for horizontal scaling (scale-out)—adding dozens of cheap, standard machines to a cluster.
  • Four Main Types of NoSQL Databases:
    1. Key-Value Stores (e.g. Redis, DynamoDB): Simplest model; stores data as keys pointing to values. Lightning-fast for session caches and user shopping carts.
    2. Document Stores (e.g. MongoDB, CouchDB): Stores data in rich JSON or BSON documents. Highly flexible for content management and catalogs.
    3. Column-Family Stores (e.g. Cassandra, HBase): Stores data in sparse, wide columns instead of rows. Excels at high-write logging and historical analytics.
    4. Graph Databases (e.g. Neo4j): Stores entities as nodes and relationships as edges. Perfect for social networks, fraud rings, and recommendation maps.
  • Consistency Model: BASE vs. ACID: RDBMS enforces strict ACID (Atomicity, Consistency, Isolation, Durability) which slows down distributed networks. NoSQL adopts BASE (Basically Available, Soft state, Eventual consistency), guaranteeing that the system remains online and all nodes will eventually sync up.
Key Advantages of NoSQLMajor Disadvantages & Limitations
Horizontal Scalability: Seamlessly expands storage and throughput by adding cheap commodity servers.Eventual Consistency: Data written to one node may take a few seconds to reflect on others; unsuitable for strict banking ledgers.
Dynamic, Schema-less Design: Add new fields or nested arrays instantly without running slow ALTER TABLE commands.No Unified Standard: Unlike SQL, each NoSQL product has its own custom query language and proprietary API.
High Performance: Optimized for simple, super-fast key lookups and single-document writes without locking tables.Poor Join Capabilities: Multi-table joins are either unsupported or must be coded manually in application logic.
Fault Tolerance: Automatically replicates data across nodes; if one machine dies, the database continues serving users.Data Duplication: Denormalizing data into documents leads to duplicated records that require manual application-level synchronization.
When to choose which: Use NoSQL for massive, rapidly growing datasets with varied structures and simple access patterns (social media feeds, user sessions, IoT sensor storage). Stick with RDBMS when you need strict transactional integrity, zero data loss, and complex multi-table joins (core banking ledgers, accounting, flight seat bookings).
If it comes as a 4-mark question: Write the definition, draw Fig 1.24, and explain 2 advantages and 2 disadvantages from the table.
Quick recall NoSQL = non-relational, schema-less, horizontal scale-out (commodity clusters), BASE (eventual consistency). 4 types: Key-Value, Document, Column-Family, Graph. Pros: scale/speed; Cons: weak joins/eventual consistency.

Q8. Explain integrating diverse data and the aggregate data model.

Unit I · 8 marks · Exam focus: Two-part answer: Part A covers data integration challenges and ETL vs ELT pipelines; Part B explains Martin Fowler's Aggregate Data Model in NoSQL.

Part A · Integrating Diverse Data

Definition: Data Integration is the process of combining heterogeneous data from completely different sources (databases, APIs, streaming logs, files) into a unified, consistent, and centralized view for enterprise reporting and analytical decision-making.
  • Core Challenges in Data Integration:
    • Format Heterogeneity: Merging relational tables, JSON payloads, CSV exports, and raw text files.
    • Schema & Naming Mismatches: One database calls customer ID cust_id, while another calls it CustomerNumber.
    • Entity Resolution: Determining whether "A. Kumar, Delhi" in System A is the exact same individual as "Ankit Kumar, New Delhi" in System B.
    • Data Quality & Veracity: Stripping duplicates, handling missing phone numbers, and standardizing date formats.
  • ETL vs. ELT Architecture:
    • ETL (Extract → Transform → Load): Traditional approach (Fig 1.9). Data is extracted from sources, cleaned and transformed on a separate staging server, and finally loaded into a structured Data Warehouse (schema-on-write). Best for curated corporate reporting.
    • ELT (Extract → Load → Transform): Modern Big Data approach. Raw data is extracted and dumped directly into a scalable Data Lake (e.g. HDFS or Amazon S3) first. Transformation happens later on-demand inside the lake using powerful distributed engines like Spark (schema-on-read).

Part B · The Aggregate Data Model

Definition: An Aggregate is a collection of closely related data entities that are treated as a single, cohesive unit for data storage, reading, updating, and distributed replication across a cluster (formalized by Martin Fowler in NoSQL Distilled).
  • Why Aggregates Solve Distributed Scale: In an RDBMS, retrieving a customer's order requires executing joins across 5 normalized tables (Orders, OrderItems, Products, Customers, Payments). On a distributed cluster where those 5 tables live on 5 different servers, a join requires expensive network chatter that grinds the database to a halt.
    The Aggregate model bundles the entire order—line items, shipping address, and payment details—into one single document (Fig 1.29).
  • Aggregate-Oriented vs. Aggregate-Ignorant:
    • Aggregate-Oriented NoSQL: Key-Value, Document, and Column-Family databases. The entire aggregate lives on one server node, allowing single-disk, atomic read/writes without network joins.
    • Aggregate-Ignorant Databases: Relational and Graph databases. They break data down into fine-grained tables and reconstruct relationships dynamically using joins.
  • Relationship Between Aggregates: Aggregates reference each other using simple foreign keys or ID pointers (e.g. the Order aggregate stores only the customerId, rather than embedding the entire customer profile).
If it comes as a 4-mark question: Answer whichever part is specifically asked. If the prompt is broad, answer Part A (Data Integration & ETL vs ELT) with Fig 1.9, as it is the most frequently asked half.
Quick recall Integration = unifying heterogeneous data via ETL (clean then store) or ELT (store raw in lake, transform on demand). Aggregate = bundling related entities into one atomic unit (document/key-value) to enable fast distributed sharding without network joins.

Q9. Explain the components of Data Science and the 5 P's.

Unit II · 8 marks · Exam focus: The 5 P's framework (Purpose, People, Process, Platforms, Programmability), how they interlink, and a practical real-world example.

Definition: In modern enterprise computing (pioneered by UC San Diego), the core components of Data Science are formulated as the 5 P's: Purpose, People, Process, Platforms, and Programmability. These interdependent pillars work together to transform raw Big Data into valuable data products and automated business decisions.
  • 1. Purpose (The "Why"): The clear business challenge, strategic goal, or question that justifies the project. Without a defined purpose, data science is aimless number-crunching.
    Example: A food delivery app asking: "How can we accurately predict delivery arrival times within ±3 minutes to reduce customer cancellations?"
  • 2. People (The "Who"): The cross-disciplinary team required to build and deploy solutions. It includes Domain Experts (who understand the business), Data Engineers (who build pipelines), Data Scientists / ML Engineers (who design mathematical models), and Business Stakeholders.
  • 3. Process (The "How"): The structured scientific methodology followed from start to finish: Problem formulation → Data acquisition → Cleaning & feature engineering → Model training → Validation → Deployment → Feedback loop.
  • 4. Platforms (The "Where"): The distributed infrastructure and compute/storage environments that host the data and algorithms. Examples include Hadoop/HDFS clusters, Apache Spark, cloud infrastructure (AWS/GCP/Azure), and GPU computing clusters.
  • 5. Programmability (The "With What"): The programming languages, libraries, and automated scripts that turn mathematical formulas into production software. Examples include Python, R, SQL, PySpark, scikit-learn, and workflow schedulers like Apache Airflow.
  • How the 5 P's Interlink: The Purpose determines the right People to hire; the team defines the systematic Process; the process dictates the computing Platform needed; and Programmability ties the whole architecture together into automated, repeatable pipelines.

Q10. Explain the complete Data Science process with an example.

Unit II · 8 marks · Exam focus: The 5-stage iterative lifecycle (Acquire → Prepare → Analyze → Report → Act), the feedback loop, comparison with CRISP-DM, and a full worked case study.

Definition: The Data Science Process is an iterative, structured scientific workflow that takes a project from an abstract business question to a deployed, value-generating solution. It consists of five core stages: Acquire, Prepare, Analyze, Report, and Act (APARA).
  • 1. Acquire (Data Collection): Identify, gather, and ingest raw data from internal databases, web APIs, real-time sensor streams, and public repositories into the working storage environment.
  • 2. Prepare (Exploration & Cleaning — ~70% of Project Effort): Split into two essential sub-tasks:
    • Explore (EDA): Compute descriptive statistics (mean, median, standard deviation), plot histograms, and uncover correlation patterns.
    • Pre-process / Clean: Handle missing values (imputation or removal), eliminate duplicate rows, filter out extreme sensor noise/outliers, normalize numerical scales, and encode categorical labels.
  • 3. Analyze (Model Building & Machine Learning): Select the appropriate analytical techniques (regression, classification, clustering, or neural networks), train models on historical training sets, and rigorously evaluate performance using metrics like Accuracy, Precision, Recall, and RMSE.
  • 4. Report (Communication & Storytelling): Translate dense mathematical findings and confusion matrices into intuitive, visual charts and business dashboards. Present actionable insights clearly to non-technical business managers.
  • 5. Act (Deployment, Decision & Monitoring): Embed the validated model into live production applications (e.g. an automated REST API). Continuously monitor real-world accuracy, collect feedback, and loop back to Step 1 as new questions arise.
  • Industry Standard: CRISP-DM Framework: The 5-stage APARA process directly mirrors the 6 phases of CRISP-DM (Cross-Industry Standard Process for Data Mining):
    1. Business Understanding → 2. Data Understanding → 3. Data Preparation → 4. Modeling → 5. Evaluation → 6. Deployment.
Process StageInput to StageOutput from Stage
1. AcquireBusiness question & data source connectionsRaw, uncurated data dumps
2. PrepareRaw, noisy datasetsClean, validated, feature-engineered dataset
3. AnalyzeClean datasetTrained and evaluated mathematical model
4. ReportModel evaluation results and performance metricsExecutive charts, dashboards, and recommendations
5. ActActionable business insightsDeployed live production service, operational ROI
Worked Real-World Example: IPL Cricket Team Selecting Bowlers for an Auction
1. Acquire: Pull 10 years of ball-by-ball IPL match data from Cricinfo and official match tracking APIs.
2. Prepare: Filter out rain-affected matches; handle missing speed gun telemetry; compute economy rates in powerplay vs death overs.
3. Analyze: Train regression and clustering models to identify bowlers who reliably concede under 8 runs per over in the death overs (overs 16–20) on spin-friendly pitches.
4. Report: Present a visual dashboard to the team coach showing the top 3 undervalued death-over specialist bowlers within their salary purse.
5. Act: The franchise bids for and buys the targeted bowlers in the auction, monitoring their match performances and refining the model each week!
Mnemonic "All Players Are Really Active" → Acquire, Prepare, Analyze, Report, Act.

Q11. What is Big Data Modeling and Management? Explain its six concerns.

Unit II · 8 marks · Exam focus: Definition of Big Data Management and Data Model (Structure/Operations/Constraints), plus a thorough explanation of all six management concerns.

Definition: Big Data Management is the comprehensive set of architectures, governance policies, and computational tools required to ingest, store, validate, operate upon, scale, and secure massive data assets throughout their entire lifecycle. A Data Model formally defines data along three dimensions: Structure (how data is organized), Operations (how it is queried/manipulated), and Constraints (rules ensuring integrity).
  • 1. Ingestion Concern (Getting Data In): Handling the continuous intake of data from varied outside sources. Organizations must balance Batch Ingestion (scheduled periodic bulk loads via Sqoop) with Streaming Ingestion (sub-second real-time event capture via Kafka/Flume), while establishing backpressure policies so sudden traffic spikes don't crash intake servers.
  • 2. Storage Concern (Where and How to Persist Data): Managing the physical memory hierarchy (CPU Cache → RAM → SSD → Hard Disk → Cloud Cold Archive). It involves selecting the right database paradigm (HDFS for distributed file storage, NoSQL for real-time document/key access, and Data Lakes vs. Data Warehouses) to balance access speed against storage costs.
  • 3. Quality Concern (Keeping Data Clean & Trustworthy): Dirty data produces faulty models. Big data quality frameworks detect and resolve the MIDIO defects: Missing values, Invalid data, Duplicate records, Inconsistent formats across systems, and extreme Outliers.
  • 4. Operations Concern (Manipulating Data at Scale): Executing relational and matrix operations across billions of records in parallel without running out of cluster memory. Core operations include Selection (filtering rows), Projection (choosing columns), Joins, Unions, and Aggregations (computing sums/averages across groups).
  • 5. Scalability Concern (Growing the System Seamlessly): Ensuring the architecture can absorb a 10× or 100× increase in data volume and user queries. Rather than Scaling Up (buying a cost-prohibitive supercomputer), Big Data management prioritizes Scaling Out (adding cheap commodity servers to a cluster, partitioning data into shards, and replicating blocks).
  • 6. Security & Governance Concern (Protecting the Asset): Safeguarding enterprise data against unauthorized breaches and ensuring compliance with privacy regulations. Protects the fundamental CIA Triad:
    • Confidentiality: Authentication (Kerberos) and Role-Based Access Control (RBAC) ensuring only authorized users view records.
    • Integrity: Cryptographic encryption at rest (AES-256) and in transit (TLS) preventing tampering.
    • Availability: Cluster replication and failover guarantees ensuring systems stay online 24/7.
    • Compliance: Anonymizing Personally Identifiable Information (PII) to satisfy data protection acts (such as India's DPDP Act and GDPR).
Mnemonic The Six Concerns: "I Saw Queen Oprah Speak Secretly" → Ingestion, Storage, Quality, Operations, Scalability, Security. Data Model = SOC (Structure, Operations, Constraints).
If it comes as a 4-mark question: Write the definition, draw Fig 2.11, and explain Ingestion and Storage (the two most heavily tested concerns) in 2-3 lines each.
Quick recall Data Model = Structure + Operations + Constraints (SOC). 6 Management Concerns: Ingestion (batch/stream) · Storage (lake/NoSQL) · Quality (MIDIO cleaning) · Operations (parallel algebra) · Scalability (scale-out) · Security (CIA triad + encryption).

Q13. Explain a real-world Data Science example using advanced techniques.

Unit II · 8 marks · Exam focus: Recommender systems (Netflix / Amazon) walked through the 5-step lifecycle, advanced modeling techniques, and a complete worked cosine similarity numeric.

Definition: A Recommendation System is an advanced Data Science application that predicts the preference or rating a user would assign to an item (such as a movie, product, or song), generating personalized suggestions by analyzing historical user interactions and collective community behavior.
  • Famous Industry Milestone: The Netflix Prize (2006–2009) offered $1,000,000 to the first team that could improve Netflix's movie recommendation accuracy by 10%. The winning team succeeded by combining Matrix Factorization with an ensemble of diverse machine learning models.
  • Walkthrough Across the 5 Data Science Stages (Fig 2.27):
    1. Acquire: Collect user viewing history, watch duration, explicit star ratings, search queries, time of day, and device type.
    2. Prepare: Filter out automated bot accounts, remove accidental 5-second clicks, normalize star ratings, and construct a high-dimensional User-Item Interaction Matrix.
    3. Analyze: Apply advanced recommendation algorithms (Collaborative Filtering, Matrix Factorization, and Deep Learning).
    4. Report: Measure performance via offline metrics (RMSE, Precision@K) and live online business dashboards tracking average user watch time and subscriber churn.
    5. Act: Deploy real-time recommendation microservices that dynamically assemble a unique, personalized home screen for each user the moment they open the app.
Advanced TechniqueHow It Works in Plain English
Collaborative FilteringFinds users with similar past viewing habits and recommends titles that those similar users loved, but the current user hasn't seen yet.
Matrix Factorization (SVD)Decomposes the massive, sparse User-Item rating matrix into lower-dimensional vectors capturing hidden latent taste factors (e.g. action quotient, comedy level).
Content-Based FilteringRecommends items that share descriptive features (director, genre, actors) with items the user previously rated highly.
Deep Learning & EmbeddingsNeural networks (like Two-Tower models) learn complex non-linear patterns from multi-modal inputs (thumbnails, watch history, search queries).
A/B TestingServes Algorithm A to 50% of users and Algorithm B to 50% of users, verifying with statistical confidence which model increases viewer engagement.
Worked Numerical Example: User-Based Collaborative Filtering using Cosine Similarity
Three users rate 5 movies on a 1 to 5 scale (0 indicates the user hasn't watched the movie yet):
• User A: $\mathbf{A} = (5, 4, 0, 1, 5)$
• User B: $\mathbf{B} = (4, 5, 0, 1, 4)$
• User C: $\mathbf{C} = (1, 0, 5, 4, 1)$
Cosine Similarity Formula: $ ext{Sim}(\mathbf{u}, \mathbf{v}) = \dfrac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\| imes \|\mathbf{v}\|}$
Calculate Similarity between User A and User B:
Dot product: $\mathbf{A} \cdot \mathbf{B} = (5 imes 4) + (4 imes 5) + (0 imes 0) + (1 imes 1) + (5 imes 4) = 20 + 20 + 0 + 1 + 20 = 61$.
Magnitudes: $\|\mathbf{A}\| = \sqrt{25+16+0+1+25} = \sqrt{67} pprox 8.185$; $\|\mathbf{B}\| = \sqrt{16+25+0+1+16} = \sqrt{58} pprox 7.616$.
$ ext{Sim}(\mathbf{A}, \mathbf{B}) = \dfrac{61}{8.185 imes 7.616} = \dfrac{61}{62.337} pprox \mathbf{0.979}$ (Extremely high similarity!)
Calculate Similarity between User A and User C:
Dot product: $\mathbf{A} \cdot \mathbf{C} = (5 imes 1) + (4 imes 0) + (0 imes 5) + (1 imes 4) + (5 imes 1) = 5 + 0 + 0 + 4 + 5 = 14$.
Magnitude: $\|\mathbf{C}\| = \sqrt{1+0+25+16+1} = \sqrt{43} pprox 6.557$.
$ ext{Sim}(\mathbf{A}, \mathbf{C}) = \dfrac{14}{8.185 imes 6.557} = \dfrac{14}{53.67} pprox \mathbf{0.261}$ (Very low similarity).
Recommendation Decision: User B is far more similar to User A (0.979 vs 0.261). The system recommends to User A the movies that User B enjoyed!
Mnemonic Core Recommendation Stack C-M-D-A: Collaborative filtering, Matrix factorization, Deep learning, validated by A/B testing.

1-mark questions

Quick revision flashcards · High-yield 1-mark concepts written in clear, direct English with supporting micro-diagrams for instant exam recall.

Q1

Define Big Data.

Massive datasets whose Volume, Velocity, and Variety exceed the storage and processing limits of traditional RDBMS, requiring distributed clusters of commodity computers for parallel analysis.
Key takeaway: Exceeds single-server RDBMS limits; scales horizontally on distributed clusters.
Q2

List the 5 Vs of Big Data.

The five core dimensions: Volume (scale/size), Velocity (arrival speed), Variety (diverse formats), Veracity (trustworthiness/cleanliness), and Value (business utility and ROI).
Mnemonic: 5 Vs = Volume, Velocity, Variety, Veracity, Value.
Q3

Differentiate structured and unstructured data.

Structured: Follows a rigid predefined schema in rows and columns, easily queryable with SQL (e.g. bank accounts).
Unstructured: Has no predefined data model; requires specialized AI/NLP/Vision parsing (e.g. video files, audio clips, photos).
Key takeaway: Fixed schema (SQL tables) vs. No predefined schema (media/text).
Q4

Name three sources of Big Data.

1. Human-generated: Social media posts, emails, online reviews.
2. Machine-generated: IoT sensors, web server clickstream logs, GPS trackers.
3. Organisational / Transactional: ERP systems, CRM records, banking UPI transactions.
Mnemonic: H-M-O → Humans, Machines, Organisations.
Q5

Expand ETL and ELT.

ETL: Extract → Transform → Load (clean and transform data before loading it into a structured Data Warehouse).
ELT: Extract → Load → Transform (dump raw data directly into a Data Lake first, transforming later on-demand).
Key takeaway: ETL = Warehouse (clean first); ELT = Data Lake (load raw first).
Q6

Differentiate Data Lake and Data Warehouse.

Data Warehouse: Stores curated, heavily transformed, structured data for historical business reporting (schema-on-write).
Data Lake: Low-cost repository that stores vast quantities of raw data in native formats until needed (schema-on-read).
Key takeaway: Warehouse = schema-on-write; Lake = schema-on-read.
Q7

What is Hadoop?

An open-source Apache framework designed for distributed, fault-tolerant storage (HDFS), cluster resource negotiation (YARN), and parallel batch processing (MapReduce) running on commodity hardware.
Core trio: HDFS (Storage) + YARN (Scheduling) + MapReduce (Compute).
Q8

What is the role of the NameNode?

The master server of HDFS. It manages the filesystem namespace, directory hierarchy, user permissions, and keeps the mapping of data blocks to DataNodes in memory (it does not store actual file contents).
Key takeaway: NameNode = metadata in RAM; DataNodes = raw data blocks on disk.
Q9

Default HDFS block size and replication factor?

Block size: 128 MB in Hadoop 2.x and 3.x (64 MB in Hadoop 1.x).
Replication factor: 3 by default (stored across multiple separate racks for fault tolerance).
Key numbers: 128 MB per block · 3 copies stored per block across racks.
Q10

Expand YARN and name its components.

Yet Another Resource Negotiator.
Components: ResourceManager (cluster-wide master), NodeManager (worker agent on each machine), ApplicationMaster (per-job negotiator), and Container (CPU+RAM allocation).
Key components: RM (cluster master) · NM (node agent) · AM (per-job) · Container.
Q11

Expand NoSQL and list its four types.

Not Only SQL. Non-relational, distributed databases built for horizontal scaling.
Four types: Key-Value (Redis), Document (MongoDB), Column-Family (Cassandra/HBase), and Graph (Neo4j).
Four families: Key-Value, Document, Column-Family, and Graph.
Q12

State the CAP theorem.

A distributed data store can simultaneously provide at most two out of three guarantees: Consistency (all nodes see the exact same data at the same time), Availability (every non-failing node returns a response), and Partition Tolerance (system functions despite network communication breaks).
Rule: When network partition (P) occurs, the system must trade off C against A.
Q13

Define Data Science.

An interdisciplinary field that extracts actionable insights, knowledge, and predictive models from structured and unstructured data by combining Computer Science, Mathematics & Statistics, and Domain Expertise.
Triad: Computer Science + Mathematics/Statistics + Domain Knowledge.
Q14

List the five P's of Data Science.

1. Purpose: The core business objective.
2. People: The multidisciplinary team.
3. Process: The systematic scientific methodology.
4. Platforms: The compute/storage infrastructure.
5. Programmability: Code and automated pipelines (Python, SQL).
Mnemonic: 5 Ps = Purpose, People, Process, Platforms, Programmability.
Q15

List the steps of the Data Science process.

An iterative 5-stage lifecycle:
Acquire (gather raw data) → Prepare (explore, clean, pre-process) → Analyze (train and evaluate models) → Report (visualize insights) → Act (deploy live decisions).
Mnemonic: APARA → Acquire, Prepare, Analyze, Report, Act.
Q16

Define Data Ingestion.

The transportation of data from disparate external sources (RDBMS, streaming event queues, logs, IoT sensors) into a target storage or analytics repository (HDFS, Kafka, Data Lake) in batch or real-time streams.
Key takeaway: Moving data from outside generators into internal storage.
Q17

Differentiate batch and streaming ingestion.

Batch (Sqoop): Collects accumulated data periodically in large chunks; high throughput with higher latency (hours or days).
Streaming (Kafka / Flume): Collects and processes each event continuously as it occurs; sub-second real-time latency.
Key difference: Periodic chunks (Batch) vs. Instant live events (Streaming).
Q18

Differentiate selection and projection.

Selection (σ): A horizontal operation filtering rows that meet a specified condition (e.g. WHERE age > 20).
Projection (π): A vertical operation selecting specific columns across all rows (e.g. SELECT name, city).
Relational algebra: Selection = Rows (σ); Projection = Columns (π).
Q19

Differentiate scale up and scale out.

Scale Up (Vertical): Adding more CPU cores, RAM, or storage to a single server (hits hardware and cost limits).
Scale Out (Horizontal): Adding more standard commodity servers to a networked cluster (indefinitely expandable).
Big Data rule: Scaling out on commodity nodes always beats scaling up.
Q20

List Data Security measures.

1. Access Control: User authentication (Kerberos) & Role-Based Authorization (RBAC).
2. Encryption: AES-256 for data at rest; TLS 1.3 for data in transit.
3. Data Masking: Anonymizing sensitive PII.
4. Auditing: Tamper-proof access and query logs.
Four pillars: Auth/RBAC, Encryption, Data Masking, and Auditing.
Q21

What is a Big Data Management Plan?

An architectural blueprint specifying how an organization handles: Ingestion (streams/batches), Storage (lake/NoSQL), Quality (cleansing/deduping), Operations (analytics), Scalability (scale-out), and Security (governance).
Mnemonic: "I Saw Queen Operate Scaled Security" (I-S-Q-O-S-S).
Q22

What is Collaborative Filtering?

A recommendation system technique that predicts items a user will like based on the historical ratings or viewing preferences of other users who share similar taste (computed using Cosine Similarity).
Key concept: Users with similar past tastes will like similar items in the future.
Q23

What is A/B Testing?

A controlled experiment where users are split randomly into two groups: Version A (baseline control) and Version B (modified treatment) to statistically determine which yields a higher conversion rate.
Key concept: Controlled split-testing to statistically prove which version converts better.
Q24

What is the CIA triad in Data Security?

The three fundamental pillars of information security:
Confidentiality: Unauthorized individuals cannot view sensitive data.
Integrity: Data cannot be altered or tampered with.
Availability: Authorized users have reliable access when needed.
CIA Triad: Confidentiality, Integrity, Availability.
