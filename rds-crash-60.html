Unit 1 · Intro to Data Science ~8% of paper · mostly Part-A

Data Science & the DIKW ladder

  • Data Science = extracting knowledge and insight from data using statistics + programming + domain knowledge.
  • Data = raw facts (23, "Jon") · Information = data with meaning (Jon is 23) · Knowledge = patterns (customers under 25 buy more) · Wisdom = right action.
  • Data types: structured (tables), unstructured (images/text), semi-structured (JSON/XML).
  • Variable = a named property that varies across records: qualitative (category: gender) or quantitative (number: age — discrete or continuous).

Data processing chain

  • Collect → Clean/Prepare → Store → Analyse → Visualise/Communicate — every DS project walks this chain.
  • Wholeness of data analytics: all stages form ONE pipeline; a weak stage (dirty data) poisons every later stage.

Data mining · Data warehouse · DB vs DW

  • Data mining = digging through big data for hidden patterns (market-basket: "bread buyers also buy butter").
  • Data warehouse = a central store of historical data from many sources, built for analysis (OLAP), not daily transactions.

B1 · CENTRAL TENDENCY + DISPERSION · 3× — came EVERY year · 10 M
Explain measures of central tendency and dispersion. Calculate them in R.
Like you're 5Centre = "where do most marks sit?" (mean/median/mode). Spread = "how far apart are the marks?" (range/variance/SD).

Central tendency (the centre)

  • Mean = sum ÷ count = Σx / n · R: mean(x)
  • Median = middle value after sorting · R: median(x)
  • Mode = value that appears most often (no built-in; use table(x) and pick the max)

Dispersion (the spread)

  • Range = max − min
  • Variance = average of squared distances from mean = Σ(x − x̄)² / (n−1) · R: var(x)
  • SD = √variance (same units as data) · R: sd(x)
  • IQR = Q3 − Q1, the middle 50% · R: IQR(x)

Worked example — x = 2, 4, 4, 4, 5, 5, 7, 9

  • Mean = (2+4+4+4+5+5+7+9)/8 = 40/8 = 5
  • Median = middle of 4 and 5 = 4.5 · Mode = 4 (appears 3 times)
  • Σ(x−5)² = 9+1+1+1+0+0+4+16 = 32 → Variance = 32/7 = 4.571 → SD = 2.138
  • Range = 9−2 = 7
x <- c(2, 4, 4, 4, 5, 5, 7, 9)
mean(x); median(x)        # 5, 4.5
var(x); sd(x); IQR(x)     # 4.571, 2.138, 1.5
diff(range(x))            # 7
B2 · HYPOTHESIS TESTING + t-TEST · 3× — came EVERY year · 10 M
What is hypothesis testing? Steps + t-test example in R.
Like you're 5It's a court case. H₀ = "innocent" (nothing changed). Data = evidence. Strong evidence (p < 0.05) → guilty (reject H₀). Weak evidence → let go (fail to reject).

A hypothesis test uses sample data to decide whether a claim about a population is believable.

The 6 steps

  • 1. State hypotheses — H₀ (null: no difference, μ = 70) vs H₁ (alternative: μ ≠ 70)
  • 2. Choose α — significance level, normally 0.05
  • 3. Compute test statistic — t = (x̄ − μ) / (s/√n)
  • 4. Find p-value — R gives it directly
  • 5. Decide — p < α → reject H₀; p ≥ α → fail to reject H₀
  • 6. Conclude in words

Types

  • One-sample t: one group vs known value · t.test(x, mu = 70)
  • Two-sample t: compare two groups · t.test(x, y)
  • Paired t: before vs after on same people · t.test(x, y, paired = TRUE)

Worked example — claim: class average is 70

scores <- c(68, 72, 75, 69, 71, 66, 74, 73, 70, 67)
t.test(scores, mu = 70)
# t = 0.522, df = 9, p-value = 0.614

p (0.614) > α (0.05) → fail to reject H₀ — class mean is 70

B6 · FIT A BINOMIAL DISTRIBUTION (NUMERICAL) · May-24 Q4(b) · 5–10 M
Fit a Binomial distribution: x = 0–5, f = 2, 16, 28, 12, 9, 3.
Like you're 5Find the average → turn it into probability p → use the binomial formula to predict what the table SHOULD look like.
  • Step 1: N = Σf = 2+16+28+12+9+3 = 70
  • Step 2: Σfx = 0+16+56+36+36+15 = 159 → mean x̄ = 159/70 = 2.2714
  • Step 3: p̂ = x̄ / n = 2.2714 / 5 = 0.4543 (divide by n = 5 trials, NOT by 70!) · q̂ = 0.5457
  • Step 4: Expected E(x) = 70 · C(5,x) · p̂ˣ · q̂⁵⁻ˣ

B7 · GRADE-CLASSIFIER SCRIPT (functions + if + loop) · May-25 Q4 · 15 M
Write an R script using a function, conditional statements and a loop to classify student grades.
Like you're 5One machine (function) reads a mark and stamps A/B/C/F; a loop feeds every student into the machine.
# Function: decide grade for one mark
grade <- function(m) {
  if (m >= 80)      return("A")
  else if (m >= 60) return("B")
  else if (m >= 40) return("C")
  else              return("F")
}

marks <- c(91, 72, 55, 38, 85)
names <- c("Asha","Ravi","Meena","Sam","Jo")

# Loop: classify every student
for (i in 1:length(marks)) {
  cat(names[i], ":", marks[i], "->", grade(marks[i]), "\n")
}
# Asha : 91 -> A
# Ravi : 72 -> B
# Meena: 55 -> C
# Sam  : 38 -> F
# Jo   : 85 -> A

# Bonus mark: vectorised one-liner
sapply(marks, grade)
  • function() = reusable block with return() · if / else if / else = decision ladder · for loop = repeat per student.

B10 · DEBUGGING TECHNIQUES · 2× · 5–7.5 M
Explain debugging techniques in R.
Like you're 5Code crashed. Five torchlights: one shows WHERE it died, one walks line-by-line, one freezes the code mid-run so you can look around.
  • traceback() — run right after an error; shows the chain of calls that led to the crash.
  • debug(f) — next call of f runs line-by-line (n = next). undebug(f) to stop.
  • browser() — placed inside a function; execution pauses there to inspect variables.
  • trace() — temporarily inject extra code (e.g. a print) into a function without editing it.
  • options(error = recover) — on any error, choose a call frame to jump into and inspect.
f <- function(x) { y <- x * 2; browser(); y + z }   # z missing!
f(3)        # pauses at browser(); type ls(), y, then Q
traceback() # after the error: shows f(3) caused it
