1.1 Introduction to Java, JDK, JRE and JVM

Java was built so code written on a Windows PC runs unchanged on Linux or Mac. (ek baar likho, har jagah chalao)

Definition: Java is a high-level, object-oriented, class-based, platform-independent programming language created by James Gosling at Sun Microsystems in 1995.
  • JDK (Java Development Kit): Complete software bundle needed to write and compile Java programs. Contains javac compiler.
  • JRE (Java Runtime Environment): Software bundle required to run compiled Java bytecode. Contains runtime libraries + JVM.
  • JVM (Java Virtual Machine): Abstract software machine that executes bytecode by translating it into CPU-specific machine instructions.
  • History: Developed in 1991 as Oak for interactive television; renamed to Java in 1995; acquired by Oracle Corporation in 2010.

Inside the JDK — the four tools you actually use:

  • javac (Java compiler): translates .java source code into .class bytecode.
  • java (the launcher, part of the JRE): loads a .class file into the JVM and runs it.
  • jdb (Java debugger): steps through a running program to help find bugs.
  • jar (Java Archive tool): packs compiled classes into one .jar file for distribution over a network.
Common mistake: thinking jdb is what executes a program. Compiling uses javac; running uses java; jdb is only for debugging.

Primary Java Features:

Mnemonic S-P-O-R-T-S-M-D: Simple, Platform-independent, Object-oriented, Robust, Threaded (multithreaded), Secure, Multithreaded, Distributed.

All 12 Java buzzwords (features), in full — this is also called "Why Java?" in exams:

  • Simple: syntax based on C/C++; removed confusing, rarely-used features such as explicit pointers and operator overloading; no manual memory clean-up is needed (the JVM manages it automatically, see 1.2).
  • Object-Oriented: software is organised as a combination of objects, each holding both data and behaviour.
  • Platform independent: the same bytecode runs on Windows, Linux, macOS — anywhere a JVM exists (see 1.2, WORA).
  • Secured: no explicit pointers, every program runs inside the JVM's sandbox, and Java uses a public-key encryption system for security.
  • Robust: strong memory management, no pointers (avoids memory-corruption bugs), and built-in exception handling with compile-time type checking.
  • Architecture neutral: no implementation-dependent feature sizes — e.g. int is always 4 bytes in Java on every platform (exact int sizes in C vary by compiler/platform; the exam point is that Java's size is fixed everywhere).
  • Portable: the same bytecode file can be carried to any platform; the javac compiler itself is written in ANSI C for a clean portability boundary.
  • Dynamic: more adaptive to an evolving environment than C/C++; carries extensive run-time information to verify and resolve access to objects.
  • Interpreted: bytecode is translated on the fly into native machine instructions and is not stored anywhere — it can be interpreted on any system that provides a JVM.
  • High performance: the JIT (Just-In-Time) compiler translates bytecode directly into native machine code for very high speed.
  • Multithreaded: supports writing programs that do many things at once; each thread is like a separate program executing concurrently, and threads share one common memory area.
  • Distributed: designed for the distributed environment of the internet; Java's Remote Method Invocation (RMI) lets a program call methods on another machine over a network.
Mnemonic remember all 12 in three groups of four — SOPS (Simple, OOP, Platform-independent, Secured) · RAPD (Robust, Architecture-neutral, Portable, Dynamic) · IHMD (Interpreted, High-performance, Multithreaded, Distributed).

What is Java, and where is it used?

Definition: Java is both a programming language and a platform — a platform is any hardware or software environment in which a program runs; Java supplies its own software platform, the JRE.
  • Standalone application: a desktop/window-based app installed on a machine, e.g. a media player or antivirus — built using AWT and Swing.
  • Web application: runs on the server and creates dynamic pages, e.g. irctc.co.in — built using Servlet, JSP.
  • Enterprise application: distributed applications such as banking systems — built using EJB.
  • Mobile application: apps for phones — built using Android or Java ME.

Oracle/Sun's own long-standing marketing claim is that Java runs on roughly 3 billion devices worldwide — a promotional figure worth knowing for the exam, not one this course independently verifies.

History of Java — how it got its name:

  • The Java language project was started in June 1991 by James Gosling, Mike Sheridan and Patrick Naughton — a small team of Sun engineers nicknamed the "Green Team" — to write software for digital devices such as set-top boxes and televisions.
  • James Gosling first called the language "Greentalk", with the file extension .gt.
  • It was then renamed "Oak". Oak is a symbol of strength and the national tree of several countries (the reason given in these notes); a commonly told alternative story is that it was named after an oak tree that stood outside Gosling's office — different sources give different reasons.
  • In 1995 the name changed again because "Oak" was already a trademark of Oak Technologies. The team considered "dynamic", "revolutionary", "silk", "jolt", "DNA" before settling on "Java" — Gosling said Java was one of the top choices along with Silk.
  • Java is also the name of an island in Indonesia famous for its coffee, and "java" is common slang for coffee — which is why the Java logo is a coffee cup.
  • Java was originally developed by James Gosling at Sun Microsystems and released in 1995; Sun Microsystems was later acquired by Oracle Corporation in 2010.
Quick recall JDK = JRE + Tools; JRE = JVM + Libraries; JVM executes bytecode. Java is platform independent because of bytecode. 12 buzzwords, 6 OOP pillars, born 1991 as "Oak", renamed "Java" in 1995.

1.2 Java Virtual Machine (JVM) Architecture & Execution Pipeline

Bytecode is the universal language that lets Java code travel across any operating system without re-compilation. (bytecode sabhi OS ki aam bhasha hai)

Definition: The JVM (Java Virtual Machine) is a runtime engine that loads intermediate bytecode (.class file) produced by javac, verifies it, and converts it into machine code for execution.
  • Bytecode: Platform-independent intermediate code representation stored in .class files after compilation.
  • WORA (Write Once, Run Anywhere): Java code compiled on one OS can run on any OS having a compatible JVM.
  • Class Loader Subsystem: Performs three steps: Loading (loads .class file), Linking (Verification, Preparation, Resolution), and Initialization (executes static initializers).
  • Runtime Data Areas:
    • Method Area: Stores class structure, field/method data, and static variables.
    • Heap: Stores all created objects and instance variables. Managed by the garbage collector.
    • Java Stack: Stores stack frames for active methods, local variables, and partial results.
    • PC Register: Holds the address of the current JVM instruction being executed.
    • Native Method Stack: Contains state for native (C/C++) methods.
  • Execution Engine:
    • Interpreter: Reads and executes bytecode instructions one by one.
    • JIT Compiler (Just-In-Time): Compiles frequently executed bytecode chunks (hotspots) directly into native CPU code to boost performance.
    • Garbage Collector: Automatically deallocates unreferenced heap memory.

Compile-time vs run-time, in one line each:

StageWhat happens
Compile-time (javac)The .java source file is checked for syntax errors and translated into platform-independent bytecode (.class).
Run-time (java / JVM)The class loader loads the bytecode, verifies it, and the execution engine converts it into native machine instructions to run.
Common mistake: Thinking bytecode is CPU machine code. Bytecode is instructions for the JVM; the JVM translates it into CPU instructions.
Quick recall JVM architecture = Class loader subsystem + Runtime memory areas (Heap, Stack, Method area) + Execution Engine (Interpreter + JIT + GC).

1.3 Structure of a Java Program

Every Java program starts execution from main() inside a public class. (main method se program chalu hota hai)

Definition: A Java program consists of one or more class definitions where execution begins at the public static void main(String[] args) entry point.

Program: Hello World program line-by-line structure demo.

// Every Java program must be inside a class
public class HelloWorld {
    // Entry point method executed by JVM
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
Hello, Java!
  • public: Keyword making the class/method accessible from outside the package by the JVM.
  • class: Keyword used to define a class template.
  • static: Allows the JVM to call main() without creating an instance object of the class first.
  • void: Return type indicating the method does not return any value.
  • main: Name of the entry-point method recognized by the JVM.
  • String[] args: Array of string parameters passed via command line arguments.
  • System.out.println(): System class, out static stream, println method to output text followed by a new line.
  • System.out.println() in full: System is a class in the java.lang package; out is an output-stream object that is a member of the System class; println() is a method supported by that out object, used to display any kind of output on the screen.

Steps to write, compile and run a Java program:

  • The PATH environment variable must point to the JDK's bin folder (e.g. C:\Program Files\Java\jdk1.x.x\bin) so the javac and java commands work from any folder. Typed once via My Computer → Properties → Advanced → Environment Variables.
  • The saved file name must match the public class name exactly, including capitalisation, e.g. HelloWorld.java for public class HelloWorld.
  • At compile time the .java file is converted into bytecode (.class); at run time that bytecode is converted into machine-understandable instructions.

Java comments: statements that are not executed by the compiler or interpreter; used to explain code or temporarily hide it.

Variables & Type Conversion / Casting:

  • Variables: Named storage locations in memory (Local, Instance, Static variables).
  • Literals: Constant values assigned directly to variables (e.g., 100, 'A', 3.14f).
  • Widening (Implicit Casting): Converting a smaller type to a larger type automatically. Safe with no data loss: byte → short → int → long → float → double.
  • Narrowing (Explicit Casting): Converting a larger type to a smaller type manually using cast syntax (target_type). May result in data loss.

Program: Demonstrating primitive data types, widening, and narrowing type casting.

public class DataTypeDemo {
    public static void main(String[] args) {
        byte b = 100;
        int i = b;            // Implicit widening: byte -> int
        double d = 10.5;
        int x = (int) d;      // Explicit narrowing: double -> int
        char c = 'A';
        boolean flag = true;
        System.out.println("b=" + b + ", i=" + i + ", x=" + x + ", c=" + c + ", flag=" + flag);
    }
}
b=100, i=100, x=10, c=A, flag=true

Some values never change (e.g. the value of pi, about 3.142; a day always has 24 hours) — these are called constants. Java has no separate "constant" keyword; a static final variable is used as one, e.g. static final double PI_APPROX = 3.142; (final itself is covered fully in Unit II).

        int n = 9;                          // local variable
        System.out.println("x=" + x + ", m=" + m + ", n=" + n + ", PI_APPROX=" + PI_APPROX);

Scope and lifetime of a variable:

Definition: the scope of a variable is the block of code in which it is accessible; its lifetime is how long it stays in memory. A block begins with { and ends with } — one block is one new scope.
  • A variable is created when its scope is entered and destroyed when its scope is left — a local variable declared inside a method does not hold its value outside that method.
  • Instance and static variables live longer: as long as their object (instance) or their class (static) stays in memory.
Mnemonic B-S-I-L-F-D (Byte, Short, Int, Long, Float, Double) for integral to floating widening order.
Quick recall Java has 8 primitive types; widening is automatic, narrowing requires explicit (type) cast. 3 variable categories: local (in a method), instance (per object), static (per class, shared).

public class OperatorDemo {
    public static void main(String[] args) {
        int a = 10, b = 3;
        int pre = ++a;             // Pre-increment: a becomes 11, pre=11
        int post = b++;            // Post-increment: post=3, b becomes 4
        int bit = 5 & 3;           // Bitwise AND: 101 & 011 = 001 (1)
        int max = (a > b) ? a : b;  // Ternary operator
        System.out.println("pre=" + pre + ", post=" + post + ", bit=" + bit + ", max=" + max);
    }
}
pre=11, post=3, bit=1, max=11

The cast operator (type) is listed by many textbooks as its own operator category, distinct from arithmetic/relational/logical operators — it is the operator form of type casting. See the Data Types topic for the full widening/narrowing rules and hierarchy diagram.

Common mistake: Confusing && (short-circuit logical AND) with & (bitwise AND). && stops evaluating if the first condition is false.
Quick recall Pre-increment (++i) increments before value use; post-increment (i++) uses current value first. Ternary format: cond ? trueVal : falseVal.

1.6 Expressions, Evaluation, and Type Promotion

When mixed data types meet in an expression, Java automatically promotes smaller types to match the largest type in the expression. (badi data type me promotion ho jata hai)

Definition: An expression is a combination of variables, constants, operators, and method calls that evaluates to a single value governed by operator precedence and type promotion rules.

Simple example: int marks = 25; int extmarks = 75; int total = 0; total = marks + extmarks; → total becomes 100.

  • Automatic Type Promotion Rules:
    • All byte, short, and char values are promoted to int during expression evaluation.
    • If one operand is long, the entire expression is promoted to long.
    • If one operand is float, the entire expression is promoted to float.
    • If any operand is double, the entire result is promoted to double.
Worked Example: Type Promotion Evaluation
Given: byte b=40; char c='a' (ASCII 97); int i=50; float f=5.67f; double d=0.1234;
Expression: (f * b) + (i / c) - (d * 5)
Step 1: f * b → 5.67f * 40 → 226.8f (promoted to float)
Step 2: i / c → 50 / 97 → 0 (integer division)
Step 3: d * 5 → 0.1234 * 5 → 0.6170 (promoted to double)
Step 4: 226.8f + 0 - 0.6170 → 226.8 + 0 - 0.6170 → 226.18300305175782
Result = 226.18300305175782 (double)

Program: Verifying the worked expression result in Java.

public class ExprDemo {
    public static void main(String[] args) {
        byte b = 40;
        char c = 'a';
        int i = 50;
        float f = 5.67f;
        double d = 0.1234;
        double result = (f * b) + (i / c) - (d * 5);
        System.out.println("Result = " + result);
    }
}
Result = 226.18300305175782

Type Conversion vs. Type Casting — both change a value from one data type to another, but differ in who does the work:

Type conversion is automatic and done by the compiler when the source and target types are compatible; type casting is manual and done by the programmer with the cast operator, typically to force a larger/incompatible type into a smaller one.

1.7 Selection Statements (if, if-else, switch)

Selection statements branch code execution based on conditional true/false decisions or value matching. (conditional decision ke hisaab se rasta chuno)

Definition: Selection statements (decision-making statements) allow a program to choose between different execution paths based on the boolean result of a condition or discrete value match.
  • if statement: Executes block only if condition evaluates to true.
  • if-else statement: Executes if block when true, else block when false.
  • else-if ladder: Tests multiple conditions sequentially until one evaluates to true.
  • switch statement: Multi-way branch comparing an integer/char/String expression against multiple case values. Requires break to prevent fall-through.

Program: Selection using if-else and switch statements.

public class SelectionDemo {
    public static void main(String[] args) {
        int number = 15;
        if (number % 2 == 0) {
            System.out.println(number + " is Even");
        } else {
            System.out.println(number + " is Odd");
        }
        int day = 2;
        switch (day) {
            case 1: System.out.println("Monday"); break;
            case 2: System.out.println("Tuesday"); break;
            default: System.out.println("Other day");
        }
    }
}

Tuesday

1.8 Iteration & Jump Statements (for, while, do-while, break, continue)

Looping statements repeat a block of code until a specified condition becomes false. (jab tak condition true hai, tab tak chalao)

Definition: Iteration statements (loops) repeatedly execute a statement block as long as a loop termination condition remains true.
  • for loop: Entry-controlled loop ideal when the number of iterations is known in advance (initialization; condition; update).
  • while loop: Entry-controlled loop that tests condition before executing the loop body.
  • do-while loop: Exit-controlled loop that executes the body at least once before testing condition.
  • Enhanced for loop (for-each): Simplifies traversing collections and arrays without manual index tracking. Syntax: for (Type var : array) { ... }.
  • Labeled for loop: A label: placed before a loop lets a break or continue inside a NESTED loop target the labelled (usually outer) loop directly, instead of only the innermost one. Syntax: label: for (init; cond; update) { ... }.
  • break: Immediately terminates the innermost loop or switch block.
  • continue: Skips the rest of the current iteration and jumps to the next loop evaluation step.

public class LoopDemo {

        for (int i = 1; i <= 5; i++) {
            if (i == 4) continue; // Skip i=4

        }
        System.out.println("Sum = " + sum);
        int count = 1;
        do {
            System.out.print(count + " ");
            count++;
        } while (count <= 3);
        System.out.println();
    }
}

1.9 Arrays (1D, 2D, and Jagged Arrays)

An array organizes multiple data items of the same type under a single variable name indexed sequentially. (ek naam ke andar multiple elements rakhna)

Definition: An array is a fixed-size, contiguous indexed collection of homogeneous elements stored in contiguous heap memory.
  • 1D Array: Single row of elements accessed by index arr[i] (0 to length-1).
  • 2D Array: Array of 1D arrays forming a matrix/table of rows and columns accessed as arr[r][c].
  • Jagged Array: Multi-dimensional array in which sub-arrays have different lengths.
  • Declaration only creates a reference, no memory for elements yet: int marks[]; (or int[] marks;).
  • Creation uses new to allocate memory on the heap for the given size: marks = new int[6];. Every element is auto-initialised to the type's default value (0 for int, false for boolean, null for object types) until assigned.
  • Declaration + creation together: int marks[] = new int[6];
  • Declaration + initialization (size is inferred from the value list, new int[] is implicit): int marks[] = {60, 58, 70, 80, 78, 89};
  • 2D array creation: int marks[][] = new int[3][6]; allocates 3 rows of 6 columns each; or with an initializer int marks[][] = {{...}, {...}, {...}};.
AdvantageWhy
Code optimizationOne variable holds many values; data is easy to retrieve and sort.
Random accessAny element can be read directly by its index, in O(1) time.

Disadvantage - Size limit: an array is fixed-size and cannot grow at runtime; when the size must change, the Collection framework (e.g. ArrayList) is used instead.

2.1 Classes and objects

A class is the plan of a house; an object is the actual house built from that plan. (class = naksha, object = asli ghar)

Definition: A class is a user-defined blueprint that groups data (fields) and behaviour (methods) under one name. An object is an instance of a class: a real entity created in memory with the new keyword, having its own state (field values) and sharing the class's behaviour.
  • Members of a class: fields (variables that store state) and methods (functions that act on the state). Constructors and blocks also live inside a class.
  • State + behaviour + identity: every object has field values (state), methods (behaviour) and its own memory location (identity).
  • A class takes no memory for fields until an object is created; each object gets its own copy of instance variables.
  • new does three things: allocates memory on the heap, runs the constructor, returns the reference. (new = memory + constructor + address)
  • The dot operator (s1.name, s1.show()) reaches a member through a reference.
  • A class body can hold six kinds of members: data members, methods, constructors, blocks, nested classes and interfaces. General shape: class ClassName { // fields // methods }; an object is then declared as ClassName obj = new ClassName();.
  • Student s1; only makes a reference (value null). s1 = new Student(); makes the object.
  • Student s3 = s1; copies the reference, not the object: both names now point to one object (see output line 3 below).
  • Unreferenced objects are later removed by the garbage collector; Java has no delete.

2.4 Polymorphism: overloading and overriding

One word, many forms: "pay" works differently for UPI, card and cash, but you just say pay. (ek naam, kai roop)

Definition: Polymorphism is the ability of one method name (or reference) to take many forms. In Java it is of two kinds: compile-time polymorphism, achieved by method overloading, and run-time polymorphism, achieved by method overriding with dynamic method dispatch.

(a) Compile-time polymorphism: method overloading

  • Overloading: same method name, different parameter list (number, type or order) in the same class.
  • The compiler picks the version by matching the arguments, so it is decided before the program runs.
  • Return type alone cannot overload: int f() and double f() is an error.
  • Java does not allow user-defined operator overloading (only built-in + joins strings).
class Calculator {
    int add(int a, int b) {              // 2 int parameters
        return a + b;
    }
    int add(int a, int b, int c) {       // different NUMBER of parameters
        return a + b + c;
    }
    double add(double a, double b) {     // different TYPE of parameters
        return a + b;
    }
}

public class OverloadDemo {
    public static void main(String[] args) {
        Calculator c = new Calculator();
        System.out.println(c.add(2, 3));       // compiler picks add(int,int)
        System.out.println(c.add(2, 3, 4));    // picks add(int,int,int)
        System.out.println(c.add(2.5, 1.5));   // picks add(double,double)
    }
}

(b) Run-time polymorphism: method overriding and dynamic method dispatch

  • Overriding: child class gives its own body for a method with the same signature as the parent's.
  • Dynamic method dispatch: a parent-type reference can hold a child object (Payment p = new UpiPayment();); the JVM calls the method of the actual object at run time, not of the reference type.
  • @Override annotation asks the compiler to check that a method really overrides.
class Payment {
    void pay(int amt) { System.out.println("Paying Rs." + amt); }
}

class UpiPayment extends Payment {
    @Override
    void pay(int amt) { System.out.println("Paying Rs." + amt + " by UPI"); }
}

class CardPayment extends Payment {
    @Override
    void pay(int amt) { System.out.println("Paying Rs." + amt + " by card"); }
}

public class DispatchDemo {
    public static void main(String[] args) {
        Payment p;                   // parent-type reference
        p = new UpiPayment();
        p.pay(200);                  // decided at RUN time: UpiPayment's pay
        p = new CardPayment();
        p.pay(500);                  // same call, now CardPayment's pay
        p = new Payment();
        p.pay(50);

  • Same name and same parameter list as the parent method.
  • Return type same, or a subclass of it (covariant return).
  • Access cannot be more restrictive (a public method cannot become private).
  • final, static and private methods cannot be overridden (a static method with the same signature only hides the parent's).
  • Needs inheritance (IS-A); constructors cannot be overridden.

2.5 Static binding and dynamic binding

Binding is just: which body gets wired up to a method call. Decide it while reading the code (compiler), or decide it while the program is actually running (JVM)? (binding = call ko uske body se jodna)

Definition: Binding is the process of connecting a method call to its actual body (method definition). Static binding (early binding) happens at compile time and is used for overloaded methods; dynamic binding (late binding) happens at run time and is used for overridden methods.
  • Static binding is done by the compiler: when several overloaded methods share a name, the compiler looks at the arguments in the call and wires up the matching method there and then.
  • Dynamic binding is done by the JVM: when a method is overridden, the same call can reach different bodies depending on which object is actually sitting behind the reference; that object exists only at run time, so only the JVM can make this decision.
  • Static binding is also called early binding; dynamic binding is also called late binding.
  • This is the same split as compile-time vs run-time polymorphism (Fig 2.8) seen from the compiler/JVM's point of view instead of the programmer's.

1. Static binding — resolved by the compiler, for overloaded methods:

public class Animal {
    void eat() {                       // method without arguments
        System.out.println("animal is eating");
    }
    void eat(String food) {            // overloaded: method with a String argument
        System.out.println("dog is eating... " + food);
    }
    public static void main(String[] args) {
        Animal a = new Animal();
        a.eat();                        // compiler binds this to eat() at compile time
        a.eat("Biscuits");               // compiler binds this to eat(String) at compile time
    }
}

  • Both calls are wired up while javac reads the source: the number and type of arguments in a.eat() and a.eat("Biscuits") are enough to pick a method, with no need to know what a points to at run time.

2. Dynamic binding — resolved by the JVM, for overridden methods:

2.6 Abstract class and abstract methods

"Every shape has an area" is true, but you cannot compute the area of just "a shape"; each real shape must say how. (adhoora class, bacche poora karein)

Definition: An abstract class is a class declared with the abstract keyword that cannot be instantiated and may contain abstract methods. An abstract method is a method declared without a body (abstract double area();) that every concrete subclass must override.
  • Abstraction (the general idea) means hiding implementation detail and showing only functionality — sending an SMS or paying by UPI, you just type and send; the delivery mechanics stay hidden. (andar kya ho raha hai, dekhne ki zarurat nahi) An abstract class is one of Java's two tools for achieving it (the other is the interface, next topic).
  • Cannot create an object: new Figure() is a compile error, but a reference Figure f = new Rect(4, 5); is allowed.
  • Can have both abstract and concrete methods, fields, a constructor, and even a main() method. (kuch ready, kuch baaki)
  • If a class has even one abstract method, the class must be declared abstract.
  • A subclass must override all abstract methods, or itself be declared abstract.
  • An abstract class with zero abstract methods is legal too (unusual, but the compiler does not complain) — though the whole point of declaring one is usually to hold at least one abstract method.
  • Gives partial abstraction (0 to 100 percent) and a common base for run-time polymorphism.
  • abstract cannot combine with final, static or private on a method.
abstract class Figure {
    String name;
    Figure(String n) { name = n; }       // abstract class CAN have a constructor
    abstract double area();              // no body: child must override it
    void print() { System.out.println(name + " area = " + area()); }  // concrete
}
class Rect extends Figure {
    double l, b;
    Rect(double l, double b) { super("Rectangle"); this.l = l; this.b = b; }
    double area() { return l * b; }
}
class Round extends Figure {
    double r;
    Round(double r) { super("Circle"); this.r = r; }
    double area() { return 3.14 * r * r; }
}

public class AbstractDemo {
    public static void main(String[] args) {
        // Figure f = new Figure("x");   error: Figure is abstract
        Figure f1 = new Rect(4, 5);   f1.print();
        Figure f2 = new Round(2);     f2.print();
    }
}

2.7 Interface and multiple inheritance

An interface is a contract, like a phone charging port standard: any company's phone that implements it must provide those pins. (interface = wada, class ko nibhana padega)

Definition: An interface is a reference type declared with the interface keyword that contains abstract methods (and constants) specifying what a class must do. A class uses implements to accept the contract and must provide bodies for all its abstract methods. A class can implement many interfaces, which is how Java achieves multiple inheritance.
  • Methods are public abstract by default; variables are public static final (constants).
  • No constructors, no object creation: new Camera() is an error.
  • Implementing methods must be declared public in the class.
  • Java 8 added default methods (with a body, e.g. volume()) and static methods in interfaces; Java 9 added private methods.
  • Multiple inheritance: class Smartphone implements Camera, MusicPlayer (Fig 2.16). A class can extend one class and implement many interfaces together: class A extends B implements X, Y.
  • An interface extends other interfaces, not implements them, and — unlike a class — it may extend more than one interface at a time.
  • A field inside an interface must be initialised at the point of declaration, since it is implicitly final and can never be assigned later: int MAX = 100;
  • If a class implements an interface but leaves even one abstract method without a body, that class itself must be declared abstract — the same rule that governs abstract classes (2.6).

Creating a user-defined package

  • Write package name; as the first statement of the source file.
  • Package name = folder name; college.exam means folder college/exam. Use lowercase.
  • Compile with javac -d . File.java: -d tells javac where to put the class file and it creates the package folder automatically (. = current folder). The syntax is really javac -d <directory> <file>, so -d can equally name any other path, e.g. javac -d d:/madhu File.java.
  • Classes used from outside the package must be public.

Step 1: file project/Greet.java, the package member:

package mypack;                       // must be the first statement

    public void hello(String name) {
        System.out.println("Hello " + name);
    }
}

Step 2: file project/UsePack.java, a class outside the package that imports it:

import mypack.Greet;                  // single-type import (or: import mypack.*;)

public class UsePack {
    public static void main(String[] args) {
        Greet g = new Greet();
        g.hello("Riya");
    }
}

Q1. Difference between method overloading and method overriding, with a suitable example

Method overloading: Defining two or more methods with the same name but different parameter lists (number, type or order of parameters) in the same class. The call is decided at compile time, so it is compile-time (static) polymorphism.
Method overriding: A child class redefines a method of its parent class with the same name, same parameters and same return type. The method that runs is decided at run time by the actual object, so it is run-time (dynamic) polymorphism.

Q2. Explain abstract class and interface in Java

Abstract class: A class declared with the abstract keyword that cannot be instantiated. It can have abstract methods (no body) and concrete methods (with body), variables and constructors. A subclass must override all abstract methods or itself be abstract.
Interface: A reference type declared with the interface keyword that defines a contract: methods are public and abstract by default and variables are public static final (constants). A class uses implements to provide the bodies. One class can implement many interfaces, which is how Java achieves multiple inheritance.

Rules of an abstract class

  • Declared with abstract; an abstract method has no body and ends with ;.
  • Cannot create objects: new Account() is a compile error, but a reference Account a is allowed.
  • Can have constructors (called through super()), instance variables, static and final methods.
  • If a class has even one abstract method, the class must be abstract.
  • Gives partial abstraction (0 to 100%).

Rules of an interface

  • Methods are public abstract by default; variables are public static final.
  • No constructors, cannot be instantiated.
  • A class implements an interface and must give bodies to all its methods (declared public).
  • An interface can extend other interfaces; a class can implement many interfaces.
  • From Java 8, interfaces can also have default and static methods with bodies.

Q3 (a). Short note: Array of objects

Definition: An array of objects is an array whose elements are references to objects of a class. The array stores references, not the objects themselves; each object must be created separately with new.
  • Syntax: ClassName[] arr = new ClassName[size];
  • Step 1: creating the array only creates size references, all null.
  • Step 2: create each object: arr[0] = new ClassName(...);
  • Step 3: access members through the index: arr[i].member.
  • Diagram: see Fig 2.4 (array cells holding arrows to separate objects).
  • Use: storing records of many students, employees or products and processing them in a loop.
class Student {
    String name;
    int marks;
    Student(String name, int marks) {
        this.name = name;
        this.marks = marks;
    }
}

public class StudentArray {

        list[2] = new Student("Kabir", 65);

        }
    }
}

Q3 (b). Short note: Class and objects

Class: A user-defined blueprint (template) that describes the data members (state) and methods (behaviour) common to all its objects. A class takes no memory for data until objects are created.

  • Syntax of a class: class ClassName { data members; methods; }
  • Creating an object, three steps in Car c1 = new Car();: declaration (Car c1), instantiation (new allocates memory), initialization (the constructor Car() runs).
  • Members are accessed with the dot operator: c1.brand, c1.display().

Q4. Short note: Packages (also in the syllabus)

Definition: A package is a group of related classes and interfaces stored together in one folder, declared with the package keyword. It works like a folder in a computer.
  • Types: built-in (java.lang, java.util, java.io) and user-defined. Diagram: Fig 2.19.
  • Advantages: avoids name conflicts, groups related classes, provides access protection, makes code reusable and easy to find.
  • package statement must be the first statement of the file.
  • Compile with javac -d . Calculator.java; -d . creates the folder mypack (see Fig 2.21).
  • Import: import mypack.Calculator; (one class), import mypack.*; (all public classes), or the fully qualified name mypack.Calculator.
  • java.lang is imported automatically.
  • Access protection across packages: only public members are visible to other packages; protected is visible to subclasses in other packages; default (no modifier) stays inside its own package.

2.10 Short answers (1 mark)

Q1. Define class and object.
A class is a user-defined blueprint containing fields and methods. An object is an instance of a class created with new, having its own state and memory on the heap.
Q2. What is an array of objects?
An array whose elements are references to objects of one class, e.g. Book[] b = new Book[3];. Each object must be created separately with new, otherwise the element is null.
Q3. Why does Java not support multiple inheritance with classes?
To avoid the diamond problem: if two parents have the same method, the child's call becomes ambiguous. Multiple inheritance is achieved through interfaces.
Q4. Differentiate overloading and overriding.
Overloading: same name, different parameters, same class, compile-time. Overriding: same signature in child class, needs inheritance, run-time (dynamic dispatch).
Q5. What is dynamic method dispatch?
The mechanism by which a call to an overridden method through a parent-class reference is resolved at run time according to the actual object type.
Q6. What is an abstract class?
A class declared abstract that cannot be instantiated; it can have abstract (bodyless) methods, concrete methods and constructors. Subclasses must override the abstract methods.
Q7. Define interface.
A reference type with public abstract methods and public static final constants; a class uses implements to provide the bodies and may implement several interfaces.
Q8. What is a package? Name two built-in packages.
A named group of related classes and interfaces giving a namespace and access control. Examples: java.lang, java.util.
