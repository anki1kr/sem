Q1. What is Big Data? Discuss in detail.

Unit I · 8 marks · examiner wants the definition, why an ordinary RDBMS fails at this scale, the evolution, and a quick advantages/disadvantages sweep.

Definition: Big data refers to data sets whose volume, velocity and variety exceed the capacity of traditional database systems to capture, store, manage and analyse them, and which therefore need new, distributed, cost-effective forms of processing to extract insight and support decisions.
  • Evolution (Fig 1.1):
    • Flat files (1960s) — no query language.
    • RDBMS (Codd, 1970) — tables, SQL, fixed schema.
    • Data warehouses (1990s) — historical data for reporting.
    • Web-scale data — search/social outgrow one server; Google GFS/MapReduce answer it.
    • Hadoop (2006, open source) → NoSQL, Spark, cloud, data lakes.
  • Why RDBMS fails at this scale:
    • Scale-up only — cost/hardware ceiling on one server.
    • Fixed schema — can't hold JSON/logs/video without redesign.
    • Speed — row-by-row inserts can't match continuous streams.
    • Cost — licensed DB + high-end storage.
    • Single point of failure — one machine holds the data.
  • Big data approach: many cheap commodity machines; computation moves to data (data locality); raw first, structure later (schema-on-read).
  • Advantages (D-C-F-P-S-A): Decisions, Cost cut, Fraud detection, Productivity, Service, Agility.
  • Disadvantages (T-S-C): Talent shortage, Security risk, Compliance burden.
PointTraditional dataBig data
SizeGigabytes to a few terabytesTerabytes to petabytes and beyond
StructureMostly structured (tables)Structured + semi-structured + unstructured
SchemaSchema-on-write, fixedOften schema-on-read, flexible
ArchitectureCentralised, scale-upDistributed, scale-out
Mnemonic Advantages D-C-F-P-S-A: Decisions, Cost, Fraud, Productivity, Service, Agility. Disadvantages T-S-C: Talent, Security, Compliance.
Common mistake: "Big data" is not only about size — a small but very fast stream, or data in many mixed formats, is also a big-data problem.

  • Languages: Hadoop core = Java; Streaming API → Python jobs; Pipes → native C++.

Q5. Explain Hadoop architecture (HDFS, MapReduce and YARN) with a diagram.

Unit I · 8 marks · examiner wants the four core modules, then one paragraph each on HDFS storage, MapReduce processing and YARN resource management.

Definition: Apache Hadoop is an open-source Java-based framework for distributed storage and processing of very large data sets across clusters of commodity hardware, built from four core modules: Hadoop Common, HDFS, YARN and MapReduce.
  • HDFS (storage): master–slave. NameNode = metadata only (namespace, block map); DataNodes = actual blocks (128 MB default), send heartbeats. Blocks replicated 3×, rack-aware, for fault tolerance.
  • MapReduce (processing) – 3 phases:
    • Map — record → (key, value) pairs.
    • Shuffle/sort — groups pairs by key.
    • Reduce — aggregates values per key, writes to HDFS.
    • Classic example: word count.
  • YARN (resources) – Hadoop 2, separates resource mgmt from processing:
    • ResourceManager (Scheduler + ApplicationsManager) — per-cluster master.
    • NodeManager — on every worker node.
    • ApplicationMaster — one per job, negotiates resources.
    • Containers — CPU+memory bundles running tasks.
  • Fit together: DataNode + NodeManager on same physical nodes → tasks run where data sits — data locality.
  • Key features: scalable (add nodes), fault tolerant (replication + task re-run), cost-effective (commodity HW, open source).
LayerMaster daemonSlave daemon
HDFS (storage)NameNodeDataNode
YARN (resources)ResourceManagerNodeManager
Mnemonic C-H-Y-M = "Chai Hai Yaar, Masala": Common, HDFS, YARN, MapReduce.
If it comes as 4 marks: write the definition, draw Fig 1.11, and cover only HDFS (NameNode/DataNode/replication) + YARN (ResourceManager/NodeManager) — drop the MapReduce phases.
Quick recall Hadoop = Common + HDFS (store) + YARN (resources: RM, NM, AM, Container) + MapReduce (map → shuffle/sort → reduce); worker nodes carry both a DataNode and a NodeManager, giving data locality.

Unit I · 8 marks · examiner wants all 5 Vs defined with one example each, plus the two extra V's some books add.

Definition: The characteristics of big data are commonly summarised as the 5 Vs: Volume, Velocity, Variety, Veracity and Value.

Q7. What is NoSQL? Discuss its advantages and disadvantages.

Unit I · 8 marks · examiner wants a short NoSQL definition, why it exists (scale-out), then a clean advantages-vs-disadvantages table.

Definition: NoSQL ("Not only SQL") databases are non-relational, usually schema-less, distributed databases designed to store structured, semi-structured and unstructured data with horizontal scalability and high availability.
  • Why NoSQL: RDBMS clusters hard to shard; NoSQL scale-out on commodity clusters, flexible schema, avoids app-object/row impedance mismatch.
  • Consistency: usually BASE (eventual), not strict ACID.

Q8. Explain integrating diverse data and the aggregate data model.

Unit I · 8 marks · two-part question — examiner wants ETL/ELT integration in Part A and the NoSQL aggregate concept in Part B.

Part A · Integrating diverse data

Definition: Data integration is combining data from heterogeneous sources (different formats, schemas, systems) into a unified, consistent, usable view for analysis.
  • Challenges: heterogeneous formats (CSV/JSON/XML/images), schema mismatch (cust_id vs customerNo), data quality/veracity, batch+streaming mix, semantic conflicts.
  • Schema mapping: match source field → target field (types, units). Entity resolution: same real-world entity across sources.
  • ETL: transform before load, for warehouses. ELT: load raw first, transform in target, for lakes.
PointETLELT
OrderExtract → Transform → LoadExtract → Load → Transform
SchemaSchema-on-writeSchema-on-read
Best forStructured, traditional DWLarge, diverse, big data
Mnemonic ETL = "Tidy then Load" (warehouse). ELT = "Load then Tidy" (lake).

Part B · Aggregate data model

Definition: An aggregate is a collection of related objects treated as a single unit for storage, retrieval, update and distribution (Sadalage & Fowler, NoSQL Distilled).
  • Links between aggregates: references by id, not nested copies.
  • Aggregate-oriented: key-value, document, column-family. Aggregate-ignorant: relational, graph.
  • Consequence: atomic updates within one aggregate; aggregate = unit of sharding/replication (one node per read).
PointAggregate-orientedAggregate-ignorant
ExamplesKey-value, document, column-familyRelational, graph
TransactionsAtomic within one aggregateACID across many rows/nodes
If it comes as 4 marks: write ONLY the part named in the question. If unnamed, write Part A (integration + ETL/ELT) with Fig 1.9 and its table — it is the more commonly asked half.
Quick recall Integration = combine heterogeneous data via ETL (warehouse) or ELT (lake). Aggregate = related objects handled as one unit; key-value/document/column-family are aggregate-oriented, relational/graph are aggregate-ignorant.

Q10. Explain the complete Data Science process with an example.

Unit II · 8 marks · examiner wants all five steps explained in order, with the iterative loop and one worked example.

Definition: The data science process is an iterative sequence of five steps: Acquire, Prepare (explore + pre-process), Analyze, Report, and Act.

    6. Deployment

Q11. What is Big Data Modeling and Management? Explain its six concerns.

Unit II · 8 marks · examiner wants the data-model definition (structure/operations/constraints) plus all six management concerns, one line each.

Definition: Big data management is the set of activities and systems for ingesting, storing, ensuring quality of, operating on, scaling and securing very large and varied data so it stays usable. A data model describes data by structure, operations and constraints.
  • Ingestion: data in, batch (periodic) or streaming (continuous), under an ingestion/error policy (Kafka, Sqoop).
  • Storage: memory hierarchy (cache → RAM → SSD → HDD → tape); models (HDFS, NoSQL, warehouse vs lake).
  • Quality: accurate/complete/consistent — clean missing, invalid, duplicate, inconsistent values (MIDIO), outliers.
  • Operations: selection, projection, join, union, aggregation — run in parallel at scale.
  • Scalability: scale up (bigger machine) or scale out (more commodity machines; partition + replicate).
  • Security: access control, encryption (rest + transit), privacy/anonymisation, auditing — protects CIA triad (Confidentiality, Integrity, Availability).
Mnemonic "I Saw Queen Oprah Speak Secretly" = Ingestion, Storage, Quality, Operations, Scalability, Security. Data model = SOC: Structure, Operations, Constraints.
If it comes as 4 marks: write the definition, draw Fig 2.11, and explain only Ingestion and Storage (the two most-asked concerns) in one line each.
Quick recall Six concerns I-S-Q-O-S-S; data model = structure + operations + constraints; each concern gets its own deeper treatment (ingestion, storage, security etc.) in the full notes.

Assume 5,000,000 events/day (page views, app events, orders, posts), average 2 KB each

Q13. Explain a real-world Data Science example using advanced techniques.

Unit II · 8 marks · examiner wants a recommendation system walked through the 5-step process, plus the named advanced techniques and one worked similarity example.

Definition: A recommendation system is a data science application that predicts which items (movies, products, songs) a user is likely to prefer, using the user's past behaviour and the behaviour of similar users.
  • Well-known fact: Netflix Prize (2006-2009) — US$1M for 10% ratings-accuracy gain; winners used matrix factorisation + model ensembles.
  • Similar systems: Amazon suggestions, YouTube, Spotify playlists.
TechniqueWhat it does
Collaborative filteringRecommends what similar users liked
Matrix factorisationBreaks the sparse user × item matrix into hidden taste factors
Content-based filteringUses item features (genre, cast) to find similar shows
Deep learningNeural networks learn patterns from long viewing sequences
A/B testingShows two versions to two user groups, keeps the better one
Worked example: user-based collaborative filtering (computed in Python) · ratings for 5 shows, 0 = not watched
A = (5, 4, 0, 1, 5), B = (4, 5, 0, 1, 4), C = (1, 0, 5, 4, 1)
Cosine similarity = (A·B) / (|A| × |B|)
A·B = 61; |A| = 8.185; |B| = 7.616 ⇒ sim(A,B) = 61/(8.185×7.616) = 0.979

1-mark questions

Q1. Define big data.
Data sets whose volume, velocity and variety exceed traditional database capacity, needing distributed, cost-effective processing.
Q2. List the 5 Vs of big data.
Volume, Velocity, Variety, Veracity, Value (some books add Variability and Visualization).
Q3. Differentiate structured and unstructured data.
Structured has a fixed schema in rows/columns (SQL tables); unstructured has no model and needs special analysis (images, video, text).
Q4. Name three sources of big data.
Human-generated (social media), machine-generated (IoT sensors, logs), organisational (transactions, ERP/CRM).
Q5. Expand ETL and ELT.
ETL = Extract, Transform, Load (transform before loading, for warehouses). ELT = Extract, Load, Transform (raw first, for data lakes).
Q6. Differentiate data lake and data warehouse.
A warehouse holds processed, structured data (schema-on-write); a lake holds raw data of all types (schema-on-read).
Q7. What is Hadoop?
An open-source Apache framework for distributed storage (HDFS) and processing (MapReduce, YARN for resources) on commodity clusters.
Q8. What is the role of the NameNode?
HDFS master; stores metadata (namespace, block map, locations) but not actual data.
Q9. Default HDFS block size and replication factor?
128 MB block size (Hadoop 2.x/3.x) and replication factor 3, both configurable.
Q10. Expand YARN and name its components.
Yet Another Resource Negotiator. Components: ResourceManager, NodeManager, ApplicationMaster, Container.
Q11. Expand NoSQL and list its four types.
"Not only SQL". Types: key-value (Redis), document (MongoDB), column-family (Cassandra, HBase), graph (Neo4j).
Q12. State the CAP theorem.
A distributed store cannot guarantee Consistency, Availability and Partition tolerance together; during a partition it must give up C or A.
Q13. Define data science.
Using data with statistics, computing and domain knowledge to produce insights that lead to actions and value.
Q14. List the five P's of data science.
Purpose, People, Process, Platforms, Programmability.
Q15. List the steps of the data science process.
Acquire, Prepare, Analyze, Report, Act — iterative.
Q16. Define data ingestion.
Getting data from its sources into the data system, in batches or as a stream, under an ingestion policy.
Q17. Differentiate batch and streaming ingestion.
Batch loads large chunks periodically (high latency); streaming loads records continuously (low latency).
Q18. Differentiate selection and projection.
Selection picks rows satisfying a condition; projection picks chosen columns of each row.
Q19. Differentiate scale up and scale out.
Scale up = a more powerful single machine (hardware ceiling); scale out = more commodity machines (partition + replicate).
Q20. List data security measures.
Access control, encryption at rest and in transit, privacy/masking, auditing.
Q21. What is a big data management plan?
A design stating how data is ingested, stored, kept at quality, operated on, scaled and secured for an organisation.
Q22. What is collaborative filtering?
A recommendation technique suggesting items liked by users with similar behaviour (e.g. by cosine similarity).
Q23. What is A/B testing?
Showing two versions to two random user groups and keeping the one that performs better on a chosen metric.
Q24. What is the CIA triad in data security?
Confidentiality, Integrity, Availability — the three goals every security control protects.
