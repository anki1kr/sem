1.1 What is Data Science? Part-A repeat

Definition Data Science is a multi-disciplinary field that combines statistics/mathematics, computer science (programming & algorithms), and domain expertise to extract actionable insight from raw data through a pipeline of collection → cleaning → analysis → visualisation → decision.
Why it matters DS is the umbrella that uses statistics + computing + domain together — alone, none of the three solve real-world problems. A pure statistician without code can't process big data; a pure programmer without stats can't tell signal from noise; a pure domain expert without either can't quantify a hunch. The whole point of "data science" as a label is to insist on all three at once.

(1) Netflix recs — collaborative filtering · (2) UPI fraud detection — anomaly detection · (3) ECG heart-attack prediction — classification

1.2b Meaning of Variables Part-A repeat

Definition A variable is a measurable characteristic or attribute that varies across observations (units, people, rows). It "varies" — if every unit had the same value it would be a constant, not a variable. In a dataset, every column is a variable and every row is an observation.
  • By value type — Continuous: any value in a range, infinitely divisible (height, weight, temperature, time). Discrete: countable whole values only (number of children, defects, dice roll).
  • By measurement (categorical) — Nominal: named categories with no order (colour, gender, blood group). Ordinal: categories with a natural rank but unequal gaps (grade A/B/C, satisfaction Low/Med/High).
  • By role in a model — Independent (X): the input / predictor / cause, controlled or observed. Dependent (y): the output / response, whose value depends on X. Example: y = exam-score depends on X = hours-studied.
Plain English A variable is just "the thing you're recording that can be different for each person". Continuous = you measure it on a ruler (can be 1.71 m). Discrete = you count it (2 cars, never 2.3). Nominal = names with no winner (red vs blue). Ordinal = names that line up (Gold > Silver > Bronze). X is what you change, y is what you watch happen.
R link — how is a variable stored? (1.5M Part-A)
In a data.frame, each column IS a variable. Build one and read off its columns: 
df <- data.frame(
  hours = c(2, 4, 6),   # numeric (continuous) → X
  grade = c("C","B","A"),  # categorical (ordinal)
  score = c(50, 65, 82))   # numeric → y
str(df)   # shows each variable's type
Here hours and score are numeric variables, grade is a categorical (factor) variable; hours is the independent X and score the dependent y.

1.3b Wholeness of Data Analytics 5M dropper

Definition The wholeness of data analytics is the idea that analytics is a single connected maturity ladder of four climbing types — each answers a harder business question and adds more value than the one below it. The standard order is Descriptive → Diagnostic → Predictive → Prescriptive; you cannot trust the higher rungs until the lower ones are solid.

Exam hook Examiner loves "explain the four types of analytics" as a 5M Part-B short. Draw the ladder, give one R verb + one company example per rung, and state the punch-line: value and difficulty rise together, and each rung depends on the one below. summary() = descriptive, cor() = diagnostic, lm()/predict() = predictive, optim()/rules = prescriptive.

1.5 Paths to Data Science

  • Statistician → DS: strong inference, weaker on engineering — pick up SQL + Python/R.
  • Programmer → DS: strong on engineering — learn distributions, hypothesis testing.
  • Domain expert → DS: deep context — learn statistics + a tool.
  • Business analyst → DS: dashboards + storytelling — graduate to predictive modelling.
    • What each path brings + what it lacks Every route into DS starts with one strong leg — the work is building the other two.
    • Statistician path: deep probability + inference but often weak on large-scale data engineering — priority add-on: SQL, Python/R pipelines, version control (git).
    • Software engineer path: strong on algorithms + scalable code but may skip statistical rigour — priority add-on: hypothesis testing, distributions, model evaluation metrics (RMSE, F1).
    • Domain expert path (doctor, banker, economist): irreplaceable contextual knowledge that prevents nonsense models — priority add-on: one tool end-to-end (R or Python) and basic probability.
    • Business analyst path: storytelling + dashboards but descriptive only — priority add-on: predictive modelling (lm(), decision trees) so answers shift from "what happened" to "what will happen".
    • Practical tip: pick one role first (data analyst → ML engineer → data scientist) rather than trying to master everything at once — domain-specific skills compound faster than generic breadth.
    Exam hook "Explain the paths to data science" is a 5M Part-B pattern. Answer = four backgrounds + what each adds + what each must learn. Conclude: DS is a T-shaped skillset — one deep pillar + broad awareness of the other two.

1.6 Data Mining

Definition The process of discovering patterns, correlations and anomalies in large data sets using statistics, machine learning and database systems.

Tasks (CCRAS): Classification (spam/ham) · Clustering (customer segments) · Regression (sales forecast) · Association rules (market basket) · Sequential patterns (clickstream).

Why it matters The "analysis" stage of the DS pipeline is literally data mining. Senior profs separate the two: data science is the umbrella; data mining is one component (pattern discovery).
Data Mining — deeper definition & task types Data mining is the automatic extraction of previously unknown, valid, and actionable patterns from large datasets. It sits at the intersection of statistics, machine learning, and database systems.
  • Classification: assign items to predefined classes — e.g. spam/not-spam email, fraud/legitimate transaction. Algorithm learns a boundary from labelled training data.
  • Clustering: group similar items with no predefined labels — e.g. Flipkart segments customers into "bargain hunters", "premium buyers", "impulse buyers" without a teacher.
  • Regression: predict a continuous numeric value — e.g. forecasting tomorrow's electricity demand based on temperature and day-of-week.
  • Association rule mining: find "if X then Y" co-occurrence rules — classic example: supermarket basket analysis ("customers who buy bread also buy butter 73% of the time").
  • Anomaly / outlier detection: flag unusual data points — UPI/credit-card fraud detection flags a ₹2 lakh transaction when the card's usual spend is ₹500.
Data mining vs machine learning — the distinction examiners test Data mining = the goal (find hidden patterns in stored data). Machine learning = one of the tools used to achieve that goal. You can also mine data with pure SQL aggregations or statistics — ML is just the most powerful hammer. Exam answer: "ML is a subset of techniques used in data mining, not a synonym."

Plain English Database = filing cabinet your shopkeeper uses for today's bills — every sale, every receipt, fast to update. Data Warehouse = a giant warehouse of every old bill your shop has ever issued, organised so analysts can ask "how did sales change over 5 years?" without slowing the cash counter.
What exactly IS a data warehouse? (Inmon's 4 properties + schema)
Definition · Data Warehouse

A Data Warehouse is a subject-oriented, integrated, time-variant, non-volatile collection of data built to support management decision-making (the four properties from W. H. Inmon, the "father of the data warehouse").

  • Subject-oriented — organised around business subjects (Sales, Customer, Product), not around an application's day-to-day process.
  • Integrated — data from many source DBs is cleaned and conformed to one consistent format (same units, codes, naming) during ETL.
  • Time-variant — stores a long history with a time dimension, so trends across years can be analysed (an OLTP DB keeps only the current value).
  • Non-volatile — data is loaded then read; it is not updated or deleted in place, so analytical results stay reproducible.
SITN — Subject-oriented · Integrated · Time-variant · Non-volatile (Inmon's 4)

A warehouse uses a dimensional schema:

  • One central fact table — holds numeric, additive measures (e.g. units_sold, revenue) + foreign keys
  • Surrounded by dimension tables — descriptive context: who (Customer), what (Product), where (Store), when (Date)
Star vs Snowflake in one line Star schema keeps each dimension as a single flat (denormalised) table — fewer joins, faster reads, slight redundancy. Snowflake schema normalises a dimension into sub-dimensions (Product → Category → Department) — saves space, but more joins slow queries. Warehouses usually prefer star for analytical speed.

1.8 Advice for New Data Scientists

  1. Statistics first — without inference, you're just plotting.
  2. Master one language end-to-end (R or Python) before sampling others.
  3. Build domain knowledge — DS without context produces meaningless models.
  4. Communicate — a one-line takeaway beats a 30-page report.
  5. Work on messy data — Kaggle-clean ≠ industry. Practice ETL.
  6. Version everything — code (git), data (DVC), models (MLflow).
    7. Expanded advice — what the teacher's notes add These are the career-survival tips that separate working data scientists from Kaggle hobbyists.
    • Choose your first role deliberately — data analyst → ML engineer → data scientist is a proven ramp. Don't try to be all three at once; depth in one role beats shallow breadth across all.
    • Learn SQL before fancy ML — 80% of real DS work is querying and wrangling data in databases. A data scientist who can't write a JOIN is unemployable in most companies, regardless of their neural-network knowledge.
    • Focus on practical applications, not just theory — work on open datasets (Kaggle, data.gov.in, RBI open data) and replicate published results. You understand lm() much better after fitting a real housing-price model than after reading its formula.
    • Build in public — a GitHub profile with 3–5 complete projects is worth more than any certification. Recruiters check repos, not résumé bullet-points.
    • Develop communication skills — the output of DS is a decision, not a model. If you can't explain your findings in one sentence to a non-technical manager, the model has zero business value.
    • Find a mentor — DS is a young field; structured mentorship shortens the path from student to industry-ready by years. Reach out to practitioners on LinkedIn with specific, brief questions.

1.9 Cloud Computing Part-A 2025

Definition On-demand delivery of compute, storage, networking and applications over the internet on a pay-as-you-use basis.

Key feature for DS — elastic on-demand compute:

  • Train a model on 32 cores for 1 hour → pay only for that hour
  • No upfront hardware cost; scale up for experiments, scale down when idle
Five essential characteristics (NIST definition) Cloud computing has five defining characteristics that distinguish it from simply renting a server.
  • On-demand self-service: provision compute or storage yourself through a web portal — no phone call to an admin, no waiting. Example: spin up an AWS EC2 VM in 2 minutes.
  • Broad network access: available over the internet from any device — laptop, phone, tablet. Your R script on Google Colab runs whether you are in Mumbai or Manali.
  • Resource pooling: provider's hardware is shared across many customers (multi-tenancy); each user gets an isolated slice. One physical server may host 20 virtual machines.
  • Rapid elasticity: scale up (more CPU, RAM) during peak load, scale down when idle — automatically. Hotstar scales to millions during IPL, then shrinks after the match.
  • Measured service: usage is metered and billed precisely — pay per GB stored, per CPU-hour consumed. No upfront hardware cost.
Why cloud matters for data science specifically Training a deep-learning model on a laptop takes days; on a cloud GPU cluster it takes hours. Elastic compute lets a student or startup access the same horsepower as a large company without buying hardware. Indian DS teams routinely use AWS SageMaker, Google Colab, or Azure ML to run experiments at scale.
Plain English Renting compute over the internet, like getting electricity from the grid instead of running a generator at home. You pay only for what you use, scale up when you need a big GPU, scale down to almost nothing when idle. No server to buy, no admin to hire.

1.10 AI vs ML vs DS

  • AI — any technique enabling machines to mimic human intelligence (rules, search, learning).
  • ML — subset of AI; algorithms that learn from data without explicit programming.
  • DL — subset of ML using deep neural networks (3+ layers).
  • DS — broader practice that uses ML/AI as tools alongside stats and visualisation to deliver insight.
    • Artificial Intelligence — definition, goals, types AI is the simulation of human intelligence in machines — making a computer reason, learn, and make decisions the way a person does, without being explicitly programmed for every scenario.
    • Goals of AI: replicate human intelligence · solve knowledge-intensive tasks · build systems that learn from experience and improve over time · automate tasks that require perception + action (self-driving car, Aadhaar face-match at airports).
    • Rule-based AI: earliest form — programmer writes explicit if-then rules. Example: a chess program with hardcoded moves. Fast but brittle (breaks on unseen situations).
    • Machine Learning AI: system learns rules from data, not from a programmer. Example: spam filter that learns new spam patterns every week from user feedback.
    • Deep Learning AI: ML with neural networks having 3+ layers — automatically extracts features. Example: Google Translate, voice assistants (Alexa, Siri), medical image diagnosis.
    • Indian examples: Aadhaar biometric verification (face/fingerprint AI), IRCTC chatbot, Zerodha's algo trading, Practo's symptom checker.
    Machine Learning — definition, how it works, types Machine learning is a subset of AI that gives computers the ability to learn from data without being explicitly programmed (Arthur Samuel, 1959).
    • How ML works: feed training data → algorithm finds patterns → builds a model → model predicts on new unseen data. The more data, the better the model.
    • Supervised learning: labelled input-output pairs (X, y) — algorithm learns the mapping f(X)→y. Tasks: classification (spam/ham), regression (house price). Examples: lm(), decision tree, SVM.
    • Unsupervised learning: only X (no labels) — algorithm finds hidden structure. Tasks: clustering (customer segments), dimensionality reduction (PCA). Examples: k-means, hierarchical clustering.
    • Reinforcement learning: agent learns by trial-and-error in an environment, rewarded for good actions. Example: AlphaGo, self-driving car navigation.
    • ML in everyday India: Netflix/Hotstar recommendations · UPI fraud scoring · Swiggy delivery-time estimate · Google Maps traffic prediction — all ML models running on historical data.

2.1 What is R? History & Features

Definition R is an open-source, interpreted, high-level language and environment for statistical computing and graphics. Created by Ross Ihaka & Robert Gentleman at the University of Auckland (1993); current stable maintained by the R Core Team and distributed via CRAN.

Key features:

  • Vectorised operations — built-in element-wise arithmetic (no explicit loop for x + y).
  • 18,000+ packages on CRAN (statistics, ML, viz, bioinformatics).
  • First-class statistics — distributions, hypothesis tests, GLMs built in.
  • Reproducible reports via R Markdown / Quarto (PDF, HTML, Word).
  • Cross-platform & free (GPL-2).

Limitations:

  • Single-threaded by default
  • Slower than C/Python for heavy loops
  • Steeper learning curve for non-statisticians
  • Weaker production-deployment story than Python

  • Inf = "too big to write" (overflow or division by zero).

2.7 Objects & Type Conversions Part-A 2024(e)

R has 6 atomic types — everything is an object:

  • logical — TRUE / FALSE
  • integer — 5L
  • double (numeric) — 3.14
  • complex — 2+3i
  • character — "hello"
  • raw — raw bytes
# inspect type
class(3.14)             # "numeric"
typeof(3.14)            # "double"
class(5L)               # "integer"

# convert type
as.integer("42")        # 42
as.numeric("3.14")      # 3.14
as.character(99)        # "99"
c(TRUE, 2L, 3.5, "x")   # all become character
Coercion rule — the single most-tested trap A vector is homogeneous, so when you c() mixed types together R silently promotes every element up to the most general type present, following the fixed ladder logical → integer → double → complex → character. It never demotes — one string in the mix turns the whole vector into character. 
# Watch each result climb the ladder
c(TRUE, FALSE)        # logical
c(TRUE, 5L)           # integer  -> c(1L, 5L)   (TRUE counts as 1)
c(TRUE, 2.5)          # double   -> c(1.0, 2.5)
c(2L, 4.5)            # double   -> c(2.0, 4.5)
c(3.5, "x")           # character-> c("3.5", "x")

# Explicit coercion can FAIL silently -> NA + warning
as.numeric("hello")   # NA (with a warning) — not an error
as.integer(3.9)       # 3   (truncates toward zero, does NOT round)

a && b           # tests only a[1] & b[1] -> in R >= 4.3 this ERRORS (length > 1)

  • Testing if (x == NA) — always yields NA, never TRUE. Use is.na(x), or isTRUE() to fold an NA condition to FALSE.

The 6 layers in prose — one paragraph each

  • 1 · Data — the data frame fed to ggplot() is the foundation: every layer above derives its values from these columns. One plot can refer to a single data frame or layer-specific overrides. Example: ggplot(data = students) binds the students data frame to the plot.
  • 2 · Aesthetics (aes()) — the mapping from data columns to visual channels (x, y, colour, fill, size, shape, alpha). Aesthetics describe what variable controls what visual, never raw values. Example: aes(x = hours, y = marks, colour = grade) maps three columns to three channels.
  • 3 · Geometries (geom_*) — the visual marks drawn for each row: points, bars, lines, boxplots, polygons. Geometries consume aesthetics and emit shapes; multiple geoms can stack on the same aesthetic mapping. Example: geom_point(size = 3) draws a scatter, geom_bar(stat = "count") draws bars.
  • 4 · Statistics (stat_*) — optional transformations applied before drawing: smoothing, binning, density estimation, summary statistics. Every geom has a default stat (e.g. geom_bar uses stat_count); explicit stats let you overlay fits or summaries. Example: stat_smooth(method = "lm") overlays a linear-regression line with confidence band.
  • 5 · Facets (facet_*) — split the plot into small multiples by one or two categorical variables, so subgroups can be compared side-by-side without overlapping. Replaces base-R's manual par(mfrow=). Example: facet_wrap(~ grade) creates one panel per grade; facet_grid(sex ~ year) builds a 2-D matrix.
  • 6 · Themes (theme_*) — non-data styling: fonts, gridlines, panel background, legend position, axis ticks. Themes never change the data or its mapping, only the presentation. Example: theme_minimal() strips chartjunk for publication; theme(legend.position = "bottom") tweaks one element.

Compose order:

  • Mandatory: Data → Aesthetics → Geometries — these three must always be present
  • Optional: Statistics, Facets, Themes — refinements layered on top
  • Each layer is added with the + operator: ggplot(df, aes(x, y)) + geom_point() + stat_smooth() + facet_wrap(~g) + theme_minimal()
  • Layers are independent objects — swap any one without redrawing the rest
Plain English Base graphics = paint directly on a canvas, one brush stroke at a time — fast and final. ggplot2 = stack transparencies (data layer + mapping layer + shapes layer + theme layer) and combine them with +. Slower to render, but much easier to change later — just swap one layer instead of redrawing.

4.8 Hypothesis Testing ⭐ 2023 Q4a, 2025 Q6a (8–10 M)

Definition Hypothesis testing is a formal statistical procedure to decide between two competing claims about a population parameter using sample data and a chosen significance level α.

The six steps (memorise the order)

  1. State H₀ & H₁ — null (no effect, equality) and alternative (claim to test).
  2. Choose α — significance level, typically 0.05 (5%).
  3. Select test statistic — z, t, χ², F, depending on data.
  4. Compute test stat & p-value from the sample.
  5. Decision rule — reject H₀ if p < α (or |stat| > critical value).
  6. Interpret in context — translate back to the original problem.

Common pitfalls (1) p > α does not prove H₀ — only fails to reject. (2) α is set before looking at data. (3) Don't confuse statistical with practical significance.
Plain English Hypothesis testing = an honest court. H₀ (null) is the "innocent" default — no effect, no difference. The sample is the evidence. If the evidence is strong enough (p-value below α=5%), we reject H₀ ("guilty"); otherwise we acquit ("not enough proof"). We never prove H₀ — we just fail to reject it. Same logic as "innocent until proven guilty".

One-tailed vs two-tailed

  • Two-tailed (default):
    • H₁: parameter is simply different (≠)
    • α split into both tails — 2.5% each at α = 0.05
    • Use when you have no prior direction about which way the effect goes
  • One-tailed:
    • H₁ claims a specific direction (> or <)
    • All of α sits in one tail → more power to detect an effect in that direction
    • R syntax: t.test(x, mu=50, alternative="greater") or "less"

  • Type I (α) — false positive:
    • Rejecting a true null — "convicting the innocent"
    • Controlled directly by the chosen significance level α
  • Type II (β) — false negative:
    • Failing to reject a false null — "acquitting the guilty"

4.9 Correlation 2023 Q4c, 2024 Part-A(d,h), 2025 Part-A(i)

Definition Correlation measures the strength and direction of the linear relationship between two numeric variables. Pearson's r ∈ [−1, +1]:
r = +1 → perfect positive · r = 0 → none · r = −1 → perfect negative.
r = Σ(xᵢ − x̄)(yᵢ − ȳ) / √[ Σ(xᵢ − x̄)² · Σ(yᵢ − ȳ)² ] 
x <- c(1, 2, 3, 4, 5)
y <- c(2, 4, 5, 4, 5)

cor(x, y)                       # 0.775 (Pearson)
cor(x, y, method="spearman")    # rank-based
cor.test(x, y)                  # also reports p-value

cov(x, y)                       # 1.5 (covariance)
Covariance vs Correlation (2024 Part-A h) Covariance measures joint variability in original units — magnitude is hard to interpret. Correlation standardises covariance by SDs, giving a unit-free [−1, 1] number → directly comparable across datasets. cor(x,y) = cov(x,y) / (sd(x) × sd(y)).
Plain English Correlation packs two facts into one number from −1 to +1. The sign says the direction (positive = both rise together, negative = one rises as the other falls). The size says the strength (close to ±1 = strong straight-line link, near 0 = no linear link). Covariance says the same direction but in messy original units (kg × marks) — correlation is the cleaned-up, unit-free version.

Definition

Hypothesis testing is a formal statistical procedure to decide between two competing claims about a population parameter using sample data and a chosen significance level α.

The six steps (in order)
  1. State H₀ & H₁ — null (no effect / equality) and alternative (the claim to test).
  2. Choose α — significance level, typically 0.05 (5%), fixed before seeing data.
  3. Select the test statistic — z, t, χ², F, depending on the data.
  4. Compute the statistic & p-value from the sample.
  5. Decision rule — reject H₀ if p < α (or |stat| > critical value).
  6. Interpret in context — translate the result back to the original problem.

What "debugging in R" means

When a function throws an error, R's debugging tools let you:

  • Inspect the call stack — which function called which, in what order.
  • Pause execution and examine the environment — live values of all local variables at that point.
  • Step through code line-by-line or inject a breakpoint without editing the source.

R ships five built-in debugging facilities, each suited to a different stage:

  • traceback(): a post-mortem tool. Run it after an error to print the call stack that led to the failure — read it bottom-to-top to find where the error originated.
  • debug(fn): flags a function so that every future call enters step-through (interactive) mode, executing one line at a time. Undo with undebug(fn).
  • browser(): a breakpoint you insert inside the code. Execution pauses exactly there and drops into an interactive prompt where you can inspect or change variables.
  • trace(): injects code (often browser()) into a function without editing its source — handy for functions in packages you cannot modify. Remove with untrace().
  • options(error = ...): sets a global handler that fires on any uncaught error, e.g. options(error = recover) drops you into the frame of your choice automatically.
Interactive browser commands

Once paused (via debug(), browser(), or recover), use these single-letter commands:

  • n — execute the next line (step over).
  • s — step into a function call on the current line.
  • c — continue until the next breakpoint or the function returns.
  • Q — quit the debugger and abort execution.
  • where — print the current call stack.

Binomial distribution — definition & assumptions

The Binomial distribution models the number of successes in n independent, identical Bernoulli trials each with success probability p.

  • Fixed n: number of trials is predetermined (here n = 5).
  • Independent trials: outcome of one trial does not affect others.
  • Constant p: probability of success is the same for every trial.
  • Binary outcomes: each trial is success (1) or failure (0) only.
PMF: P(X = x) = C(n, x) · px · qn−x , x = 0, 1, …, n Mean = np , Variance = npq , where q = 1 − p
Step-by-step fitting

Step 1 — Compute total frequency N and weighted sum Σfx.

N = Σf = 2 + 16 + 28 + 12 + 9 + 3 = 70
Σfx = 0·2 + 1·16 + 2·28 + 3·12 + 4·9 + 5·3 = 0 + 16 + 56 + 36 + 36 + 15 = 159
Sample mean x̄ = Σfx / N = 159 / 70 = 2.2714

Step 2 — Estimate p̂ by method of moments.

  • For Binomial(n, p), the expected value is E(X) = np.
  • Setting E(X) = x̄ gives p̂ = x̄ / n (method of moments estimator).
p̂ = x̄ / n = 2.2714 / 5 = 0.4543
q̂ = 1 − p̂ = 1 − 0.4543 = 0.5457

Examiner traps
  • p̂ = x̄ / n, NOT x̄ / N. Divide the sample mean by the number of trials (n = 5), not by the total frequency (N = 70). This is the most common slip.
  • Σfx arithmetic. Compute each fx product separately (0·2, 1·16, 2·28, 3·12, 4·9, 5·3) before summing — rushing causes carry errors especially at x = 2 and x = 3.
  • Expected must sum to N. If Σ E ≠ 70 (within rounding), recheck the p̂ calculation. Rounding p̂ early cascades into all six expected values.
  • In R, use dbinom(x, size=n, prob=p_hat) — not dpois. Binomial needs both size and prob; Poisson needs only lambda.

Binomial
  • n independent trials, each with success probability p; counts the successes.
  • Mean = np tells the expected number of successes; variance = npq shows spread.
  • Approaches Normal when n is large and p is not extreme (np > 5 and nq > 5).
Poisson
  • Models rare, independent events occurring at a constant average rate λ per interval.
  • Signature property: mean = variance = λ. If observed variance ≫ mean, Poisson is a poor fit.
  • Limiting case of Binomial when n → ∞ and p → 0 with np = λ fixed.
Normal
  • Symmetric bell curve; fully described by μ (centre) and σ² (spread).
  • Empirical rule: 68% within ±1σ, 95% within ±2σ, 99.7% within ±3σ.
  • Foundation of inference — the Central Limit Theorem says sample means are approximately Normal for large n regardless of the parent distribution.
Uniform
  • Every value in [a, b] is equally likely; PDF is a flat horizontal line.
  • Mean = midpoint of the interval; variance = (b−a)²/12 (depends only on the range width).
  • Used as the starting distribution when generating random numbers in simulations.
Exponential
  • Models time between events in a Poisson process (memoryless property).
  • Memoryless: P(X > s + t | X > s) = P(X > t) — past waiting time does not affect future.
  • Mean = 1/λ; if λ = 2 calls/min, average wait = 0.5 min; variance = 1/λ².

Explain how to create a matrix in R. Demonstrate element-wise multiplication, matrix multiplication (%*%), and combining matrices with cbind()/rbind().

1. Creating a matrix
  • A matrix is a 2-D atomic structure: all elements share one type, laid out in rows × columns.
  • Built with matrix(data, nrow, ncol, byrow). By default R fills column-wise (byrow = FALSE); set byrow = TRUE to fill row-wise.
  • Use dimnames (a list of row/col names) for labelled axes, or dim(x) <- c(r, c) to reshape an existing vector into a matrix.
2. Element-wise vs matrix multiplication
  • A * B — element-wise (Hadamard) product: same-shape matrices, each cell A[i,j]×B[i,j].
  • A %*% B — true matrix product: inner dimensions must match (cols of A = rows of B); result is rows(A) × cols(B).
3. Worked R example

1 · Matrix creation + element-wise product — matrix(..., byrow=TRUE) then A * B (Hadamard product)

# --- Create matrices (fill row-wise) ---
A <- matrix(1:4, nrow = 2, byrow = TRUE)   # [[1,2],[3,4]]
B <- matrix(c(5,6,7,8), nrow = 2, byrow = TRUE) # [[5,6],[7,8]]

# --- Element-wise product  A * B ---
A * B
#      [,1] [,2]
# [1,]    5   12      # 1*5, 2*6
# [2,]   21   32      # 3*7, 4*8

2 · Matrix product + combine — A %*% B (dot product), then cbind() / rbind()

# --- Matrix product  A %*% B ---
A %*% B
#      [,1] [,2]
# [1,]   19   22      # 1*5+2*7, 1*6+2*8
# [2,]   43   50      # 3*5+4*7, 3*6+4*8

# --- Combine matrices ---
cbind(A, B)   # 2x4  -> columns of B appended to A
rbind(A, B)   # 4x2  -> rows of B stacked below A
dim(cbind(A, B))   # 2 4
dim(rbind(A, B))   # 4 2
The trap — A * B is NOT A %*% B For A=[[1,2],[3,4]], B=[[5,6],[7,8]]: element-wise top-left is 1×5 = 5, but matrix-product top-left is 1×5 + 2×7 = 19. Writing * where the question wants the dot-product is the single most common matrix error.

Key takeaways · revise these 5
  • Create: matrix(data, nrow, ncol, byrow) — fills column-wise unless byrow=TRUE; atomic, single type.
  • A * B — element-wise, needs identical dimensions; cell A[i,j]×B[i,j].
  • A %*% B — true matrix product, needs cols(A)=rows(B); row×column dot-products.
  • cbind() appends columns (matching rows) → wider; rbind() stacks rows (matching columns) → taller.
  • Inspect with dim(), nrow(), ncol(), t() (transpose); never confuse * with %*% in the exam.

Write short notes on: lapply() and sapply() functions in R.

lapply()
  • lapply(X, FN) applies function FN to every element of a list or vector X.
  • Output is always a list of the same length as the input — structure preserved even when results differ in type or length.
  • Replaces an explicit for loop; runs in C internally, so shorter and faster.
sapply()
  • sapply(X, FN) = simplified lapply — same call, but the result is collapsed when possible.
  • Returns a vector when every result is a scalar, a matrix when results are equal-length vectors, otherwise a list.
  • Pick it when output is uniform and a clean printable vector is wanted.
Worked example
nums <- 1:3
lapply(nums, sqrt)   # list:   [[1]] 1  [[2]] 1.414  [[3]] 1.732
sapply(nums, sqrt)   # vector: 1.000 1.414 1.732

scores <- list(a=c(80,90), b=c(60,70,85))
sapply(scores, mean) # a=85.00  b=71.67
