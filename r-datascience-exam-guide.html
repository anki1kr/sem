1.1 What is Data Science? Part-A repeat

Definition Data Science is a multi-disciplinary field that combines statistics/mathematics, computer science (programming & algorithms), and domain expertise to extract actionable insight from raw data through a pipeline of collection → cleaning → analysis → visualisation → decision.
Why it matters DS is the umbrella that uses statistics + computing + domain together — alone, none of the three solve real-world problems. A pure statistician without code can't process big data; a pure programmer without stats can't tell signal from noise; a pure domain expert without either can't quantify a hunch. The whole point of "data science" as a label is to insist on all three at once.

1.2b Meaning of Variables Part-A repeat

Definition A variable is a measurable characteristic or attribute that varies across observations (units, people, rows). It "varies" — if every unit had the same value it would be a constant, not a variable. In a dataset, every column is a variable and every row is an observation.
  • By value type — Continuous: any value in a range, infinitely divisible (height, weight, temperature, time). Discrete: countable whole values only (number of children, defects, dice roll).
  • By measurement (categorical) — Nominal: named categories with no order (colour, gender, blood group). Ordinal: categories with a natural rank but unequal gaps (grade A/B/C, satisfaction Low/Med/High).
  • By role in a model — Independent (X): the input / predictor / cause, controlled or observed. Dependent (y): the output / response, whose value depends on X. Example: y = exam-score depends on X = hours-studied.
Plain English A variable is just "the thing you're recording that can be different for each person". Continuous = you measure it on a ruler (can be 1.71 m). Discrete = you count it (2 cars, never 2.3). Nominal = names with no winner (red vs blue). Ordinal = names that line up (Gold > Silver > Bronze). X is what you change, y is what you watch happen.
R link — how is a variable stored? (1.5M Part-A)
In a data.frame, each column IS a variable. Build one and read off its columns: 
df <- data.frame(
  hours = c(2, 4, 6),   # numeric (continuous) → X
  grade = c("C","B","A"),  # categorical (ordinal)

1.3b Wholeness of Data Analytics 5M dropper

Definition The wholeness of data analytics is the idea that analytics is a single connected maturity ladder of four climbing types — each answers a harder business question and adds more value than the one below it. The standard order is Descriptive → Diagnostic → Predictive → Prescriptive; you cannot trust the higher rungs until the lower ones are solid.

Mnemonic: Dogs Don't Predict Prescriptions — Descriptive, Diagnostic, Predictive, Prescriptive (easy → hard).

Exam hook Examiner loves "explain the four types of analytics" as a 5M Part-B short. Draw the ladder, give one R verb + one company example per rung, and state the punch-line: value and difficulty rise together, and each rung depends on the one below. summary() = descriptive, cor() = diagnostic, lm()/predict() = predictive, optim()/rules = prescriptive.
Common trap Don't call these "stages of the data-processing chain" — that is a different Unit-I topic (Fig 1.3: Collect → Clean → … → Decide). The four analytics types describe what kind of question you ask of clean data; the processing chain describes how raw data flows to a decision. Mixing them loses marks.

What exactly IS a data warehouse? (Inmon's 4 properties + schema)
Definition · Data Warehouse

A Data Warehouse is a subject-oriented, integrated, time-variant, non-volatile collection of data built to support management decision-making (the four properties from W. H. Inmon, the "father of the data warehouse").

  • Subject-oriented — organised around business subjects (Sales, Customer, Product), not around an application's day-to-day process.
  • Integrated — data from many source DBs is cleaned and conformed to one consistent format (same units, codes, naming) during ETL.
  • Time-variant — stores a long history with a time dimension, so trends across years can be analysed (an OLTP DB keeps only the current value).
  • Non-volatile — data is loaded then read; it is not updated or deleted in place, so analytical results stay reproducible.
SITN — Subject-oriented · Integrated · Time-variant · Non-volatile (Inmon's 4)

A warehouse is modelled as a dimensional schema: one central fact table holding numeric, additive measures (e.g. units_sold, revenue) plus foreign keys, surrounded by dimension tables giving the descriptive context (who, what, where, when — Customer, Product, Store, Date).

Star vs Snowflake in one line Star schema keeps each dimension as a single flat (denormalised) table — fewer joins, faster reads, slight redundancy. Snowflake schema normalises a dimension into sub-dimensions (Product → Category → Department) — saves space, but more joins slow queries. Warehouses usually prefer star for analytical speed.

1.8 Advice for New Data Scientists

  1. Statistics first — without inference, you're just plotting.
  2. Master one language end-to-end (R or Python) before sampling others.
  3. Build domain knowledge — DS without context produces meaningless models.
  4. Communicate — a one-line takeaway beats a 30-page report.
  5. Work on messy data — Kaggle-clean ≠ industry. Practice ETL.
  6. Version everything — code (git), data (DVC), models (MLflow).

2.1 What is R? History & Features

Definition R is an open-source, interpreted, high-level language and environment for statistical computing and graphics. Created by Ross Ihaka & Robert Gentleman at the University of Auckland (1993); current stable maintained by the R Core Team and distributed via CRAN.

Key features:

  • Vectorised operations — built-in element-wise arithmetic (no explicit loop for x + y).
  • 18,000+ packages on CRAN (statistics, ML, viz, bioinformatics).
  • First-class statistics — distributions, hypothesis tests, GLMs built in.
  • Reproducible reports via R Markdown / Quarto (PDF, HTML, Word).
  • Cross-platform & free (GPL-2).

Limitations: single-threaded by default · slower than C/Python for heavy loops · steeper learning curve for non-statisticians · weaker production-deployment story than Python.

Plain English Four ways data can be "not a normal number" — each says something different.

  • NULL = "nothing was ever here" (no box at all — used to remove a column).
  • Inf = "too big to write" (overflow or division by zero).

2.7 Objects & Type Conversions Part-A 2024(e)

R has 6 atomic types: logical, integer, double (numeric), complex, character, raw. Everything is an object.

# Inspect
class(3.14)        # "numeric"
typeof(3.14)       # "double"
class(5L)          # "integer"

# Convert (coerce)
as.integer("42")   # 42
as.numeric("3.14") # 3.14
as.character(99)   # "99"
as.logical(0)      # FALSE
as.logical(1)      # TRUE

# Implicit coercion hierarchy:
# logical < integer < numeric < complex < character
c(TRUE, 2L, 3.5, "x")   # all become "x" (character)
Coercion rule — the single most-tested trap A vector is homogeneous, so when you c() mixed types together R silently promotes every element up to the most general type present, following the fixed ladder logical → integer → double → complex → character. It never demotes — one string in the mix turns the whole vector into character. 
# Watch each result climb the ladder
c(TRUE, FALSE)        # logical
c(TRUE, 5L)           # integer  -> c(1L, 5L)   (TRUE counts as 1)
c(TRUE, 2.5)          # double   -> c(1.0, 2.5)
c(2L, 4.5)            # double   -> c(2.0, 4.5)
c(3.5, "x")           # character-> c("3.5", "x")

# Explicit coercion can FAIL silently -> NA + warning
as.numeric("hello")   # NA (with a warning) — not an error
as.integer(3.9)       # 3   (truncates toward zero, does NOT round)

2.12 Factors

Categorical data stored as integer codes + level labels — saves memory + drives statistical modelling.

g <- factor(c("M","F","M","F"), levels=c("M","F"))
levels(g)                    # "M" "F"
table(g)                     # frequency count

# Ordered factor — useful in models
o <- factor(c("L","H","M"),
  levels=c("L","M","H"), ordered=TRUE)
o[1] < o[2]                  # TRUE
# More factor operations
nlevels(g)                   # 2  — number of distinct levels
as.integer(g)                # 1 2 1 2  — underlying integer codes
levels(g) <- c("Male","Female")   # rename levels in place
droplevels(g[g == "Male"])   # drop unused levels after subsetting

# cut() turns a numeric vector INTO a factor (binning)
marks <- c(45, 72, 88, 55, 91)
grade <- cut(marks,
             breaks = c(0, 50, 70, 100),
             labels = c("Fail", "Pass", "Distinction"))
grade        # Fail Distinction Distinction Pass Distinction
table(grade) # frequency per bin
The classic factor trap — as.numeric on a factor Converting a factor of numbers back to numbers needs two steps: as.numeric(as.character(f)). A direct as.numeric(f) returns the hidden integer level codes (1, 2, 3 …), not the original values — a guaranteed silent bug.
Why factors matter for modelling A factor tells R "this is categorical, not arithmetic". Functions like lm(), aov() and ggplot() use levels to build dummy variables, order axis labels, and group computations. An ordered factor additionally lets < > comparisons work (Low < Medium < High), which a plain character vector cannot.

3.2b Logical Operators — Behaviour Cheat-Table Part-A · Unit III

In plain English Two families look identical but behave differently. The single forms (& |) are element-wise — they line up two vectors and compare position-by-position, returning a logical vector. Examiner traps
  • Using && on a multi-element vector inside if() — only the first element is read (and errors in R ≥ 4.3). Use single & for vectors.
  • Testing if (x == NA) — always yields NA, never TRUE. Use is.na(x), or isTRUE() to fold an NA condition to FALSE.
  • Expecting any()/all() to ignore NA — they return NA by default; pass na.rm = TRUE.

The term: "recursive list" (recursive vector) A recursive list is a list whose elements can themselves be lists — to any depth (a list of lists of lists…). Because of this nesting power, R officially calls a list a recursive vector, in contrast to an atomic vector (a flat c() of one type that cannot hold another vector inside it).
  • Test it: is.recursive(L) → TRUE for any list; is.recursive(c(1,2,3)) → FALSE for an atomic vector. Mirror: is.atomic() is TRUE for the atomic vector, FALSE for the list.
  • Inspect depth: str(L) prints the nested tree with indented $ levels — the fastest way to read how deep a recursive list goes.
  • Flatten it: unlist(L) collapses every nested level into a single atomic vector (and coerces to one common type via the promotion ladder).

S3 — informal, the original

The 6 layers in prose — one paragraph each

  • 1 · Data — the data frame fed to ggplot() is the foundation: every layer above derives its values from these columns. One plot can refer to a single data frame or layer-specific overrides. Example: ggplot(data = students) binds the students data frame to the plot.
  • 2 · Aesthetics (aes()) — the mapping from data columns to visual channels (x, y, colour, fill, size, shape, alpha). Aesthetics describe what variable controls what visual, never raw values. Example: aes(x = hours, y = marks, colour = grade) maps three columns to three channels.
  • 3 · Geometries (geom_*) — the visual marks drawn for each row: points, bars, lines, boxplots, polygons. Geometries consume aesthetics and emit shapes; multiple geoms can stack on the same aesthetic mapping. Example: geom_point(size = 3) draws a scatter, geom_bar(stat = "count") draws bars.
  • 4 · Statistics (stat_*) — optional transformations applied before drawing: smoothing, binning, density estimation, summary statistics. Every geom has a default stat (e.g. geom_bar uses stat_count); explicit stats let you overlay fits or summaries. Example: stat_smooth(method = "lm") overlays a linear-regression line with confidence band.
  • 5 · Facets (facet_*) — split the plot into small multiples by one or two categorical variables, so subgroups can be compared side-by-side without overlapping. Replaces base-R's manual par(mfrow=). Example: facet_wrap(~ grade) creates one panel per grade; facet_grid(sex ~ year) builds a 2-D matrix.
  • 6 · Themes (theme_*) — non-data styling: fonts, gridlines, panel background, legend position, axis ticks. Themes never change the data or its mapping, only the presentation. Example: theme_minimal() strips chartjunk for publication; theme(legend.position = "bottom") tweaks one element.

Compose order: Data → Aesthetics → Geometries are mandatory; Statistics, Facets and Themes are optional refinements. Each layer is added with the + operator, so a complete ggplot reads top-to-bottom like a recipe: ggplot(df, aes(x, y)) + geom_point() + stat_smooth() + facet_wrap(~g) + theme_minimal().

Plain English Base graphics = paint directly on a canvas, one brush stroke at a time — fast and final. ggplot2 = stack transparencies (data layer + mapping layer + shapes layer + theme layer) and combine them with +. Slower to render, but much easier to change later — just swap one layer instead of redrawing.

4.8 Hypothesis Testing ⭐ 2023 Q4a, 2025 Q6a (8–10 M)

Definition Hypothesis testing is a formal statistical procedure to decide between two competing claims about a population parameter using sample data and a chosen significance level α.

The six steps (memorise the order)

  1. State H₀ & H₁ — null (no effect, equality) and alternative (claim to test).
  2. Choose α — significance level, typically 0.05 (5%).
  3. Select test statistic — z, t, χ², F, depending on data.
  4. Compute test stat & p-value from the sample.
  5. Decision rule — reject H₀ if p < α (or |stat| > critical value).
  6. Interpret in context — translate back to the original problem.

weights <- c(48, 52, 49, 51, 53, 47, 50, 51, 49, 52)

Common pitfalls (1) p > α does not prove H₀ — only fails to reject. (2) α is set before looking at data. (3) Don't confuse statistical with practical significance.
Plain English Hypothesis testing = an honest court. H₀ (null) is the "innocent" default — no effect, no difference. The sample is the evidence. If the evidence is strong enough (p-value below α=5%), we reject H₀ ("guilty"); otherwise we acquit ("not enough proof"). We never prove H₀ — we just fail to reject it. Same logic as "innocent until proven guilty".

One-tailed vs two-tailed

  • Two-tailed (default) — H₁ says the parameter is simply different (≠). The α is split into both tails (2.5% each at α = 0.05). Use when you have no prior direction.
  • One-tailed — H₁ claims a direction (> or <). All of α sits in one tail, giving more power to detect an effect in that direction. In R: t.test(x, mu=50, alternative="greater") or "less".

Type I & Type II errors — the decision matrix

Decision \ RealityH₀ is TRUEH₀ is FALSE
Reject H₀Type I error (α) — false positiveCorrect (power = 1 − β)
Fail to reject H₀Correct decisionType II error (β) — false negative
  • Type I (α) — rejecting a true null. "Convicting the innocent." Controlled directly by the chosen significance level.
  • Type II (β) — failing to reject a false null. "Acquitting the guilty." Reduced by larger samples or bigger effect sizes.
  • Power = 1 − β — the probability of correctly detecting a real effect. Increasing n raises power without inflating α.
Reading any t.test() / cor.test() output Every base test prints the same anatomy: the test statistic (t, χ², z), the degrees of freedom, the p-value, the confidence interval, and a sample estimate. Decision is always the same rule: reject H₀ when p < α; for a mean-difference test, a CI that excludes the null value corroborates rejection.

4.9 Correlation 2023 Q4c, 2024 Part-A(d,h), 2025 Part-A(i)

Definition Correlation measures the strength and direction of the linear relationship between two numeric variables. Pearson's r ∈ [−1, +1]:
r = +1 → perfect positive · r = 0 → none · r = −1 → perfect negative.
r = Σ(xᵢ − x̄)(yᵢ − ȳ) / √[ Σ(xᵢ − x̄)² · Σ(yᵢ − ȳ)² ] 
x <- c(1, 2, 3, 4, 5)
y <- c(2, 4, 5, 4, 5)

cor(x, y)                       # 0.775 (Pearson)
cor(x, y, method="spearman")    # rank-based
cor.test(x, y)                  # also reports p-value

cov(x, y)                       # 1.5 (covariance)
Covariance vs Correlation (2024 Part-A h) Covariance measures joint variability in original units — magnitude is hard to interpret. Correlation standardises covariance by SDs, giving a unit-free [−1, 1] number → directly comparable across datasets. cor(x,y) = cov(x,y) / (sd(x) × sd(y)).
Plain English Correlation packs two facts into one number from −1 to +1. The sign says the direction (positive = both rise together, negative = one rises as the other falls). The size says the strength (close to ±1 = strong straight-line link, near 0 = no linear link). Covariance says the same direction but in messy original units (kg × marks) — correlation is the cleaned-up, unit-free version.

Worked answer — May-2024 Q1d/h verbatim: compute cor, cor.test, and verify cor = cov ÷ (sd·sd).

cor(hours, marks)                          # 0.993  (Pearson, default)
cor(hours, marks, method = "spearman")     # 1.000  (rank-based)

cor.test(hours, marks)
#         Pearson's product-moment correlation
# t = 19.0, df = 5, p-value = 7.4e-06
# alternative hypothesis: true correlation is not equal to 0
# 95 percent confidence interval:
#  0.953 0.999
# sample estimates:
#       cor
# 0.993
# -> p < 0.05  =>  reject H0 (correlation IS non-zero)

# Manual relation: cor = cov / (sd_x * sd_y)
cov(hours, marks) / (sd(hours) * sd(marks))   # 0.993 (matches cor())

Explain the debugging techniques available in R (traceback(), debug(), browser(), trace(), options(error)) with examples.

What "debugging in R" means

When an R function throws an error or returns a wrong result, debugging tools let you inspect the call stack (which function called which) and pause execution to examine the environment (the live values of local variables). R ships five built-in debugging facilities, each suited to a different stage:

  • traceback(): a post-mortem tool. Run it after an error to print the call stack that led to the failure — read it bottom-to-top to find where the error originated.
  • debug(fn): flags a function so that every future call enters step-through (interactive) mode, executing one line at a time. Undo with undebug(fn).
  • browser(): a breakpoint you insert inside the code. Execution pauses exactly there and drops into an interactive prompt where you can inspect or change variables.
  • trace(): injects code (often browser()) into a function without editing its source — handy for functions in packages you cannot modify. Remove with untrace().
  • options(error = ...): sets a global handler that fires on any uncaught error, e.g. options(error = recover) drops you into the frame of your choice automatically.
Interactive browser commands

Once paused (via debug(), browser() or recover), these single-letter commands drive the session:

  • n — execute the next line (step over).
  • s — step into a function call on the current line.
  • c — continue until the next breakpoint or the function returns.
  • Q — quit the debugger and abort execution.

  • Supervised learning learns a mapping from inputs (X) to a known output label (Y) using labelled training data. The model is told the "right answer" during training, then generalises to unseen data.

Definition

Data Science is an interdisciplinary field that uses scientific methods, algorithms and systems to extract knowledge and actionable insight from structured and unstructured data. It fuses statistics, computer science / programming and domain expertise to turn raw data into decisions. In short, it is the practice of converting data → information → knowledge → wise action.

  • Statistics & Mathematics — probability, inference, distributions and modelling that let us quantify uncertainty and test hypotheses (the "is this real?" layer).

Explain how to create a matrix in R. Demonstrate element-wise multiplication, matrix multiplication (%*%), and combining matrices with cbind()/rbind().

1. Creating a matrix
  • A matrix is a 2-D atomic structure: all elements share one type, laid out in rows × columns.
  • Built with matrix(data, nrow, ncol, byrow). By default R fills column-wise (byrow = FALSE); set byrow = TRUE to fill row-wise.
  • Use dimnames (a list of row/col names) for labelled axes, or dim(x) <- c(r, c) to reshape an existing vector into a matrix.
2. Element-wise vs matrix multiplication
  • A * B — element-wise (Hadamard) product: same-shape matrices, each cell A[i,j]×B[i,j].
  • A %*% B — true matrix product: inner dimensions must match (cols of A = rows of B); result is rows(A) × cols(B).
3. Worked R example
# --- Create matrices (fill row-wise) ---
A <- matrix(1:4, nrow = 2, byrow = TRUE)   # [[1,2],[3,4]]
B <- matrix(c(5,6,7,8), nrow = 2, byrow = TRUE) # [[5,6],[7,8]]

# --- Element-wise product  A * B ---
A * B
#      [,1] [,2]
# [1,]    5   12      # 1*5, 2*6
# [2,]   21   32      # 3*7, 4*8

# --- Matrix product  A %*% B ---
A %*% B
#      [,1] [,2]
# [1,]   19   22      # 1*5+2*7, 1*6+2*8
# [2,]   43   50      # 3*5+4*7, 3*6+4*8

# --- Combine matrices ---
cbind(A, B)   # 2x4  -> columns of B appended to A
rbind(A, B)   # 4x2  -> rows of B stacked below A
dim(cbind(A, B))   # 2 4
dim(rbind(A, B))   # 4 2
The trap — A * B is NOT A %*% B For A=[[1,2],[3,4]], B=[[5,6],[7,8]]: element-wise top-left is 1×5 = 5, but matrix-product top-left is 1×5 + 2×7 = 19. Writing * where the question wants the dot-product is the single most common matrix error.

Key takeaways · revise these 5
  • Create: matrix(data, nrow, ncol, byrow) — fills column-wise unless byrow=TRUE; atomic, single type.
  • A * B — element-wise, needs identical dimensions; cell A[i,j]×B[i,j].
  • A %*% B — true matrix product, needs cols(A)=rows(B); row×column dot-products.
  • cbind() appends columns (matching rows) → wider; rbind() stacks rows (matching columns) → taller.
  • Inspect with dim(), nrow(), ncol(), t() (transpose); never confuse * with %*% in the exam.
