Functional Blocks of a Computer ⭐ Repeated 3×

Definition A digital computer is built from three functional units linked by a system bus: the CPU (the processor), the main memory, and the I/O subsystem. This is the classic Von Neumann organisation — instructions and data share the same memory.

The Three Functional Units

  • CPU (Central Processing Unit) — the brain. Has three internal parts: the ALU (Arithmetic & Logic Unit — does add, subtract, AND, OR, shift), the Control Unit (CU) (generates timing/control signals, sequences instruction execution), and a set of registers (fast on-chip storage: PC, IR, MAR, MBR, AC, general-purpose).
  • Main Memory — stores the program (instructions) and data. Addressable in words/bytes; CPU reads/writes via the address and data buses. Volatile (RAM).
  • I/O Subsystem — interfaces (controllers) connecting peripherals (keyboard, disk, display) to the bus. Converts external signals to a form the CPU understands.

The System Bus (three buses)

  • Address Bus — carries the memory/device address; unidirectional (CPU → memory). Width fixes the addressable space (n lines ⇒ 2ⁿ locations).
  • Data Bus — carries the actual data/instruction; bidirectional. Width = word size.
  • Control Bus — carries timing & command signals (READ, WRITE, clock, interrupt, bus-grant); bidirectional.
Why this matters The single shared memory bus creates the Von Neumann bottleneck: the CPU cannot fetch an instruction and read/write data in the same cycle, since both contend for one bus. The Harvard architecture fixes this by giving instructions and data separate memories and buses.

Instruction Execution Cycle & RTL ⭐ Repeated 4×

Definition Every instruction passes through the Fetch → Decode → Execute cycle. Register Transfer Language (RTL) is the notation that describes each micro-operation as a transfer between registers, written destination ← source.

Key Registers in the Cycle

  • PC (Program Counter) — holds the address of the next instruction.
  • MAR (Memory Address Register) — holds the address being sent on the address bus.
  • MBR / MDR (Memory Buffer / Data Register) — holds data just read from / to be written to memory.
  • IR (Instruction Register) — holds the current instruction being decoded.
  • ALU + AC (Accumulator) — perform and hold the result of the operation.

Signed Number Representation ⭐ Repeated 5×

Definition Three schemes encode the sign of a binary integer. In all three the MSB is the sign bit (0 = positive, 1 = negative). They differ in how the magnitude of a negative number is stored.
  • Sign-Magnitude — sign bit + true magnitude. Simple to read but has two zeros (+0, −0) and needs separate add/subtract logic.
  • 1's Complement — negate by inverting every bit. Also has two zeros; addition needs an end-around carry.
  • 2's Complement — negate by inverting all bits then adding 1. Single zero, subtraction = addition of the negative, no end-around carry. This is why all modern CPUs use 2's complement.

3

4

Computer Arithmetic — Ripple Carry vs Carry Look-Ahead Adder ⭐ Repeated 3×

Definition An n-bit adder is built from n full adders. A full adder takes Aᵢ, Bᵢ, Cᵢ and outputs sum Sᵢ = Aᵢ ⊕ Bᵢ ⊕ Cᵢ and carry Cᵢ₊₁ = Aᵢ·Bᵢ + (Aᵢ⊕Bᵢ)·Cᵢ.

Ripple Carry Adder (RCA)

  • Full adders are cascaded — the carry-out of stage i feeds the carry-in of stage i+1.
  • Stage i cannot compute its true sum until the carry has rippled through all lower stages.
  • Slow: worst-case delay grows linearly, ≈ n × (gate delay) for n bits.

Carry Look-Ahead Adder (CLA)

The CLA computes all carries in parallel from the inputs, removing the ripple. For each bit define two signals:

  • Generate Gᵢ = Aᵢ · Bᵢ — this stage produces a carry regardless of carry-in (both inputs 1).
  • Propagate Pᵢ = Aᵢ ⊕ Bᵢ — this stage passes an incoming carry through.
  • Carry recurrence: Cᵢ₊₁ = Gᵢ + Pᵢ · Cᵢ.

Expanding the recurrence gives each carry as a direct function of the inputs and C₀:

C₁
C₁ = G₀ + P₀·C₀
C₂
C₂ = G₁ + P₁·G₀ + P₁·P₀·C₀
C₃
C₃ = G₂ + P₂·G₁ + P₂·P₁·G₀ + P₂·P₁·P₀·C₀
Why CLA is faster Each carry above is a two-level (AND-OR) expression of inputs already available — so every carry is ready after a constant ≈2-gate delay, independent of n, versus the RCA's n-stage ripple. The cost is far more gates (the expressions grow with i), so CLA trades hardware area for speed. Real ALUs build wide adders by chaining 4-bit CLA blocks.

Booth's Signed Multiplier ⭐ Repeated 4×

Definition Booth's algorithm multiplies two signed 2's-complement numbers directly (no sign correction). It scans the multiplier's bit pair (Q₀, Q₋₁) and acts on runs of 1's, replacing many additions with one add + one subtract per run.

Recoding Rule (examine Q₀ Q₋₁)

  • 0 0 or 1 1 → no arithmetic, just arithmetic shift right (ASR) of A·Q·Q₋₁.
  • 0 1 → A ← A + M, then ASR. (end of a run of 1's)
  • 1 0 → A ← A − M, then ASR. (start of a run of 1's)

Restoring vs Non-Restoring Division ⭐ Repeated 3×

Definition Both algorithms divide an unsigned dividend (in register pair A:Q, A = remainder, Q = quotient) by a divisor M over n steps. Each step shifts A:Q left then either subtracts or adds M.

Restoring Algorithm — repeat n times

  • Shift A:Q left by 1.
  • A ← A − M.
  • If A < 0 (MSB = 1): set Q₀ = 0 and restore by A ← A + M.
  • Else (A ≥ 0): set Q₀ = 1 (no restore).

Non-Restoring Algorithm — repeat n times

  • If A ≥ 0: shift left, A ← A − M.   If A < 0: shift left, A ← A + M.
  • Set Q₀ = 1 if the new A ≥ 0, else Q₀ = 0.
  • No separate restore step — a wrong subtraction is corrected by adding M in the next cycle. If A is negative after the last step, do one final A ← A + M.

Worked Example — 7 ÷ 3 (4-bit, restoring)

Dividend Q = 7 = 0111, divisor M = 3 = 0011, A = 0000. Run n = 4 cycles. Expected: quotient = 2, remainder = 1.

DMA Controllers & I/O Transfer Modes ⭐ Guaranteed 10M

DMA (Direct Memory Access) transfers data directly between high-speed peripherals and main memory without passing through the CPU, saving clock cycles.

Why DMA gets Priority The CPU is patient because its instructions can wait. High-speed I/O peripherals are volatile and impatient — if incoming data blocks are not read instantly, they will overwrite and be lost. Thus, DMA holds higher bus priority.

Memory Organization & Address Lines ⭐ Numerical

A memory chip is a 2-D grid of cells. The cells are grouped into words (a word = the number of bits read/written in one access, e.g. 8 bits). The CPU selects one word using the address bus and transfers it over the data bus.

The Address-Line Rule A memory with 2n words needs n address lines (because n bits address 2n distinct locations). The number of data lines = word size in bits. Capacity = (number of words) × (word size).
Worked Example — 4K × 8 memory
Capacity = 4K words, each word 8 bits wide.
Number of words = 4K = 4 × 1024 = 4096 = 212.
Address lines = n where 2n = 212 → 12 address lines.
Data lines = word size = 8 data lines.
Quick conversions 1K = 210 · 1M = 220 · 1G = 230. So 1K×8 → 10 addr / 8 data; 16K×8 → 14 addr / 8 data; 1M×16 → 20 addr / 16 data.

Interrupts & Process State Transitions ⭐ Guaranteed

Interrupt An interrupt is a signal that forces the CPU to suspend the current program, save its state, and run an Interrupt Service Routine (ISR), then resume. It lets the CPU respond to events without wasteful polling.
Types of Interrupts
  • Hardware interrupt: raised by a device (disk done, key pressed, timer tick) on a physical line.
  • Software interrupt (trap): raised by an instruction (e.g. INT, a system call) inside the program.
  • Maskable: can be disabled/ignored by clearing the interrupt-enable flag (most device interrupts).
  • Non-maskable (NMI): cannot be disabled — reserved for critical faults (power failure, memory parity error).
Role in Process State Transitions

Interrupts drive the OS scheduler's state changes:

  • A process issues an I/O request → it is moved Running → Blocked (waiting) while the device works.
  • The device finishes and raises an I/O-completion interrupt → the ISR moves the process Blocked → Ready.
  • A timer interrupt expires the running process's time-slice → it is preempted Running → Ready, letting the scheduler dispatch another.

Pipeline Hazards & Flynn's Classification ⭐ Repeated 3×

Flynn's Parallel Taxonomy Classifies parallel computers by Instruction streams vs Data streams: (1) SISD: Uni-core PC, (2) SIMD: Vector/GPU graphics processor, (3) MISD: Redundant spacecraft systems (rare), (4) MIMD: Modern multicore processors.

The Three Pipeline Hazards

  • Structural Hazard: Hardware conflicts. E.g., when instruction-fetch and data-memory access try to use a single-port memory block at the same time. Resolved by splitting into Instruction and Data caches (Harvard architecture).
  • Data Hazard: Operands not ready. An instruction depends on a previous instruction's result that has not yet completed the write-back stage (RAW, WAR, WAW). Resolved by forwarding or stalling (bubbles).
  • Control Hazard: Branch delays. Decisions on jumps affect which instructions to fetch next. Resolved by branch prediction or branch target buffers.

Pipelining: Basic Concept & 5-Stage RISC Pipeline ⭐ Core 10M

Plain English A pipeline is an assembly line for instructions. Instead of finishing one instruction completely before starting the next, the CPU splits each instruction into stages and overlaps them — while instruction 1 is being executed, instruction 2 is being decoded and instruction 3 is being fetched. Like a laundromat where you wash, dry and fold different loads at the same time.

The classic 5-stage RISC pipeline breaks every instruction into these stages, each handled by a separate hardware unit:

  • IF — Instruction Fetch: read the instruction from memory using the Program Counter.
  • ID — Instruction Decode: interpret the opcode and read source registers.
  • EX — Execute: the ALU performs the arithmetic/logic operation or address calculation.
  • MEM — Memory Access: read from or write to data memory (only load/store instructions use this).
  • WB — Write Back: write the result back into the destination register.

In an ideal pipeline, once it is "full", one instruction completes every clock cycle even though each individual instruction still takes 5 cycles to traverse the pipe. The pipeline does not make a single instruction faster — it improves throughput (instructions finished per unit time).

Throughput & Speedup ⭐ Numerical 10M

Key Terms Throughput = number of instructions completed per unit time. Speedup = how many times faster the pipelined processor is compared to a non-pipelined one running the same workload.

Let a pipeline have k stages, processing n instructions, with each stage taking time τ (one clock cycle).

Time (non-pipelined) = n × k × τ
Time (pipelined) = (k + n − 1) × τ
Speedup S = (n × k) / (k + n − 1)

The first k cycles fill the pipeline (instruction 1 reaching write-back); after that, the remaining (n − 1) instructions each finish one cycle apart — giving the (k + n − 1) total. As n → ∞, the speedup approaches its ideal maximum of k (equal to the number of stages).

Worked Example — k = 4 stages, n = 100 instructions

1
Time without pipeline = n × k × τ = 100 × 4 × τ = 400 τ cycles.
2
Time with pipeline = (k + n − 1) × τ = (4 + 100 − 1) × τ = 103 τ cycles.
3
Speedup S = (n × k) / (k + n − 1) = 400 / 103.
4
S = 3.88 (the pipelined CPU is ~3.88× faster). Ideal limit as n → ∞ is k = 4, so 3.88 is close to the ceiling.
Exam tip Always state the two times separately (400τ and 103τ) before dividing — examiners award marks for the substitution steps, not just the final ratio. The answer is unitless (a ratio), so no τ in the final speedup.

Concurrent Memory Access & Cache Coherency ⭐ Likely 10M

The Cache Coherency Problem In a multicore system each core has its own private cache but they share one main memory. When several cores cache the same memory block and one core writes to it, the copies in the other cores' caches become stale (out of date). If a core then reads its stale copy it gets a wrong value. Keeping all cached copies consistent is the cache coherency problem.

Coherency Solutions (Protocols)

  • Write-Invalidate: when a core writes a block, it broadcasts an invalidate signal so every other cache marks its copy invalid. Other cores must re-fetch the fresh value. Most common (used by MESI).
  • Write-Update (write-broadcast): a write broadcasts the new value to all caches holding that block so they update in place. Higher bus traffic, used less often.
  • Snooping: every cache controller monitors ("snoops") the shared bus for reads/writes to addresses it holds, and reacts (invalidate or update). Works on bus-based systems.
  • MESI protocol: the standard snooping protocol. Each cache line is tagged Modified, Exclusive, Shared or Invalid — these four states track whether a copy is dirty, sole, shared or stale, and drive the invalidate logic.
Memory hook MESI = Modified · Exclusive · Shared · Invalid — the four states a cache line can be in. "Invalidate one, everyone re-reads" is the core idea of write-invalidate coherency.

Set-Associative Cache Mapping ⭐ Guaranteed 10M

A physical address is partitioned into distinct fields to query cache rows:

Set-Associative Address Fields
• WORD = log₂ (Block Size in Bytes)
• SET = log₂ (Total Cache Size / (Block Size × Set Size))
• TAG = Address Width − SET − WORD
Direct Mapping vs Associative • Direct Mapping has a dedicated LINE field; a block can map to exactly one cache line, causing thrashing.
• Set-Associative allows a block to reside in any line within the target SET, balancing search logic complexity with higher hit rates.

Page Replacement Tracing

The Algorithms • FIFO (First-In-First-Out): Evicts oldest page. Suffers from Belady's Anomaly (faults can rise with frame count).
• LRU (Least-Recently-Used): Evicts page untouched for longest time. Most realistic.
• Optimal: Evicts page used farthest in future. Provides theoretical lower bound baseline.

Memory Hierarchy ⭐ 5M / sub-part

The Idea No single memory is both fast and cheap and large. So a computer stacks several memory types in a hierarchy: tiny-fast-costly at the top, huge-slow-cheap at the bottom. The CPU looks at the top first; data moves up on demand. This works because of locality of reference (a recently/nearby item is likely reused soon).

Climbing up the pyramid: speed ↑, cost-per-bit ↑, capacity ↓. Climbing down: cheaper, slower, bigger.

L1 / L2 / L3 split • L1: smallest (~32 KB), fastest, split into I-cache + D-cache, private per core.
• L2: larger (256 KB–1 MB), still per-core, a bit slower.
• L3: largest (MB), shared across all cores, slowest cache level.

Effective access uses the hit ratio h: Tavg = h·Tcache + (1−h)·Tmain. A high hit ratio makes the slow level almost invisible.

Memory Interleaving

Why A single memory module is busy for its whole cycle time on one access. Interleaving splits memory into several independent banks (modules) so consecutive addresses land in different banks. The CPU can then start a new access in bank 2 while bank 1 is still completing — accesses overlap in parallel, raising bandwidth.
  • Low-order interleaving: the low address bits select the bank. Consecutive addresses (0,1,2,3…) spread across banks 0,1,2,3 — so sequential / burst access (instruction fetch, array scan) hits all banks in turn and overlaps. Best for streaming.
  • High-order interleaving: the high address bits select the bank. A whole contiguous block sits in one module. Good for fault isolation and easy module expansion, but no overlap on sequential access.

Write Policies

The Question When the CPU writes to a cached block, when does main memory get the new value? Two answers — and a second axis for what happens on a write that misses.
  • Write-through: every write updates cache AND main memory at once. Memory is always consistent; no dirty bit needed; but slow (every write hits slow memory). A write buffer hides some latency.
  • Write-back (copy-back): write only updates the cache line and sets its dirty bit. Memory is updated only when that line is evicted. Fast, less memory traffic; but memory is temporarily stale (a problem for DMA / multicore coherence).

On a write miss:

  • Write-allocate: load the block into cache first, then write (usually paired with write-back).
  • No-write-allocate: write straight to memory, skip caching the block (usually paired with write-through).

Introduction

Addressing modes are rules built into the ISA. They tell the CPU how to find the effective address (EA) of an operand from the bits in the instruction. The instruction has only a small address field (often 8–16 bits). The real memory address can be 32 or 64 bits wide. Addressing modes bridge this gap. They also let the CPU trade code size, speed, flexibility, and decoder cost. Example: a smartphone CPU runs the same instruction set on millions of programs only because addressing modes hide the address gap.

  • Use 1 — smaller code: a short address field can reach a big memory via indirection or indexing.
  • Use 2 — flexible compilers: indexed and indirect modes let one piece of code walk arrays, structs, linked lists without rewriting.
  • Use 3 — relocation: relative and base-register modes let a program run at any memory address. No re-linking needed.
  • Use 4 — recursion: stack-based addressing handles nested calls with local frames.
  • Use 5 — ISA style: CISC (x86) keeps the full set; RISC (ARM, RISC-V) keeps only a few for pipeline simplicity.

  • ARM AArch64 (RISC): only load-store + immediate + register + register-shifted + PC-relative. No indirect, no direct-to-memory ALU ops. Every memory touch is an explicit LDR/STR.

  • Apple Silicon M-series hits 5+ GHz because ARM64's small mode set lets the front-end decode 8 instructions per cycle without blowing up the decoder.
  • JVM / .NET CLR / WebAssembly all use a zero-address (stack) ISA. RPN maps neatly onto a stack. Bytecode runs anywhere.

(5) Indexed and Base look the same in math but differ by use: indexed walks data, base relocates code.
Conclusion

Addressing modes are the ISA's contract with the compiler. They trade decoder cost for code density and flexibility. Knowing the EA formula for each mode is a must for any compiler or low-level systems engineer.

(b) Booth's Algorithm — Why & How

Booth's algorithm does signed (2's-complement) multiplication. It looks at the last two bits Q₀Q₋₁ of the multiplier, picks one of four actions, then shifts right. A long run of 1s becomes one subtract + one add instead of many adds. So multiplying negative numbers gets faster. No sign-extension needed.

(b) Stack-CPU + RPN Evaluation: (A+B)*(C-D)

A stack-based CPU (zero-address machine) keeps all operands on a hidden operand stack. Instructions name no operand. They just pop the top of stack (TOS), do the work, and push the result. RPN (postfix) fits this style. The operator comes right after its two operands. Think of it like a cinema multiplex queue: last in, first out.

Stack-CPU Characteristics & Trade-offs
  • Zero-address instructions: math opcodes carry no operand field. So instruction words are short and bytecode is dense.
  • Hidden operand source: ADD/SUB/MUL always pop two from TOS and push the result. Only PUSH and POP touch memory.
  • RPN fits naturally: a postfix expression read left-to-right is the program.
  • Recursion is easy: stack frames support nested calls. No need to save/restore registers.
  • Cost: every temporary goes on the stack. Slower than register machines. But the bytecode is portable (JVM, Wasm).
  • Pop order trap: for SUB and DIV, the second pop is the first operand. The first pop is the second operand.
Modern Relevance
  • IEEE-754 is everywhere: every commodity CPU FPU uses it. ARM Cortex-M0/M3 ship single-precision FPUs. Cortex-M7 adds double. x86 SSE/AVX work on packed singles/doubles.
  • Booth in silicon: modern multipliers use Radix-4 Booth (looks at 3 bits) plus Wallace-tree reduction. They compute 64-bit products in about 3 cycles. The classic 2-bit Booth still shows up in low-power DSPs.
  • Stack machines in production: JVM bytecode (every .class file), .NET CIL, WebAssembly, PostScript, Forth — all run on virtual stack machines. Wasm's stack ISA lets a 2 MB binary run the same on x86, ARM, RISC-V.
  • FMA fusion: AVX-512 and ARM NEON fuse multiply-add into one rounding (a*b + c). More precision, half the instructions for matrix work.
Common pitfalls (1) Bias trap: write the biased exponent E + 127, not the raw exponent. For E = -3, the field stores 124. (2) Hidden bit: the leading 1. of a normal mantissa is hidden. Never write it into the 23 stored bits. (3) Booth: the starting Q₋₁ = 0 bit is a must. Skip it and every pass shifts wrong. (4) Booth uses Arithmetic Shift Right (keeps the sign bit), not Logical Shift Right. (5) RPN: do not flip operand order on SUB. The second-popped value is the minuend. The first-popped is the subtrahend.
Conclusion

IEEE-754 made floating-point one standard across all CPUs after 1985. Booth's encoding cut signed-multiply adds by about 50%. It is still the base of every modern multiplier tree. The zero-address stack-CPU model made portable bytecode (JVM, Wasm) possible. All three ideas — float format, signed multiplier, evaluator stack — live inside every modern CPU and runtime.

Introduction

A Control Unit (CU) makes the timing and control signals. It tells the CPU when to fetch, decode, route operands, latch results, and step PC. There are two ways to build a CU:

  • Hardwired CU — fixed logic gates. Inputs: opcode + flags + step counter. Outputs: hard-wired control lines.
  • Micro-programmed CU (Wilkes, 1951) — control signals are fetched as microinstructions from a small fast Control Memory (a ROM). One main instruction expands into a microroutine: a list of microinstructions that drive the data path one register-transfer at a time.

Inside the microprogrammed CU, the CAR (Control Address Register) (also called μPC) holds the address of the microinstruction being read from Control Memory. After every microcycle, the Address Sequencer updates the CAR. It picks from four next-address sources. The CDR (Control Data Register) latches the fetched microinstruction so its bits can drive control lines in the same clock cycle.

Address Sequencing — the 4 Next-Address Sources

After each microinstruction, the Next-Address Generator picks the new CAR value from one of four sources:

  • (1) Increment: CAR ← CAR + 1. The default. Used inside a microroutine to step linearly. A simple +1 adder does this.
  • (2) Mapping logic (Opcode-Map): the opcode is padded with zeros (e.g. 00·OPCODE·00) or fed through a PLA to give the start address of that instruction's microroutine. This is the FETCH ⇒ EXECUTE jump.
  • (3) Unconditional Branch: CAR ← absolute address from the microinstruction's branch field. Used to jump between microroutines (e.g. EXECUTE ⇒ FETCH).
  • (4) Conditional Branch: CAR ← address-field if the selected status bit (Zero, Carry, Overflow, Interrupt) is true. Else CAR + 1. This is how the CU handles conditional opcodes like JZ, BCS.

A 2-bit field inside every microinstruction picks which of the four sources is used. The Next-Address MUX decodes it.

Mapping Logic — Worked Example

Say the opcode is 4 bits and Control Memory uses 7-bit addresses. A common mapping joins bits like this:

Map
CAR(next) = 0 || OPCODE(4 bits) || 00 ⇒ for opcode 1010 (ADD), CAR becomes 0 1010 00₂ = 40 (decimal).

So the ADD microroutine starts at address 40. Four slots (40, 41, 42, 43) are reserved before the next opcode (1011) starts at 44.

Vertical vs Horizontal Microinstruction Encoding
  • Horizontal microcode: one bit per control line, no decoding. Wide microinstruction (~100 bits). Max parallel work. Low decode delay. Used in mainframe CPUs.
  • Vertical microcode: packed fields decoded into mutually exclusive control signals. Narrow (~16–32 bits). Less parallel work. Smaller ROM. Used in small CISC chips.
  • Nano-programming: two-level. Vertical microinstructions index into a horizontal nanoroutine. Trades one extra ROM read for far fewer total ROM bits.

The reward is flexibility. That is why x86 stayed binary-compatible for 45 years, and why the 2018 Spectre microcode patches shipped in days, not years.

Introduction

An I/O transfer scheme is the rule the CPU uses to move data between a device and RAM. Device speeds went from punch-card readers (10 char/s) to NVMe SSDs (7 GB/s). Three schemes grew over time. Each one uses more hardware to give the CPU more free time. Programmed I/O wastes CPU cycles in a poll loop. Interrupt-driven I/O frees the CPU between transfers. DMA takes the CPU out of the data path completely. Think of DMA like a bus depot: trucks load and unload by themselves while the driver rests.

Interrupt Mechanics — Step-by-Step
  • 1. Interrupt Request (IRQ): the device raises an INT line to the interrupt controller.
  • 2. Acknowledgement (INTA): CPU finishes the current instruction, raises INTA. The device puts its vector number on the data bus.
  • 3. Save context: PC and PSW are pushed to the stack. The IF (Interrupt-enable Flag) is cleared to block new interrupts.
  • 4. Vectored dispatch: CPU looks up the interrupt vector table at IVT_BASE + vector × 4. It loads the ISR start address into PC.
  • 5. ISR execution: the handler serves the device, clears the IRQ source. It can re-enable IF for nested handling.
  • 6. Return (IRET): pops PSW and PC. CPU resumes the old program smoothly.

Maskable interrupts (INTR) respect IF. Non-maskable interrupts (NMI) ignore IF. NMI is used for serious events like memory parity errors or watchdog timeout.

The Three DMA Transfer Modes
  • 1. Burst mode (Block transfer): The DMA controller grabs the bus with HOLD. It moves the full block (1 KB–4 MB) without breaks. Then it lets go with HLDA. CPU waits during this time. Best for fast bulk transfers (disk-to-RAM, SATA, NVMe).

  • NVMe SSDs: use queue-pair DMA. Host writes commands to queues in RAM. The SSD's DMA engine pulls commands and pushes data straight between flash and RAM. Hits 7+ GB/s on PCIe Gen4 x4 with the CPU idle.

DMA splits data movement from instruction work. This was the biggest speed gain in computer organisation since Eckert-Mauchly. The three transfer modes trade CPU stalls for I/O delay. All modern I/O (PCIe MSI-X, NVMe queue-pair DMA, GPUDirect RDMA, IOMMU isolation) is built on these 1970s ideas.

Introduction

Flynn's taxonomy (1966) sorts parallel computers by two axes: the number of parallel Instruction Streams and the number of parallel Data Streams. The 2×2 box it forms still names every modern parallel system, from a tiny embedded chip to a GPU shading 4096 pixels per clock.

  • SISD: classic Von Neumann machine. One IF/ID/EX/MEM/WB pipeline. One operand per cycle. Examples: Intel 8086, ARM Cortex-M0.
  • SIMD: one control unit sends one instruction to N data lanes. Each lane runs it on its own element. Examples: NVIDIA GPU warps (32-wide SIMT), Intel AVX-512 (8 doubles per instruction), Cray-1 vector processor.
  • MISD: N instruction streams work on the same data. Used in redundant systems where each stream checks the others. Examples: Space Shuttle's quad-redundant 4-AP1 voting computers, signal-processing systolic arrays.
  • MIMD: N cores each fetch their own instructions and work on their own data. Examples: every modern multi-core x86/ARM CPU, message-passing clusters, NUMA servers.
  • SPMD (Single Program Multiple Data) is a software pattern that sits on top of MIMD. Same binary, different data slices. OpenMP, MPI, and CUDA all use this.
5-Stage Pipeline Timing — 4 Instructions, No Hazards
Pipeline Hazards & Resolutions
  • 1. Structural Hazard: two pipeline stages want the same hardware in the same cycle.
    Examples: single-port memory needs both IF (instruction fetch) and MEM (load/store) at once. One FPU serving both ADD.F and MUL.F.
    Fixes: (a) split into separate instruction and data caches (Harvard architecture); (b) add more units (extra FPUs); (c) insert a bubble (NOP) to stall the clashing stage.
  • 2. Data Hazard: instruction j needs a result from instruction i that has not yet reached WB.
    Three sub-types:
    • RAW (Read-After-Write): j reads what i writes. A true dependency. Example: I1: ADD R1, R2, R3; I2: SUB R4, R1, R5.
    • WAR (Write-After-Read): j writes a register i has not yet read. Anti-dependency. Only matters in out-of-order pipelines.
    • WAW (Write-After-Write): two instructions write the same register. Output dependency. Only matters in out-of-order.
    Fixes: (a) Operand forwarding (bypassing): route the EX/MEM result straight back to the next instruction's ALU input; (b) compiler scheduling: move independent instructions between i and j; (c) stalling: insert pipeline bubbles; (d) register renaming: kill WAR/WAW by giving each write a fresh physical register.
  • 3. Control Hazard (Branch Hazard): branch and jump change the PC after the next instruction has already started its fetch. Wrong instructions are already in the pipe.
    Fixes:
    • Branch Prediction (BTB + 2-bit saturating counter): guess taken / not-taken from history. About 95% right for normal loops.
    • Delayed Branch (MIPS): the ISA promises that the instruction after the branch always runs. The compiler fills that delay slot.
    • Branch Target Buffer (BTB): stores recent branch targets so IF can redirect in the same cycle the branch decodes.
    • Speculative Execution: fetch and run the predicted path before the branch resolves. Squash and replay on mis-predict.

  • Out-of-order issue + register renaming: Modern cores (Zen 4, M3, Skylake) rename to 200+ physical registers and schedule 6–10 µops per cycle. This hides cache-miss delay.
  • SIMD is still alive: Intel AVX-512 (16 floats per instruction), ARM SVE / SVE2 (up to 2048 bits), NVIDIA SIMT warps (32-wide). One add instruction can do 64 FP ops on H100 tensor cores.
  • MIMD is everywhere: every smartphone has at least 4 cores. Data-centre Sapphire Rapids has 60 P-cores. Apple M3 Max = 12 P + 4 E cores.

Hazards are the cost. Forwarding, branch prediction, and register renaming push the pipeline toward the limit Sp = k. But Spectre showed that aggressive speculation creates security holes that hardware fixes (eIBRS, STIBP) cannot fully seal.

  • Inclusive vs exclusive caches: Intel uses inclusive (L3 holds every L1/L2 line) for easy coherence. AMD Zen uses victim/exclusive caching to grow total size.
  • CLOCK / Second-Chance: Linux mm/swap.c and Windows WorkingSet manager both run a circular reference-bit scan. It approximates LRU at O(1) per page.
  • TLB hierarchy: modern x86 has L1 ITLB (64 entries), L1 DTLB (64 entries), L2 STLB (~1500 entries). A page-walk after STLB miss takes ~100 cycles on a hot page-table cache, ~400+ cycles cold.
  • Huge pages: 2 MB and 1 GB pages cut TLB pressure for big workloads (databases, JVM heaps). One 2 MB TLB entry covers what would otherwise need 512 entries.
  • Unified memory (Apple M-series): CPU and GPU share the same physical RAM and same caches. No PCIe DMA copies. This used to dominate ML inference delay.
Common pitfalls (1) TLB miss ≠ cache miss: a TLB miss means the virtual-to-physical map is missing (page-walk, ~100 cyc). A cache miss means the data line is missing from L1/L2/L3 (DRAM fetch, ~200 cyc). A single reference can be a TLB hit + cache miss, or the other way. (2) In a page-replacement trace, count the compulsory misses. The first 4 references all count as faults when frames start empty. (3) Belady's anomaly: FIFO can give more faults with more frames. Never assume "more frames is always better". (4) SET ≠ LINE: in direct-mapped the index picks a line. In set-associative the same field picks a set (group of k lines). (5) Write policy: write-through (every store hits memory; safe, slow) vs write-back (stores buffer in cache, flushed on eviction; fast, needs dirty bit and coherence like MESI).
Conclusion

Cache mapping decides where a block can sit. Replacement decides which block leaves. The address split (TAG · SET · WORD) comes from power-of-two arithmetic on cache size, block size, and address width. FIFO, LRU, and Optimal trade cost for hit rate. Belady's Optimal is the theoretical floor. LRU (and its CLOCK approximation) gets within a few percent. FIFO survives only where simplicity wins over correctness. The OS kernel still solves this tradeoff inside mm/swap.c every day.

Differentiate between RISC and CISC instruction set architectures.

RISC (Reduced Instruction Set Computer) keeps a small set of simple, fixed-length instructions that each run in one cycle, favouring a pipelined load-store design. CISC (Complex Instruction Set Computer) provides many powerful, variable-length instructions that can do multi-step work in a single instruction.
