PART A 10 SHORTS · 15 MARKS · COMPULSORY

Prof pattern Stems: "define / differentiate / what is / write the formula / convert / why". Each answer = 2-4 lines or 2 points + 1 example. 10 sub-parts (a)–(j) cover the whole syllabus — leave none blank, each is 1.5 free marks.
If asked…Write this
Define PSW. Its primary flags? Program Status Word = a CPU register holding status flags the ALU sets after each operation: CF (carry), ZF (zero), SF (sign), OF (signed overflow), PF (parity). Eg: 5−5=0 → ZF=1, used by JZ branch.
What is an n-bit parallel (ripple-carry) adder? n full-adders chained so each stage's carry-out feeds the next stage's carry-in, adding two n-bit numbers in one pass. Simple but slow — the carry ripples stage to stage (delay ∝ n). Carry-look-ahead fixes this by computing all carries in parallel. (Unit-I, computer arithmetic.)
Differentiate direct vs indirect addressing. Direct: the address in the instruction is the operand's address (EA = A), 1 memory read. Indirect: the instruction points to a cell that holds the real address (EA = M[A]), 2 reads. Eg: MOV AX,[1000] vs MOV AX,@[1000].
Why does DMA have priority over CPU for the bus? I/O data is volatile — a fast incoming byte not read at once is overwritten and lost; CPU work can simply wait. So DMA gets the bus first (cycle stealing). Eg: a disk streaming a block — miss one byte and the whole sector is corrupt.
List the three pipeline hazards. Structural — two stages need the same hardware in one cycle. Data — an instruction reads a value before the earlier one writes it. Control — branches delay the pipeline because the next address isn't known yet.
Define spatial & temporal locality. Temporal: a cell used once is likely used again soon (eg loop counter i). Spatial: cells near a used cell are likely used next (eg walking an array). This is why caches work.
Pipeline speedup formula + variables. S_p = (n × k) / (k + n − 1), where n = instructions, k = stages; as n grows, S_p → k. Eg: k=4, n=100 → 400/103 ≈ 3.88×.
Differentiate write-through vs write-back cache. Write-through: every cache write also goes to RAM at once — high traffic, always consistent. Write-back: writes update only the cache line; RAM updated later on eviction (dirty bit) — low traffic.
Convert (19.625)₁₀ to binary. Integer: 19 = 16+2+1 = 10011. Fraction: 0.625 = 0.5+0.125 = .101. Result: 10011.101₂
Function of IR and PC? PC (Program Counter) holds the address of the next instruction to fetch; IR (Instruction Register) holds the current instruction's opcode being decoded. Eg: fetch at 2000 → goes to IR, PC increments to 2001.
What is RTL (Register Transfer Language)? A symbolic notation for micro-operations between registers. Eg: R1 ← R2 + R3 means add R2,R3 and store in R1. A conditional: T0: R1 ← R2 (transfer happens at time T0). Used to describe CPU control.
Differentiate hardware vs software interrupt. Hardware interrupt: raised by an external device (keyboard, timer) via an interrupt line — asynchronous. Software interrupt: raised by a program instruction (INT n, system call) — synchronous, planned.
Differentiate combinational vs sequential circuit. Combinational: output depends only on present inputs, no memory (eg adder, MUX). Sequential: output depends on inputs + past state, uses memory/clock (eg flip-flop, counter, register).
Differentiate fixed-point vs floating-point. Fixed-point: radix point at a fixed position, limited range, simple/fast. Floating-point: radix point "floats" via an exponent (1.M × 2^E), huge range, costlier arithmetic. Eg IEEE-754 single = 1+8+23 bits.
Address space is 24 bits, memory space 16 bits — words in each? Address space = 2²⁴ = 16 M words; memory space = 2¹⁶ = 64 K words. (1 address = 1 word; 2¹⁰=1K, 2²⁰=1M.)
Differentiate cache line vs block size. Block = unit of transfer between main memory and cache. Line = the cache slot that holds one block. Line size = block size; bigger blocks exploit spatial locality but raise miss penalty.
What is memory interleaving? Splitting memory into several banks that can be accessed in parallel, so consecutive addresses fall in different banks. Speeds up block/burst reads (cache fills, pipelines). Eg low-order interleaving.
Define throughput and speedup. Throughput = number of instructions/tasks completed per unit time. Speedup = (time without enhancement) / (time with enhancement). Pipelining/parallelism raise both.
Differentiate RISC vs CISC (short). RISC: few simple fixed-length instructions, load/store, many registers, hardwired control, pipelined (ARM). CISC: many complex variable-length instructions, memory operands, microprogrammed (x86).
What is Booth's algorithm? An efficient method for signed (2's-complement) multiplication. It scans the multiplier's last two bits Q₀Q₋₁ (10→sub, 01→add, 00/11→nothing) then arithmetic-shift-right. A run of 1s becomes one sub + one add → fewer operations.
Write the IEEE-754 single-precision format. 32 bits = 1 Sign + 8 Exponent (bias 127) + 23 Mantissa. Value = (−1)ˢ × 1.M × 2^(E−127); leading 1 is hidden. Double = 1+11+52, bias 1023.
What is the instruction cycle? The basic CPU loop: Fetch → Decode → Execute (+ store / interrupt check). PC supplies the address, IR holds the opcode, control unit generates the micro-operations.
Name the cache mapping techniques. Direct mapping (block → one fixed line), Associative (block → any line), Set-associative (block → any line within one set). Set-associative is the practical middle ground.
What is microprogramming? Implementing the control unit as a program of microinstructions stored in control memory (ROM). Each machine instruction triggers a micro-routine. Flexible & easy to modify, but slower than hardwired control.
Define DMA. Direct Memory Access = a controller that transfers data directly between an I/O device and memory without CPU involvement per byte. CPU only sets it up (start address + count), then is interrupted when done.

15M · #1 LOCKBooth's Algorithm — signed multiplication

Likely stem "Explain Booth's algorithm for signed multiplication and multiply (−6) × (−9) showing every step." / "Multiply the given signed numbers using Booth's algorithm."

Model answer

Booth's algorithm multiplies two signed numbers in 2's-complement form directly, with no separate sign handling. It treats a string of 1s in the multiplier as one subtraction + one addition, reducing the number of partial products.

Recoding rule — examine the multiplier's two lowest bits Q₀ Q₋₁:

Q₀ Q₋₁ActionMeaning
0 0No operationmiddle of run of 0s
0 1A ← A + Mend of a run of 1s
1 0A ← A − Mstart of a run of 1s
1 1No operationmiddle of run of 1s

After each step do an Arithmetic Shift Right (ASR) on the combined A·Q·Q₋₁ register (sign bit of A preserved). Repeat for n = bit-width of the multiplier.

Worked example — (−6) × (−9), 5-bit:

M = −6 = 11010, so −M = +6 = 00110.   Q = −9 = 10111.   Init A = 00000, Q₋₁ = 0.   5-bit → 5 steps.

StepAQQ₋₁Q₀Q₋₁ → op
Init00000101110—
10011010111010 → A−M (+6)
1·ASR00011010111shift
20001101011111 → no-op
2·ASR00001101011shift
30000110101111 → no-op
3·ASR00000110101shift
41101011010101 → A+M (−6)
4·ASR11101011010shift

Result = combined A:Q = 00001 10110₂ = +54₁₀   ✓  (−6 × −9 = +54).

Advantages: handles signed numbers uniformly (no sign correction); fewer add/subtract operations for numbers with long runs of 1s; basis of modern multiplier hardware (Booth-encoded multiplier trees).

Conclusion: Booth's algorithm is the standard hardware method for 2's-complement multiplication — one recoding table + arithmetic shift gives correct signed products with reduced operations.

Exam tip Steps = bit-width of multiplier; table rows = steps + 1 (Init). If a number is too big for n bits (eg −9 needs 5 bits, not 4) use the next width. Always verify: sign of result must match sign of (M × Q).

15M · #2 LOCKI/O Data Transfer Modes + DMA

Likely stem "Explain the modes of data transfer between CPU and I/O." / "Describe DMA with a block diagram and its working." (BCA May-25 Q7(d))

Model answer

Data moves between an I/O device and memory in three modes, differing in how much the CPU is involved.

1. Programmed I/O: the CPU runs a loop that polls the device status flag and transfers each byte itself. Simple, but the CPU wastes cycles busy-waiting. Suits slow devices.

2. Interrupt-driven I/O: the device interrupts the CPU when ready; the CPU runs an ISR to transfer the byte, then resumes its work. No busy-wait, but still one interrupt + CPU transfer per byte — costly for fast/bulk data.

3. DMA (Direct Memory Access): a DMA controller transfers a whole block directly between device and memory without the CPU per byte. CPU only programs it (start address + count), DMA takes the bus (cycle stealing), and interrupts the CPU once at the end.

DMA block diagram:

DMA working steps:

  1. CPU loads DMAC registers: memory start address, word count, read/write.
  2. Device asserts DREQ; DMAC raises BR to the CPU.
  3. CPU finishes the current cycle, asserts BG, and floats off the bus.
  4. DMAC transfers data word-by-word, incrementing address & decrementing count.
  5. On count = 0, DMAC releases the bus and sends an interrupt to the CPU.

DMA transfer modes: Burst (whole block at once, bus held), Cycle-stealing (one word per CPU idle cycle), Transparent/hidden (only when CPU isn't using the bus).

Conclusion: DMA gives the highest I/O throughput by removing the CPU from the per-byte path — essential for disks, network cards and graphics where data is fast and volatile.

Mnemonic Modes ladder: P-I-D = Programmed (poll) → Interrupt (notify) → DMA (delegate) — CPU involvement drops at each step.

15M · #3 LOCKCache Mapping + Address-Split Numerical

Likely stem "Explain cache mapping techniques with a numerical." / "Given cache and memory sizes, find the TAG/LINE/WORD bits." (BCA May-25 Q5(a))

Model answer

Cache is small fast memory between CPU and RAM that exploits locality of reference. Mapping decides which cache line a memory block can occupy.

The three mapping techniques:

TypeRuleAddress split
Directblock → exactly one line (line = block mod #lines)TAG + LINE + WORD
Associativeblock → any line (full search)TAG + WORD
Set-associativeblock → any line within one setTAG + SET + WORD

Worked numerical (direct mapping): Main memory = 64 KB, cache = 2 KB, block = 16 bytes. Find TAG/LINE/WORD bits.

  1. Memory = 64 KB = 2¹⁶ → 16-bit physical address.
  2. Block = 16 B = 2⁴ → WORD (offset) = 4 bits.
  3. Cache lines = cache/block = 2 KB / 16 B = 2¹¹/2⁴ = 2⁷ → LINE = 7 bits.
  4. TAG = 16 − 7 − 4 = 5 bits.

Answer: TAG 5 · LINE 7 · WORD 4 = 16 bits

Set-associative variation: for a 4-way set-associative cache, #sets = #lines / 4 = 2⁷/2² = 2⁵ → SET = 5 bits, so TAG = 16 − 5 − 4 = 7 bits (fewer set bits → bigger tag).

Write policies & replacement (mention for marks): write-through vs write-back; replacement algorithms FIFO, LRU, Random (associative caches need one; direct mapping doesn't — only one choice).

Conclusion: direct mapping is simple but conflict-prone; associative is flexible but costly; set-associative balances both and is used in real CPUs. Bit-splitting always = address = TAG + (SET/LINE) + WORD.

Formula card WORD = log₂(block size) · LINE = log₂(#cache lines) · SET = log₂(#sets) · TAG = addr bits − rest. Always start from total address bits = log₂(memory size).

15M · #4 LOCKAddressing Modes (x86)

Likely stem "Explain the various addressing modes with examples." (BCA May-25 Q6 · Real Paper 311404)

Model answer

An addressing mode is the rule by which an instruction specifies where its operand is. It lets the same opcode reach data in a register, in memory, or in the instruction itself — giving flexibility and compact code.

ModeOperand location (EA)Example
Immediateoperand is in the instruction itselfMOV AX, 5
Registeroperand in a registerMOV AX, BX
DirectEA = address in instructionMOV AX, [1000]
Register-indirectEA = contents of a registerMOV AX, [BX]
Indexed / DisplacementEA = base/index reg + offsetMOV AX, [SI+4]
Based-indexedEA = base reg + index reg (+ disp)MOV AX, [BX+SI]
Indirect (memory)EA = M[address in instruction]MOV AX, @[1000]
Relative (PC)EA = PC + offsetJMP +6 (branches)

Why so many modes:

  • Immediate — fast constants, no memory read.
  • Register — fastest operand access (no memory).
  • Indirect / indexed — essential for arrays, pointers, loops (vary the index each iteration).
  • Relative — position-independent code, branch targets.

Worked micro-example: if BX = 1000 and M[1004] = 25, then MOV AX,[BX+4] computes EA = 1000+4 = 1004 → loads AX = 25.

Conclusion: addressing modes trade off speed vs flexibility. Register/immediate are fastest; indexed/indirect enable data structures. A rich mode set (CISC/x86) shortens programs at the cost of decoder complexity.

15M · BACKUPHardwired vs Microprogrammed Control Unit

Likely stem "Differentiate hardwired and microprogrammed control units." / "Explain the design of a microprogrammed control unit." (in syllabus, BTech-repeated)

Model answer

The control unit (CU) generates the timing & control signals that drive every micro-operation. It is built in two ways — hardwired or microprogrammed.

Hardwired: control signals come from fixed combinational logic (gates, decoders, flip-flops, a sequence counter). Very fast, but rigid — changing the instruction set means redesigning the circuit. Used in RISC.

Microprogrammed: each machine instruction maps to a micro-routine of microinstructions stored in control memory (ROM). A microinstruction's bits directly drive the control lines. Flexible — add/modify instructions by editing the microcode. Used in CISC.

15M · BACKUPPipelining — Hazards + Speedup

Likely stem "Explain pipelining, its hazards and how they are resolved. Compute the speedup." (BTech May-26/24 repeated)

Model answer

Pipelining overlaps the execution of several instructions by splitting the datapath into stages, so one instruction is fetched while another decodes and a third executes — like an assembly line.

Classic 5-stage pipeline: IF (fetch) → ID (decode) → EX (execute) → MEM (memory) → WB (write-back). Ideally one instruction completes every clock cycle.

Hazards (and resolution):

  • Structural — two stages need the same unit; fix with separate instruction/data memory or more ports.
  • Data — instruction needs a result not yet written; fix with forwarding/bypassing, or stall/bubble, or compiler reordering.
  • Control — branch changes the PC; fix with branch prediction, delayed branch, or flushing wrong-path instructions.

Speedup formula: S_p = (n × k) / (k + n − 1), n = instructions, k = stages; max speedup → k.

Worked example: k = 5 stages, n = 100 instructions → S_p = (100 × 5) / (5 + 100 − 1) = 500 / 104 = ≈ 4.81× (approaching the ideal 5×).

Pipeline clock note: clock period = slowest stage + latch delay. If stages are 100 ns and latch 5 ns, clock = 105 ns; total time = (k + n − 1) × clock.

Conclusion: pipelining boosts throughput (not single-instruction latency). Real speedup is below the ideal k because of hazards; forwarding and branch prediction recover most of the loss.
